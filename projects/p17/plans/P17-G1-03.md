# P17-G1-03 implementation plan

P17-G1-03 replaces current command-local CLI runtimes with declarative command specifications, one
shared CLI runtime, and public core application services returning structured outcomes. Primary IDs
are `COMMAND:version`, `EWP-CF-033`, `EWP-P1-T09`, `EWP-OPT-TS02`, `EWP-OPT-TS03`, and
`EWP-P1-TS07`. G1-01 and G1-02A/B/C are all signed off.

Required-now validation is exactly `EWP-OPT-TS02`, `EWP-OPT-TS03`, `EWP-P1-TS07`, and the signed
`EWP-WF15` regression. `EWP-WF16` remains downstream: this group supplies generator-capable metadata
and a fixture proof but does not generate the full user manual or Phase-6 grouped help.

Test-first work has three owners. TS02 requires one complete live CommandSpec registry, exact
argument/alias/option shapes, known-versus-allowed enum policy, repeatability, contextual and parsed
defaults, negated semantics, and inherited-option permutations. TS03 requires one declarative
conflict/requirement graph and proves each current relation in both orders before environment or I/O.
TS07 requires live spec/service closure, static dependency bans, current-command parity, and a
fixture spec that produces parser/help/completion/docs inventory plus execution without a local
runtime.

Implementation proceeds in five ordered integration slices:

1. Add ADR 0004, public `CommandOutcome`/application/interaction types, declarative spec and relation
   types, the runtime shell, dependency zones, and the `version` end-to-end canary. `failure` is an
   explicit exit class mapped to current code 1 because the planning sketch omitted a class needed
   to preserve current generic/verification/health failures.
2. Migrate metadata/built-in and read-only cohorts: version, completion, help, agents, config,
   list, and commands.
3. Migrate diagnostics: doctor, check, and verify, preserving exact JSON/human/error/cancel behavior.
4. Migrate lifecycle commands: shared dev/promote first, then install/uninstall through one
   interaction port while preserving current non-TTY, preview, approval, picker, batch, and signal
   behavior.
5. Remove command-local runtime paths, activate the complete static gate, replay WF15 and every
   current command suite, and close traceability.

After the red boundary is committed, core application wrappers, declarative spec extraction, and
runtime/fixture infrastructure may be developed in parallel behind interfaces owned by root. Root
alone integrates `program.ts`, `index.ts`, public core exports, the registry, command rewiring,
catalog, evidence, and cohort commits.

Prohibited scope: scoped effect ports or ScanEnv removal (G1-04); tool-adapter registry cleanup
(G1-05); wire codec/JSON redesign (G1-06); typed observation/verbosity sinks (G1-07); Phase-6 help
grouping/order/progressive docs/full WF16; and every future command or inactive option. Historical
0.7 Commander ledgers remain immutable; only the evolving current-state authority may change.
