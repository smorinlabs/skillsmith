## Pure lossless TOML scanner

`human-toml.ts` accepts owned `Uint8Array` bytes and fatally decodes UTF-8. Invalid UTF-8 and a UTF-8
BOM refuse; neither is rewritten. It scans without executing caller accessors or iterators and
recognizes enough TOML lexical state to avoid false structure inside:

- basic, literal, multiline-basic, and multiline-literal strings;
- escapes and line continuations in basic strings;
- comments outside strings;
- bare, single-quoted, double-quoted, and escaped basic keys;
- dotted keys and inline tables as unsupported target aliases;
- standard and array-table headers;
- nested single-line arrays and inline tables;
- multiline arrays as structurally recognized but conservatively non-editable target values.

The scanner returns immutable copied ranges. It never treats `=`, `#`, brackets, quotes, headers,
or version-like text inside a value as structure. It performs no semantic normalization and never
serializes an untouched range.

Supported target rewrites are deliberately bounded:

- replace a single-line string, boolean, or string-array value while preserving key spelling,
  whitespace around `=`, quote preference when safe, trailing comma preference, and inline comment;
- insert a missing key only at an unambiguous table boundary using the nearest local newline form;
- create a missing `[defaults]` or `[registry]` table immediately after root `version` trivia and
  before the first table, in fixed defaults-then-registry order when both are created; the editor
  uses the nearest unique newline and one blank separator, and refuses if root/table comment
  attachment or the local newline is ambiguous;
- unset a field only under the exact comment-safe whole-line rule below;
- add a canonical `[[skills]]` block at an unambiguous array-table boundary;
- remove a comment-free skill block, or one whose leading comment block is unambiguously attached
  by direct adjacency; otherwise refuse;
- preserve mixed newline bytes for in-place replacement, but refuse any insertion/removal whose
  local newline form cannot be determined uniquely.

Standalone comments attach to a following item only when directly adjacent with no blank line.
Inline comments attach to their line. Blank-separated comments and EOF comments remain independent.
If deletion or insertion would require guessing attachment, the edit refuses. Dotted aliases,
reopened target tables, duplicate decoded keys/names, multiline target values, inline-table target
aliases, or overlapping ranges also refuse.

Scalar unset is narrower than replacement: it removes the complete physical key line only when the
line has no inline comment and no directly adjacent leading comment block. If either comment class
is attached, unset returns `unsafe-human-edit` and the manual patch; it never leaves a comment that
would become attached to the next key. Skill-block removal may remove a directly adjacent leading
comment block because that ownership is explicit above; no other unset consumes comments.

`version` is not generally editable. Rename is exactly remove-old plus add-new. `name` and `source`
cannot be unset. TOML has no null literal: normalized null `ref`/`path` is requested only through the
corresponding unset variant; add-skill may still receive a normalized declaration containing null.
Optional defaulted declaration fields are omitted on unset and re-normalize through G2-01 defaults.
`touchedTargets` is the copied/frozen, first-request-occurrence list of the exact discriminated
targets above; it never uses a dotted or caller-constructed string grammar.

Request ownership and ordering are exact:

1. copy and validate the ordinary-array request by own numeric index without invoking custom
   iterators/getters;
2. reject holes, accessors, symbols, extra keys, exotic prototypes, duplicate discriminated target
   tuples, two edits of the same field, remove/update conflicts, or duplicate final names; multiple
   distinct fields of the same skill are explicitly valid and atomic;
3. apply root edits in request order, then existing-skill edits in request order, then additions in
   request order; ranges themselves are replaced in descending byte-offset order;
4. `migrate-legacy` may appear exactly once and only at index 0; ordinary edits may follow it. A
   canonical input treats migration itself as a no-op, while an exact legacy input uses G2-01's
   semantic mapping before the remaining edits;
5. strictly read and normalize before scanning, edit only a readable canonical/exact-legacy source,
   strictly reread the candidate, and compare the complete expected semantic projection;
6. if normalized semantics are unchanged, return the original copied bytes exactly and report
   `changed: false` even when a different serialization could have been produced.

All result objects/arrays/bytes are copied and recursively frozen where JavaScript permits. No
caller source, raw requested value, or Node error is interpolated into an error.

## Manual refusal and error contract

```ts
export type ArtifactMutationErrorReason =
  | 'invalid-request'
  | 'unsafe-human-edit'
  | 'invalid-utf8'
  | 'invalid-manifest'
  | 'invalid-lock'
  | 'invalid-file-kind'
  | 'artifact-alias'
  | 'lock-contention'
  | 'external-writer-conflict'
  | 'stage-collision'
  | 'recovery-record-invalid'
  | 'recovery-conflict'
  | 'filesystem-failure'
  | 'permission-denied'
  | 'cancelled';

export interface ArtifactMutationError {
  readonly code: 'artifact-mutation';
  readonly exitCode: 2 | 3 | 6 | 130;
  readonly reason: ArtifactMutationErrorReason;
  readonly role?: 'manifest' | 'lock' | 'recovery' | 'staging' | 'backup';
  readonly field?: string;
  readonly path?: string;
  readonly manualPatch?: string;
  readonly durableState?: 'unobserved-before' | 'before' | 'after';
  readonly manifestRevision?: ArtifactFileRevision;
  readonly lockRevision?: ArtifactFileRevision;
  readonly message: string;
}
```

Exit 2 is limited to invalid requested values/combinations and an otherwise valid document whose
target cannot be edited safely. Exit 3 covers artifact state, contention, external change,
recovery conflict, special topology, collision, and non-permission I/O. `EACCES`/`EPERM` at any
capability is exit 6. Exit 130 is returned only after cancellation leaves a durable full-before or
full-after state. Recovery or rollback failure outranks cancellation.

Only a `cancelled` error may carry `durableState`. Cancellation before the fresh post-provision,
compatibility-locked snapshot reports `unobserved-before` and no revisions; a provisional snapshot
is never reported because an old writer may change it. After that locked snapshot, a pair reports
both copied/frozen revisions; the one-member config form reports only `manifestRevision` and omits
`lockRevision`. Pre-commit cancellation reports `before`; post-commit cancellation reports `after`.
Other errors omit all three fields, and an unprovable state is `recovery-conflict`, never a cancelled
result.

Messages are fixed by reason. An unsafe edit includes a deterministic unified manual patch using
logical `skillsmith.toml` labels and decoded target identity. The patch passes through the shared
redactor; credential-bearing requested values become `[REDACTED]` plus a fixed instruction to fill
the validated value locally. The original source, unrelated comments, local exception text, and
recovery content never enter the error.

## Exact file snapshots and topology

`file-state.ts` publishes immutable copied snapshots:

```ts
export type ArtifactFileRevision =
  | { readonly state: 'absent'; readonly parent: ArtifactParentRevision }
  | { readonly state: 'file'; readonly bytes: Uint8Array; readonly digest: ArtifactDigest; readonly mode: number; readonly identity: string; readonly linkCount: 1; readonly parent: ArtifactParentRevision };

export type ArtifactParentRevision =
  | { readonly state: 'present'; readonly path: string; readonly identity: string }
  | { readonly state: 'missing'; readonly nearestExistingPath: string; readonly nearestExistingIdentity: string; readonly missingSegments: readonly string[] };

export interface ArtifactPathObservation {
  readonly kind: 'absent' | 'file' | 'directory' | 'symlink' | 'other';
  readonly mode: number | null;
  readonly identity: string | null;
  readonly linkCount: number | null;
  readonly parent: ArtifactParentRevision;
}

export interface ArtifactPairSnapshot {
  readonly manifest: ArtifactFileRevision;
  readonly lock: ArtifactFileRevision;
}
```

The focused topology port reports exactly `ArtifactPathObservation`.
Observation is parent metadata, leaf metadata, bytes, leaf metadata, parent metadata. Only absent or
one-link regular files are valid. Directories, symlinks (including dangling), devices, FIFO/socket/
other nodes, multi-link files, leaf aliases, and manifest/lock paths resolving to one identity
refuse. Existing symlink ancestors are canonicalized before planning; every parent identity is
rechecked before stage creation and each destructive transition. A retarget or identity change
refuses even when bytes are equal.

Missing destination directories are represented by the nearest existing ancestor plus the exact
missing segment vector. Parent provisioning is monotonic infrastructure, not transaction-owned
residue: after the stable central lock and after a pure proof that mutation is required, each segment
uses exclusive mkdir-or-observe, validates ordinary-directory topology, fsyncs its parent, and is
reobserved before the next segment. Provisioned directories are never removed by rollback or
recovery. A crash after mkdir is therefore not an unprovable cleanup claim; the next invocation
revalidates and continues. No-op, pre-central-lock contention, and pre-provision cancellation create
no parent. After provisioning, compatibility target locks are acquired and the complete snapshot is
taken fresh before any recovery record or file mutation.

Exact file digests use G2-02's `manifest-bytes` domain for manifest bytes and `lock-canonical` only
for strictly canonical lock bytes. Internal recovery comparisons may store those public digests;
the one-member non-manifest config path uses G2-02's existing generic `resource` domain over exact
bytes. They do not introduce another hash domain.

Existing modes are preserved exactly within the supported `0o0000..0o7777` permission vocabulary.
New manifest/config and lock files use `0o600`. G2-03 promises no ACL, ownership, xattr, timestamp,
or Windows attribute preservation beyond the focused adapter's documented mode field.

Before any lock/recovery/stage path is formed, both canonical target paths and every generated ID/
basename must pass the shared sensitivity predicate. A credential-shaped target path refuses before
coordination rather than being copied into a recovery record; generated basenames contain only the
bounded internal ID grammar. Ordinary local diagnostic paths remain valid under the negative-canary
rules.

exactly 16 lowercase hex; ownership IDs are exactly 64 lowercase hex (32 bytes). A wrong, repeated,
accessor-backed, or out-of-grammar adapter result is `filesystem-failure` before the corresponding
object is created. Focused fakes provide deterministic sequences per purpose.

`recovery-file.ts` and `node-coordinator.ts` are the one real G2-03 private serialization/repository
and Node adapter. Production does not accept a caller-selected root. On POSIX the adapter derives
the account tuple and home from `os.userInfo()` (including its numeric uid), not `os.homedir()`,
`HOME`, or XDG, and uses
`join(userInfo.homedir, '.skillsmith', 'coordination', 'artifacts-v1')`; every component is a
non-symlink directory owned by that uid and the Skillsmith components are `0700`. On Windows it uses
the OS-account `userInfo()` home/username identity, rejects reparse/symlink components, and requests
the most restrictive supported mode. Correctness does not claim or depend on inspecting a Windows
DACL: transaction-to-live creation is no-replace, live backup moves target only a marker-proven
absent fixed slot, parent/leaf identities are checked, and recovery may remove only marker-proven
transaction objects directly under an already-authorized destination parent. Tests vary HOME and
every XDG variable while requiring one root. An explicit temporary root
exists only on the internal test factory, whose type is not exported by core/CLI production entry
points. G2-05 still owns every public/domain journal codec and repository.

For each distinct existing destination directory, the coordinator records a fresh 32-byte ownership
token, then `createTransactionDirectoryExclusive` creates one sibling
`.<skillsmith-artifact>-<16-lower-hex-id>` directory at mode `0700`. Fixed internal names are
`owner`, `manifest.stage`, `manifest.backup`, `manifest.discard`, `lock.stage`, `lock.backup`, and
`lock.discard`; `owner` is an
exclusive one-link `0600` file containing only the token plus LF and is file/directory/parent durable
before the composite capability returns. Recovery may adopt a null-identity directory only when the
marker matches the record exactly, then saves the observed identity before proceeding. An unmarked
or wrong-marker directory is never owned or removed.

The record carries `attempt: 1..8` and the active candidate paths. On `EEXIST`/wrong marker it first
removes and fsyncs only marker+identity-proven directories from that attempt, then CAS-advances the
attempt and candidate ID while the cursor remains `prepared`; collided paths are retained in a
non-owned collision list. A crash before the CAS safely retries the old attempt; a crash after it
uses the new attempt. Exhaustion removes the still-pre-mutation record and returns `stage-collision`
while preserving every collision. Thus retry never silently changes frozen ownership facts.

Each stage is created with `O_CREAT|O_EXCL`, exact bytes, final mode, file fsync, and an exact
digest/mode/identity re-read. Live-to-backup is one atomic move into the marker-proven owned
directory after its fixed backup slot is reobserved absent; this moves whichever live identity wins
the last-moment race and never performs a later path-based unlink. Stage-to-live and backup-to-live
use `linkFileNoReplace`, followed by unlinking only the owned transaction source and fsyncing both
directories. Temporary two-link states are recorded and accepted inside install, external-restore,
and rollback recovery. Every distinct destination directory has its own ordered fsync transcript.

The focused adapter never receives Git, HTTP, process execution, raw environment/config bags, CLI
IO, tool adapters, placement/store access, or a ledger repository. `config/save.ts` accepts the
focused adapter through an internal optional third parameter and defaults to the Node adapter; its
narrow edit API remains unchanged and delegates one-member human-config writes to this same
coordinator.

This is one logical operation with a two-level acquisition. It first acquires the stable

The callback may take a provisional absent-parent snapshot and return a no-op without provisioning.

The account-stable global root serializes production processes even when HOME/XDG values differ;
the same sorted member order prevents cycles inside hermetic adapters. The recovery namespace is
scanned under the central lock. For each discovered overlap,
`recoverEnvelopeUnderCentral` acquires that record's complete sorted member set, resolves/finalizes
or refuses it, releases those members, and rescans before the requested set is acquired. It never
calls the public wrapper or reacquires/releases central during handoff. Prior-record contention or
cancellation returns before requested-pair mutation; recovery conflict outranks cancellation.

Current `config/save.ts` delegates to the same abstraction for a one-member transaction while still
holding its historical file target. It therefore remains mutually exclusive with old binaries and
new pair writers.

Contention uses exactly `ARTIFACT_LOCK_RETRY_DELAYS_MS`; the signal is checked before each attempt,
between waits, and immediately after a late acquisition. A late acquire after cancellation is
released without invoking the callback. The contender creates/leaves no additional sidecar; an
owner's legitimate sidecar remains until that owner releases. After holder release, all adapter-
created sidecars are absent. Cancellation before/during acquisition releases every acquired member
and returns 130 without creating a live destination, stage, backup, or recovery record.

The new central sidecar uses exact proper-lockfile stale/update values `2000/1000ms`. Compatibility
member sidecars use the historical `30000/5000ms` contract from `ports/default.ts`; an unmarked
legacy member is never reclaimed under the 2s policy. After a new member lock is acquired, the
adapter immediately writes/durably verifies a private owner marker—not inside the
proper-lockfile directory, whose mtime heartbeat must remain untouched. Markers live only at
`<coordinationRoot>/member-owners/v1-<64hex>.json`, where the key is the prefix-stripped successful
`resource` digest of the canonical member target. Exact canonical JSON+LF fields are kind, version,
structured member target, central operation ID, and observed member-lock-directory identity; key/
target collisions refuse. The file is `0600`, exclusively created, file+directory durable, and its
own metadata/content identity is reobserved before cleanup.

A contender cannot inspect/reclaim members until it owns central. After a killed new holder's
central lock becomes stale, it may remove a member directory early only when current directory
identity equals the strict private marker; it then removes the exact reobserved marker and attempts
normal acquisition. Invalid/replaced marker files are preserved and refuse. If an old writer wins
the intervening race, its new unmarked identity receives the full legacy policy. A stale valid marker
whose recorded directory is already absent is removed under central before a new exclusive marker
create. Normal release rechecks/removes/fsyncs its marker before proper-lockfile release. An unmarked
member or crash between member mkdir and marker uses the 30s legacy rule, so the bounded invocation
may return contention rather than steal it.

Spawned tests hold both new and old writers longer than 2s without theft, kill a marked new holder
and require recovery within the six-attempt schedule, and prove an active/unmarked old writer remains
locked across its 5s heartbeat. A proven stale central or marked-dead member sidecar is the sole case
a contender removes a sidecar it did not create; ordinary contention never does.

snapshot algorithm; “one read” means one snapshot, not one filesystem syscall.

## External-writer guard and bounded replay

After locking, observe both exact revisions, strictly parse them, apply the typed request, and return
an exact no-op before any stage/recovery operation. Reobserve both immediately before staging and
again immediately before the first destructive transition.

The safe-replay matrix is closed:

| Change after initial plan | Disposition |
|---|---|
| no fact changed | commit original intent |
| manifest bytes changed in place; mode/identity/parent stable; complete semantic hash unchanged; every touched target retains its before value | discard stages, replay the same typed request once on newest bytes, require identical planned normalized semantics and identical supplied canonical lock, then restage |
| newest manifest already expresses every requested target and lock equals exact desired canonical bytes | converge to no-op/remaining effect |
| any semantic hash changed, including an unrelated declaration/default/placement field | refuse; a concrete caller-supplied `PortableLockV1` is never rebound or inferred |
| lock bytes/existence/mode/identity changed unexpectedly | refuse |
| manifest mode/identity/parent changed, targeted before-value changed, topology changed, or bytes perform ABA with identity drift | refuse |
| a second guard change after replay | refuse |

Formatting/comment-only replay is identified by the G2-02 manifest semantic hash and is the only
safe-replan class. Exact desired-state convergence is allowed only when the caller's lock already
validates against the newest manifest. The coordinator never changes `manifestHash`, reconstructs a
lock, or replans from Git, acquisition, ledger, live state, or command policy.

For a changed expected after-file, `identity` is `null` in `prepared` and becomes the verified stage
identity before the cursor advances beyond `staging`; a `keep` role copies its before identity and
never expects a stage. Before/rollback-target file identities are never null. `pair.lock:null` is

parent is recorded after monotonic provisioning and is rechecked before and after every create,
move, link, unlink, fsync, verification, and cleanup action.

The structured identity is the canonical manifest path plus canonical lock path or JSON `null` in
the fixed JSON byte string
`{"manifest":<JSON string>,"lock":<JSON string or null>}`. Its fingerprint is
the `.value` of a required-success `hashCanonicalInput('resource', 1, identityJson)` result. The
result must match `sha256:<64-lower-hex>`; `key` is exactly `v1-` plus the digest with the `sha256:`
prefix removed. A loaded key is always collision-checked against both structured paths and the
sorted exact member set. `discover` strictly scans all `v1-*.json` records and returns every
intersecting member set, closing same-pair and overlapping-pair handoff.

`recovery-file.ts` serializes schema keys in the interface order, arrays in recorded order, UTF-8,
one trailing LF, and no optional/unknown fields. It contains no manifest/lock bytes, source/ref
arguments, comments, arbitrary DTOs, credentials, errors, stack/cause, Git facts, or ledger state.
Create is exclusive and file+directory durable. Replace is expected-revision CAS through an
exclusive temporary, file fsync, atomic replacement inside the private `0700` namespace, and
directory fsync. Delete requires the latest revision and fsyncs the directory. Revision is the
existing `resource` digest of exact record bytes. Invalid filenames/bytes, duplicate structured
pairs, key collisions, non-monotonic cursor/ownership changes, or CAS loss refuse.

The only permitted fact changes are: prepared attempt increments with fresh candidate paths;
marker-proven directory identity adoption; stage identity adoption into a changed after-file;
forward cursor movement; one `forward -> rollback` disposition transition; exact rollback-target/
owned-object replacement with a just-atomically-captured displaced file; rollback cursor movement;
and final cleanup. Member/parent paths, before facts, ownership tokens for an active attempt, and
committed after facts never change. The private decoder validates this transition relation on every
CAS replace.

CAS temporaries have the sole grammar
`.v1-<key-hex>.cas-<expected-revision-hex>-<16-lower-hex-id>.tmp` inside the recovery directory.
`discover` processes them before records while holding central: it requires a one-link regular file,
strictly decodes/canary-checks its exact record, and matches filename key/expected revision. If the
live record still has the embedded expected revision, it completes the atomic replace and directory
fsync; if live already equals the temp revision, it removes the redundant temp and fsyncs; any other
live revision or invalid/ambiguous temp blocks with `recovery-record-invalid` and is preserved.
Spawned adapter tests kill after temp create, file fsync, replace, and directory fsync.
These private CAS temps are repository-owned residue even though they are not artifact transaction
objects, and successful discovery leaves none.

Every cursor is the durable intent immediately before the named action. Forward recovery accepts
only these exact states; every row also requires the recorded parent identities. `changedRoles` is
the effectful subset in fixed lock-then-manifest order. Keep roles copy before to after and have no
stage, backup, install cursor, or filesystem action; every successor below means the next changed
role's backup, or `pair-verify` when none remains:

| Durable cursor | Next action | Accepted action-gap states | Durable successor |
|---|---|---|---|

Inside a marker- and identity-proven transaction directory, a partial/null-identity stage at the
exact durable `staging` cursor is transaction-owned. The original in-memory attempt may delete and
recreate it because it still holds the screened candidate bytes. Those bytes are intentionally not
persisted in the recovery record, so a restarted explicit `resume` cannot reconstruct an absent or
partial candidate from a digest and must return `recovery-conflict` without mutation. Automatic
recovery before a read/new commit and explicit `rollback` may remove that staging-cursor partial,
fsync, and reach exact before-state. An exact-byte pre-mode/null-identity stage remains adoptable for
forward resume. At `prepared`, rollback/automatic recovery removes only proven directories and the
record; explicit resume conflicts. At every later cursor, especially cleanup, a null-identity wrong
stage is untrusted and preserved. A symlink, special node, unexpected hard link, wrong bytes outside
the staging-cursor rollback case, or parent change conflicts and is preserved. Thus every emitted
physical gap has a deterministic safe restart action without inventing candidate bytes; an OS crash
inside the composite transaction-directory capability may leave an unmarked directory, which is
treated as a non-owned collision and advanced through the durable retry protocol.

Immediately after a live-to-backup move, before any install, the coordinator observes the moved
file. Exact before facts advance normally. If it observes displaced external `B`, it first CAS-saves
`disposition:'rollback'`, copies exact B into that role's `rollbackTarget` and backup object, and sets
the first rollback cursor. Only then may it restore. This makes backup-restore two-link gaps durable
and ensures B is never deleted or mistaken for A.

Rollback is a separately persisted state machine. Switching from any pre-commit forward cursor
first CAS-saves `disposition:'rollback'`, `rollbackTarget` (initially exact `before`), and
the first role in fixed manifest-then-lock rollback order that differs from its target; roles already
at target and never mutated are skipped. Forward resume is thereafter forbidden:

| Durable rollback cursor | Next action | Accepted action-gap states | Durable successor |
|---|---|---|---|
| `rollback-manifest-remove` | if live differs from rollback target, atomically move it to owned `manifest.discard`, fsync, verify | live exact-after/discard absent; live absent/one atomically moved discard; live absent/backup exact rollback target after a forward backup; or live already exact rollback target | `rollback-manifest-restore` |
| `rollback-manifest-restore` | link recorded backup/discard rollback target to absent live, unlink owned source, fsync, verify; confirm absent target when required | source exact/live absent; source+live same identity with linkCount 2; source absent/live exact target; or both absent for absent target | `rollback-lock-remove`, or `rollback-verify` for one-member records |
| `rollback-lock-remove` | same atomic move-to-`lock.discard` rule | exact-after live/discard, atomically moved displaced-update, live absent/backup exact rollback target after forward backup, or live already exact target | `rollback-lock-restore` |
| `rollback-lock-restore` | same no-replace link, owned-source unlink, fsync, verify | exact source/live absent, same-identity two-link, live exact target, or exact absent target | `rollback-verify` |
| `rollback-verify` | reobserve complete rollback target and parents | exact rollback target only | `cleanup` |
| `cleanup` with `rollback` | remove only exact owned stages/backups/discards/directories, then record | exact rollback target and no owned residue/CAS temp | absent record |

If a rollback move captures a last-moment external object instead of recorded after-state, the
coordinator durably replaces that role's rollback target/object facts with the observed object before
any restore, then restores it through the same two-link row and returns external-writer conflict.
Unknown objects that were not atomically captured into an owned slot always conflict/preserve. Every
cleanup removal is preceded by marker, identity, digest, mode, and parent rechecks.

Before `committed`, `rollback` reaches the recorded rollback target even if both live paths happen to
equal after; it never turns physical after-bytes into a logical commit. `resume` follows only the
forward table and the restart restrictions in its `prepared`/`staging` rows; it never synthesizes
candidate bytes. After `committed`, either requested direction finalizes forward only when exact
after-state is proven. Automatic reads/new commits choose rollback for pre-commit records and
finalize committed records. Repeated resume, rollback, or cleanup is idempotent at every table row;
no coordinated reader returns a mixed pair.

`afterBarrier` is invoked immediately after every listed physical operation returns, after every
exact object verification, and after every durable record transition, before the next operation.
`operationId` is allocated at entry; `occurrence` increments separately for each exact kind/cursor/
role/object tuple, and `recordRevision` is the latest durable revision. Directory and role order are
unsigned-byte sorted, making every repeated fsync/record/barrier instance uniquely selectable and
hard-coded in the crash fixture.
The spawned `crash-child.ts` receives the canonical JSON of one complete barrier object over its
test-only IPC, emits the same object in `reached`, waits, and is SIGKILLed by the parent; restart uses
the real private file adapter. This covers action-returned-before-verification and verified-before-
successor-save gaps, not merely caught exceptions. No environment variable, CLI option, production
parser bypass, or throw-only fake stands in for hard-process recovery.

## Cancellation and residue table

Cancellations are checked before lock acquisition and after every recoverable barrier. It never
interrupts one move/link/unlink/fsync capability. Before the fresh post-provision compatibility-
locked snapshot it returns 130/`unobserved-before` with no revisions; before provisioning this has
zero residue, while mid-provision it completes/revalidates the current segment and may leave valid
parent infrastructure but no file/recovery residue. After the locked fresh snapshot and before
`prepared`, it returns 130/`before` with exact revisions and no file residue. After `prepared` and
before `committed`, it durably switches to rollback, reaches exact `before`, cleans,
then returns 130/`before`; an external displacement or recovery failure outranks cancellation and
returns that conflict instead. After `committed`, it finalizes/cleans exact after and returns
130/`after` with both revisions. These are the only cancelled-result states.

Dry-run (later caller), request validation, unsafe edit, approval refusal (later caller), no-op,
pre-provision cancellation, and central contention leave no destination file, no parent, no stage,
no backup, and no recovery record. Once mutation-required provisioning starts, valid parent
directories may remain as monotonic infrastructure after compatibility-lock contention,
cancellation, or crash; they are not live artifact placeholders and are never transactionally
removed. Before `prepared`, no live/stage/backup/recovery/CAS-temp residue exists. After `prepared`,
an injected hard crash may retain only the record, repository CAS temp, active/collided transaction
directory, member-owner marker/sidecar, stage, backup, discard, or temporary hard-link set enumerated
by the private protocols.
The next coordinated read or write resolves or safely refuses it before returning state.

## Portability authority and live source safety

P2-TS07 tests the existing G2-01 authorities directly; G2-03 does not create parallel URL/path
regex authorities:

- `normalizeSourceIdentity` for canonical host/repository/source-relative identity;
- `normalizeRegistryIdentity` for registry identity and exact legacy HTTPS normalization;
- `normalizePortablePath` for scope-qualified `./` and `~/` placement tokens;
- `classifyArtifactSelectorToken` for invocation-local portable versus machine-bound selectors.

The accepted v1 transport grammar remains exact: credential-free HTTPS, `ssh://git@host/...`, and
`git@host:...` scp; no HTTPS user, no SSH user other than `git`, and no port. This preserves the
signed G2-01 canonical identity. The safe SSH scheme/user spelling is ephemeral transport metadata;
it never enters canonical identity or portable hashes. A later amendment is required before custom
SSH users/ports can be accepted.

Acquisition syntax is only a shape adapter; it is not a second identity authority. It splits
transport, inline ref, and selector without discarding components, constructs exactly
`https://<host>/<repository>[//<source-path>]`, calls `normalizeSourceIdentity`, and requires the
returned host/repository/path to equal the split projection. Name selectors and refs are validated
separately by `validateManifestName` and `validateRequestedRef`. `--ref` enters this same constructor
as `overrideRef`; inline-plus-override refuses, and `runInstall` never spreads a new ref onto an
already-built object.

The current `parseSource(input, { overrideRef? })` must reject before acquisition:

- HTTPS userinfo/password, any query, any fragment, and percent-encoded delimiters/credentials;
- plain HTTP, Git protocol, `file://`, and every other scheme;
- non-`git` SSH/scp users, ports, malformed hosts, traversal, control/whitespace, doubled/empty
  segments, and foreign path forms.

The replacement DTO and formatter are exact:

```ts
export interface SourceSpec {
  readonly identity: CanonicalSourceIdentity;
  /** host/repository[//source-path], used by manifests and locks. */
  readonly canonicalSource: string;
  /** canonicalSource or host/repository/name, plus @ref when non-null. */
  readonly canonicalInvocation: string;
  /** Equals canonicalSource; selector/ref persist in their dedicated origin fields. */
  readonly originSource: string;
  /** Credential-free HTTPS or ssh://git transport; never persisted. */
  readonly cloneUrl: string;
  readonly selector:
    | { readonly kind: 'whole-repo' }
    | { readonly kind: 'name'; readonly name: string }
    | { readonly kind: 'path'; readonly path: string };
  readonly ref: string | null;
}

export interface InstallSourceTransport {
  readonly resolveRef: typeof resolveRefViaLsRemote;
  readonly fetchRepo: typeof fetchRepo;
  readonly listSkills: typeof lsTreeSkills;
  readonly materializeSkill: typeof sparseCheckoutSkill;
}
```

`canonicalSource` is `host/repository` plus `//path` only for a path selector; a name selector does
not become an identity path. `canonicalInvocation` appends `/name` for a name selector or `//path`
for a path selector and then `@ref` when non-null, so different selectors/refs do not collapse in
reports. `originSource` is exactly `canonicalSource`; `OriginRecord.skillPath` and
`refRequested` retain the separately validated resolved selector path and requested ref, so name/ref
spelling is not duplicated into persisted source identity. `SourceSpec` has no `raw`, userinfo,
query, fragment, local path, or generic metadata bag.

The existing `InstallResult` gains only `readonly requestIndex?: number` as a core-only field. A
real result always has its exact zero-based safe-integer input index; public v1 mapping deliberately
omits it.

`InstallDeps` gains optional `readonly transport?: InstallSourceTransport`; absence selects the
closed `defaultInstallSourceTransport`, and no parser dependency exists. `runInstall` always uses
the production `parseSource`. Hermetic tests use safe fake canonical HTTPS inputs such as
`fixture.invalid/acme/repo//skills/review` and inject a trusted transport that maps only those
already-validated clone URLs to local bare repositories. The adapter is passed directly by tests;
no CLI flag, environment variable, config key, production fallback, or accepted `file://` selects
it. Low-level fetch tests may still exercise Git's file transport directly, but the acquisition
source grammar never accepts it.

The existing spawned `install-live` test cannot inject `InstallDeps`; it instead passes the same
safe `https://fixture.invalid/...` input through the production parser/default transport and uses
Git's standard per-child `url.<local-file-url>.insteadOf` configuration to rewrite only the Git
subprocess destination. That is not a Skillsmith grammar or transport selector, never enters a DTO,
and is scoped to the spawned test environment. The fixture exports the exact rewrite environment so
no other test invents a bypass.

Before a `SourceSpec` is returned, one constructor applies `containsSensitiveMaterial` to the inline
and override refs, selector, canonical identity fields, all four formatted strings, and transport.
Any sensitive component refuses before report construction, fetch, or persistence. Every later
candidate `OriginRecord.source`, `refRequested`, report source, and acquisition error is checked or
redacted at the same boundary.

A second half of that same boundary runs after transport/selection/verification and before any
placement/store/ledger/report object is formed. It validates every `CandidateSkill.path` as a
normalized source-relative POSIX path, every candidate/result skill name with
`validateManifestName`, the resolved ref as exactly 40 lowercase hex, and applies
`containsSensitiveMaterial` to candidate path/name, chosen path/name, derived placement/store
components, `OriginRecord.skillPath`, and every candidates rerun line. Invalid/sensitive remote
data becomes a fixed source-level refusal and is never used as a filesystem component. Transport,
Git, verify, and nested cause/reason text passes through `redactSensitiveValue` before a public
error or report reason is constructed. TS07 injects token-shaped candidate names/paths, transport
errors, and verification messages to prove the post-resolution boundary, not only malformed input
arguments.

Presentation on refusal is byte-exact:

```ts
const rejectedSourceLabel = (input: string): string => {
  const safe = redactSensitiveString(input);
  return safe === input ? '[REJECTED_SOURCE]' : safe;
};
```

For accepted input, `requested.sources[i]` and every corresponding `result.source` equal
`canonicalInvocation`. For rejected input both equal `rejectedSourceLabel(input)`. Input order and
duplicates are preserved and every result carries an internal optional `requestIndex` used by the
human renderer; JSON intentionally omits the internal index but preserves result array order.
Fail-fast still emits one source-level result per input index: the invalid row is `refused` with the
fixed secret-safe parser error, otherwise-valid rows are `skipped` with `fail-fast`. The same label
is used in human and v1 JSON output; grouping is by numeric request index, never display text.
For compatibility with manually constructed pre-G2-03 reports that omit the optional field, the
human renderer alone falls back to its signed legacy source-label grouping; every `runInstall`
result has the numeric field, so real duplicate requests never use that fallback.
Rejected override refs use the analogous fixed `[REJECTED_REF]` unless redaction changes them; a
literal unsafe ref never enters `requested.ref`.

Fetch/acquisition failures pass through the shared redactor before becoming errors. G2-03 changes
no install selection, fetching, verification, placement, ledger schema, default-save, or command
contract and does not activate downstream install selectors.

## One recursive redactor

`packages/core/src/safety/redaction.ts` publishes:

```ts
export function containsSensitiveMaterial(input: string): boolean;
export function redactSensitiveString(input: string): string;
export function redactSensitiveValue(input: unknown): unknown;
export const redactObservationValue: typeof redactSensitiveValue;
```

The compatibility export is the same function object, not a wrapper or second implementation.
Manual-patch and acquisition sensitivity checks delegate `containsSensitiveMaterial`; it shares the
same scanner/pattern table with string redaction and is not a second regex authority.

String handling covers:

- Bearer and Basic authorization payloads;
- GitHub/OpenAI token forms and `api_key`/`api-key`/authorization/cookie/credential/password/secret/
  token assignments;
- URL userinfo/password, all query components, and fragments for URLs embedded anywhere in prose;
- percent-encoded `@`, `:`, `/`, `?`, `#`, and credential names case-insensitively.

An unsafe HTTP(S)/SSH URL is rendered as its credential-free scheme/host/path when that parse is
safe, otherwise `[REDACTED_URL]`; query and fragment are removed entirely. Ordinary safe repository
names, refs, hashes, hosts, non-secret `git` SSH transport, and useful local diagnostic paths remain
visible.

Recursive handling retains the signed untrusted-input properties: no accessors, iterators, proxy
traps, or exotic prototypes are invoked; symbols/exotics/proxies/accessors/cycles/depth/node bounds
produce fixed markers; input is not mutated; results are copied/frozen. Known sensitive keys are
redacted regardless of their value shape. Errors and nested causes are converted only through safe
own data descriptors.

Render boundaries redact; semantic persistence boundaries validate and reject before persistence.
`[REDACTED]` never becomes a manifest source/path/ref or canonical lock value. Candidate human bytes
containing recognizable credential syntax in comments/trivia refuse rather than silently rewriting
human content. Generated lock bytes and the private recovery record receive defense-in-depth canary
scans before persistence. Canary scanning is an assertion after serialization, not the primary
mechanism; arbitrary opaque strings without key/token/URL/assignment context are outside the
credential grammar.

Current CLI human/JSON error messages, debug/trace observations, manual patches, PortError-to-public
error conversion, acquisition errors/results, and every G2-03 recovery/stage/backup input must use
the same authority.
