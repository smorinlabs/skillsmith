# P17-G1-06 implementation plan

P17-G1-06 replaces independently declared command JSON schemas, ad hoc domain-field stripping, and
unversioned renderer-owned serialization with one validated wire-contract registry and explicit
domain-to-DTO mappers. Its primary IDs are `EWP-CF-037`, `EWP-P1-T12`, and `EWP-P1-TS10`.

The formal dependency, P17-G1-03, is signed off. Signed G1-04 constrains effect ownership: codecs
and mappers are pure and receive values rather than environment authority. Signed G1-05 constrains
tool authority: verify choices and capability snapshots derive from the executable tool registry.
Required-now validation is exactly `EWP-P1-TS10`; `EWP-P2-TS08` remains downstream-only and owns
persisted manifest, lock, plan, ledger, and journal codec migration.

ADR 0008 records the codec decision. The group migrates accepted current command JSON without
adding a command or option and without changing a single accepted output byte.

## Frozen wire-contract authority

- `WireCodec<Id, Version, Dto>` is the only owner of a public wire shape. Its public structural
  interface is `validate(input: unknown): Result<Dto, WireCodecError>`,
  `decode(text: string): Result<Dto, WireCodecError>`, and
  `encode(dto: Dto): Result<string, WireCodecError>`. Encoded strings are the exact UTF-8 text sent
  to CLI IO; byte assertions use `TextEncoder`. No method throws for untrusted data and no public
  signature exposes Zod. `WireCodecError` is a frozen safe record containing code
  (`malformed-json`, `invalid-shape`, `unsupported-version`, or `migration-failed`), contract ID,
  requested version, stable path segments, and sanitized message—never a cause, stack, or raw
  payload.
- A codec's `WireCodecDescriptor` is exactly `{ id, version, wireKind, embeddedVersion,
  unknownFields, formatting, migrations, compatibility }`: stable contract ID; positive
  safe-integer version; `wireKind: string | null`; `embeddedVersion: 'schemaVersion' | null`;
  `unknownFields: 'reject-recursive'`; formatting `{ indent: 0 | 2, terminalLf: boolean }`;
  source-version migration numbers; and `compatibility: 'conservative'`.
  Its private schema infers `Dto`; no parallel handwritten DTO is authoritative. Current outbound
  command codecs expose domain-to-DTO mappers only. Bidirectional DTO-to-domain artifact mappings,
  repositories, and migrations remain Phase-2 work.
- `createWireContractRegistry(codecs, commandMappings)` validates before freezing. It rejects
  duplicate `<id>@<version>` identities, malformed versions, descriptor/codec drift, duplicate
  command mappings, unknown mapped codec identities, incompatible embedded kind or version policy,
  and unlisted migrations. The same stable ID may have multiple distinct versions. Exact
  `get(id, version)` returns one codec; `latest(id)` selects the highest registered safe-integer
  version, never insertion order. Registry arrays, descriptors, maps, lookup results, and command
  projections are immutable and preserve declared order. Construction defensively owns its frozen
  views without freezing or mutating caller inputs.
- The generic core builder does not know today's command set and never imports CLI/spec policy. A
  CLI-owned production assertion compares production command mappings with the JSON-capable paths
  derived from `CURRENT_COMMAND_SPECS` (including `agents --format json`) and rejects missing or
  extra mappings. Fixture and future registries supply their own mappings without editing generic
  core code.
- Decoding parses JSON exactly once, rejects malformed or truncated input, refuses unknown future
  versions, applies only declared older-version migrations, and recursively rejects unknown object
  keys. Dynamic record keys declared by a codec remain data, not unknown schema fields.
- Encoding accepts only codec-derived DTOs, validates them, and uses the descriptor's deterministic
  JSON formatting and terminal framing. Canonical serialization does not sort semantic arrays or
  dynamic records whose current insertion order is observable. Re-encoding the same DTO is
  byte-identical.
- Current codecs declare no migrations. Under the conservative compatibility policy, any public
  field add/remove/rename/type/semantic change, enum growth, embedded kind/version change, property
  order change, JSON formatting change, or terminal-framing change is breaking and requires a new
  codec version plus an explicitly registered migration if backward decoding is supported. Recursive
  unknown-field rejection means additive fields are not silently compatible.
- Domain models remain separate. Named `to*Dto` mappers construct every public field explicitly;
  they do not spread domain reports, destructure away `error`, rely on schema stripping, or access
  excluded internal fields. Proxy/getter canaries prove ignored internals are never read.
- Application services and planners pass domain values. Current CLI renderers select the mapped
  codec, call its explicit mapper, and emit only validated codec bytes. Generic renderer,
  application, and planner modules may not call raw `JSON.parse`, build public JSON with
  `JSON.stringify`, strip fields, or own a command-output Zod object outside declared codec owners.

## Exact current inventory and bytes

The registry closes the 12 current JSON-capable command paths and ten shared output codecs:

| Current command path | Canonical codec | Version | Embedded kind |
|---|---|---:|---|
| `agents` | `agents` | 1 | absent |
| `check`, `doctor` | `health` | 1 | absent |
| `commands` | `commands` | 1 | absent |
| `config get` | `config-get` | 1 | absent |
| `config list` | `config-list` | 1 | absent |
| `dev`, `promote` | `flip` | 2 | `skillsmith.flip` |
| `install` | `install` | 1 | `skillsmith.install` |
| `list` | `list` | 2 | absent |
| `uninstall` | `uninstall` | 1 | `skillsmith.uninstall` |
| `verify` | `verify` | 1 | `skillsmith.verify` |

The complete contract registry additionally contains `error` version 1 with embedded kind `error`
and `capability-snapshot` version 1 with embedded kind `skillsmith.capabilities`. The exact
capability DTO is `{ schemaVersion: 1, kind: 'skillsmith.capabilities', tools: [...] }`, where tools
are in descriptor order and each item is exactly `{ id, order, capabilityVersion, operations }`.
`operations` has every `TOOL_OPERATIONS` key in canonical operation order and each value is exactly
`{ supported, scopes, remediation }`; scopes retain descriptor order. The mapper reads only cloned
immutable descriptor facts and never exposes inventory/verification/placement/adaptation bundles,
functions, ports, registry methods, or mutable implementation objects. It is a foundation contract
only; G1-06 does not add final `agents --capabilities` bytes.

Current embedded `schemaVersion` values remain exact. Legacy command outputs without embedded kind
remain without it. `config get` and `config list` also remain without an embedded schema version;
their codec version is registry metadata and is not injected onto the wire. Error uses compact JSON;
all other current codecs use two-space indentation. Final output has exactly one terminal LF for
`agents`, `config get`, and `error`, and no terminal LF for health (`check`/`doctor`), `commands`,
both `config list` variants, flip (`dev`/`promote`), `install`, `list`, `uninstall`, and `verify`.
Property order, omitted optional fields, dynamic-map/array order, and those framing decisions remain
byte-identical. No golden is normalized merely because its committed fixture happens to end in LF.
`config get` retains two legacy shapes: unscoped output is `{ key, value, source }` when source is
present, while scoped output is only `{ key, value }`; domain `scope` is not serialized.
`config list` retains two untagged shapes: unscoped `{ effective, sources, layers }`, while scoped output is
the selected config layer object directly. `config set`, `config unset`, `version`, help,
completion, and metadata renderer functions are not current JSON-selectable command paths and do
not enter the production command mapping.

The public package adds dedicated entry points `@skillsmith/core/contracts`,
`@skillsmith/core/contracts/v1`, and `@skillsmith/core/contracts/v2`. Versioned entry points expose
only their stable DTOs/codecs/mappers. The contracts root exposes registry and shared codec types.
The existing `@skillsmith/core` root retains domain/application and 1.x compatibility exports; it
does not become a second DTO authority and consumers need no public Zod dependency.

The contracts root exports `WireCodec`, `WireCodecDescriptor`, `WireCodecError`, `WireContractRegistry`,
`WireContractMapping`, and `createWireContractRegistry`; it does not export a core-owned current-CLI
registry instance. V1 symbols use the exact `AgentsV1Dto` / `agentsV1Codec` / `toAgentsV1Dto`
pattern for agents, health, commands, config get/list, install, uninstall, verify, error, and
capability snapshot. Verify additionally exports `createVerifyV1Codec` for G1-05 registry injection.
V2 exports `FlipV2Dto` / `flipV2Codec` / `toFlipV2Dto` and the equivalent ListV2 symbols. The
CLI-owned `wire-contracts.ts` exports `currentWireContractRegistry`,
`currentWireCommandMappings`, and `assertCurrentWireContractClosure`.
`WireContractMapping` is exactly `{ commandPath, contractId, version }`; heterogeneous mappings do
not erase mapper input types. `WireContractRegistry` exposes frozen `codecs` and `commandMappings`
plus `get(id, version)`, deterministic `latest(id)`, and `forCommand(commandPath)`. Typed renderers
invoke the named versioned mappers outside the heterogeneous registry. All three lookups return
`undefined` for an unknown identity/path rather than throwing or widening to another codec.

Verify codec construction retains G1-05 injection: tool choices come from the supplied validated
tool registry, and the production codec uses the production registry. A fixture tool or fixture
codec can be registered and routed without editing a generic codec registry, renderer coordinator,
command mapping switch, or public schema union.

## Test-first contract

`EWP-P1-TS10` is one executable selector with ten families:

1. exact 12-command-to-ten-codec mapping plus error/capability inventory, stable IDs/versions/order,
   and registry/docs parity;
2. validated immutable builder behavior, including duplicate identity, malformed, drifted, and
   unknown command/codec reference rejection, multi-version lookup/latest behavior, and caller
   purity; CLI-owned production incomplete/extra command closure is checked against
   `CURRENT_COMMAND_SPECS` rather than hard-coded by the core builder;
3. recursive strict unknown-key, wrong/future-version, malformed, truncated, and deterministic
   canonicalization fixtures;
4. codec-derived DTO compile checks and `keyof` compile-negative proof that lifecycle `error`,
   adapter functions, ports, and registry methods cannot serialize;
5. explicit mapper tests with hostile extra fields and proxy/getter canaries proving excluded fields
   are neither represented nor read;
6. byte-exact final renderer/stdout goldens for all 12 command paths, scoped and unscoped config
   variants, and the error envelope, including exact terminal framing;
7. codec round trips and current schema behavior, including registry-derived verify choices and
   capability facts without implementation leakage;
8. dedicated public-subpath import/type tests with version closure, no deep-core import, and no
   consumer-facing Zod requirement;
9. scoped static bans on ad hoc public JSON construction, renderer field stripping, and raw parsing
   outside codec/repository owners; human config quoting and downstream repository parsing are
   explicit non-authoritative exemptions; and
10. a fixture codec and command mapping proving extension without generic source edits or global
    registry mutation.

The selector must retain characterization-green clauses for already shipped schemas and exact
bytes while failing only for absent registry, public entry points, strict codecs, explicit mappers,
and migrated authority. A missing test or fixture file alone is not accepted as red evidence.

Exact required command:

`bun test tests/ergonomics/phase/EWP-P1-TS10.test.ts --test-name-pattern EWP-P1-TS10`

Focused impacted baselines and regressions include CLI output tests, runtime adapter, check/verify
contracts, core ledger characterization, catalog generation, package public-API checks, and the
full repository gate. Spawn-heavy help tests run serially when captured to avoid unrelated timeout
noise.

## Ordered implementation and ownership

Implementation proceeds in seven ordered slices:

1. Commit the genuinely red `EWP-P1-TS10` selector and compile fixtures while the focused current
   output baseline remains green.
2. Add ADR 0008; freeze codec/descriptor/registry/serialization contracts and public subpath
   exports before parallel migration.
3. Implement codec-derived v1 DTOs/mappers for agents, health, commands, config get/list, install,
   uninstall, verify, error, and capability snapshot; implement v2 DTOs/mappers for flip and list.
4. Migrate the disjoint CLI output owners to core codecs/mappers while preserving exact final
   bytes, including verify registry injection and error framing.
5. Route the shared renderer registry exclusively through mapped codecs and remove ad hoc lifecycle
   field stripping and public JSON construction from generic output paths.
6. Close strict parsing, public import/type, fixture extension, mapping inventory, mapper-canary,
   golden-byte, and static ownership gates without touching downstream artifact repositories.
7. Run the required selector, all impacted current-output/runtime/public regressions, full
   `bun run check`, fresh independent adversarial review, and traceability closure.

Root owns ADR/docs, registry interfaces/builder, package exports, shared renderer integration,
catalog/evidence, and commits. After red and interface-freeze commits, v1 and v2 codec/mappers may
be implemented in parallel with disjoint files; CLI renderer migration begins only after those
interfaces are immutable. Shared package exports, registry, current renderer registry, TS10, and
catalog remain root-owned.

Likely owned files are ADR 0008, `docs/adr/README.md`, `docs/architecture.md`,
`packages/core/README.md`, `packages/core/package.json`; new `packages/core/src/contracts/**`;
compatibility-facing core indexes; current CLI JSON output modules and error boundary;
`packages/cli/src/runtime/current-renderers.ts`; CLI spec and `contracts/wire-contracts.ts` mapping
closure files; relevant output,
runtime, contract, and public-API tests/goldens; `tests/ergonomics/phase/EWP-P1-TS10.test.ts`; and
new `tests/ergonomics/fixtures/p1-ts10/**`. `eslint.config.js` changes only if needed for an
executable, narrowly scoped ownership rule.

Prohibited scope: manifest, lock, plan, ledger, or journal codec/repository implementation or
migration (`EWP-P2-TS08`); recursive credential redaction or portable-artifact policy; new commands,
options, output fields, envelopes, kinds, or versions; final capability command output; G1-07
operation context/events/verbosity/debug work; planner/repository/coordinator redesign; public
domain-type removal; and any change to accepted human/JSON bytes, exit selection, prompts,
journals, or lifecycle semantics.
