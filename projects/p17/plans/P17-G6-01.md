# P17-G6-01 plan: standard single-lineage distribution candidates

## State and amendment authority

P17-G6-01 is the dependency-ready distribution group after signed G6-02B and G6-03. It creates
and clean-installs local release candidates for four native targets, direct archives, npm/Bun, and
Homebrew. It publishes nothing. G6-04 remains the only group authorized to publish, attest, sign,
notarize, edit the external Homebrew tap, or claim public availability.

Implementation work reached the test-first gate under an earlier custom release-engine contract.
On 2026-07-26 the user explicitly approved replacing that design after asking for an industry-
practice and first-party-repository review. This amendment reopens the earliest affected lifecycle
gate, Ready. The earlier test-first receipt remains historical evidence but no longer authorizes
implementation because it tests a custom manifest, custom archive orchestration, and a precompiled
formula that this amendment rejects.

Primary ownership remains exactly four entities:

- `EWP-P6-T01` — native release assets and checksums;
- `EWP-P6-T02` — Homebrew and npm/Bun distribution;
- `EWP-P6-TS01` — clean-machine install smoke per distribution; and
- `P1-12` — distribution.

`EWP-P6-TS01` is the only required-now executable validation. `EWP-WF01` remains downstream,
release-tier, planned, and primarily owned by G6-04. The previous executable TS01 body is
quarantined as a superseded red until a fresh Ready review passes; it must then be replaced and a
new implementation-free red recorded before product implementation resumes.

## Why the previous design is rejected

The previous contract combined valid security goals with one invalid proxy: it rejected the
absolute repository checkout path anywhere in a compiled executable. Bun bundles imported source,
npm packages, and its runtime, and has no documented `-trimpath` or compiler prefix-map equivalent.
Build paths in an executable can therefore be a toolchain/reproducibility characteristic without
being a credential, configuration file, or shipped source tree.

Trying to eliminate that string by recursively collecting and copying source dependencies would
create a private package manager and synthetic build tree. It would hide one symptom while adding
resolution, symlink, export-map, workspace, optional-dependency, and cache correctness risks. This
group therefore has a hard architecture prohibition:

> No release code may recursively collect, copy, vendor, or reconstruct the repository or its
> dependency graph to make Bun compile from a synthetic source tree.

The accepted controls are credential/configuration canaries, isolated configuration roots,
disabled Bun dotenv/bunfig autoload, gitleaks, exact artifact inventory, and build-once byte
identity. An ordinary checkout path is not a secret-leak failure criterion. Source-path removal can
be reconsidered only if Bun adds a documented prefix-map/trim-path facility or a reproducibility
project supplies a toolchain-supported method.

The old public `release-manifest.json` was also redundant: it had no consumer and duplicated
checksums, target metadata, and source identity. GoReleaser's internal `artifacts.json` and
`metadata.json` provide the candidate inventory; `SHA256SUMS` covers GitHub release assets; G6-04
adds GitHub artifact attestations; and npm trusted publishing supplies npm provenance. No custom
public manifest is generated.

## Research and first-party precedents

The design combines standard tooling with the strongest local release patterns instead of copying
one repository wholesale.

The first-party repositories were cloned and inspected at exact revisions:

- `smorin/toggle@3bc7daf48e9677004943cd23324ae522f5bd7b3a` proves build-once fan-out:
  its npm job downloads the already-created release archives, places those exact binaries in four
  tracked platform packages, stamps one tag version, publishes payload packages before the
  launcher, and uses npm trusted publishing. Its release-please and release jobs also provide tag
  provenance, non-cancel concurrency, protected environments, and short-lived GitHub App tokens.
- `smorinlabs/py-launch-blueprint@761e5829fa512a638e03d74437220ca33b6dcf67` proves the split
  between release-please, a tag/version guard, one built artifact, and protected OIDC publication.
- `smorinlabs/ts-launch-blueprint@808f11a27bb8bc4e3c8362f7057ceb55c4782668` proves deny-all
  workflow permissions, full-SHA action pins, tag/manifest equality, protected npm publication,
  trusted publishing, and a package-file-list dry run.
- `smorinlabs/homebrew-tap@19c3cd296546c7ef0a0a8056a986524238a9e1a9` is the existing public
  destination. Its policy says updates use pull requests and direct pushes to `main` are avoided.

Toggle's tracked optional platform packages and exact-byte reuse are retained. Its Node-only
launcher is not copied because Skillsmith requires both npm-without-Bun and Bun-without-Node. Its
precompiled `Formula/togl.rb`, direct push to the tap, floating action references, and lack of
artifact attestations are not precedents for new Skillsmith work.

Official mechanism research establishes these boundaries:

- Bun's documented executable interface is `bun build --compile`; imported packages and files are
  bundled automatically.
- GoReleaser has a first-class, currently experimental Bun builder plus standard target matrices,
  archives, checksums, artifact metadata, snapshots, and Homebrew cask generation.
- GoReleaser's npm publisher is deliberately not used: it is Pro/alpha, downloads binaries during
  postinstall, and is incompatible with the accepted `--ignore-scripts` installation contract.
- npm directly supports exact optional dependencies plus `os`, `cpu`, and `libc` platform filters,
  and trusted publishing automatically emits provenance for eligible public packages.
- Homebrew directs precompiled/binary-only distributions to casks; GoReleaser has deprecated its
  old precompiled-formula generator in favor of casks.

## Retained prerequisites and truth boundaries

- G6-02B owns byte-stable `completion bash|zsh|fish` output. G6-01 packages those exact bytes and
  never edits shell startup files.
- G6-03 owns version/capability documentation generation and invocation-scoped rendering. G6-01
  packages those signed runtime bytes.
- Root, CLI, and core versions remain release-please-managed and lockstep. Release staging reads
  and validates them but never edits them.
- The native matrix remains exactly macOS arm64/x64 and glibc Linux arm64/x64. Windows and musl are
  excluded.
- A Bun compiled executable is standalone with respect to Bun/Node and repository dependencies;
  this plan does not claim Linux binaries are fully static. Linux packages declare `libc: glibc`.
- G6-01 candidate evidence is not release evidence. G6-04 must bind a candidate to the exact
  release tag and commit before any external action.

## Exact target and artifact contract

The target matrix is closed and ordered for project validation:

| Order | Target ID | Bun target | GoReleaser OS/arch | npm `os` | npm `cpu` | npm `libc` |
|---:|---|---|---|---|---|---|
| 1 | `darwin-arm64` | `bun-darwin-arm64` | `darwin/arm64` | `darwin` | `arm64` | absent |
| 2 | `darwin-x64` | `bun-darwin-x64` | `darwin/amd64` | `darwin` | `x64` | absent |
| 3 | `linux-arm64` | `bun-linux-arm64` | `linux/arm64` | `linux` | `arm64` | `glibc` |
| 4 | `linux-x64` | `bun-linux-x64` | `linux/amd64` | `linux` | `x64` | `glibc` |

For version `<version>`, GitHub release candidates are exactly:

- `skillsmith-v<version>-darwin-arm64.tar.gz`;
- `skillsmith-v<version>-darwin-x64.tar.gz`;
- `skillsmith-v<version>-linux-arm64.tar.gz`;
- `skillsmith-v<version>-linux-x64.tar.gz`; and
- `SHA256SUMS`.

`SHA256SUMS` contains exactly four LF-terminated, raw-path-sorted lines in the standard
`<sha256><two spaces><archive-name>` form. It covers only the four GitHub archive assets. It does
not hash itself, npm tarballs, a cask, GoReleaser metadata, raw binaries, or internal directories.

Each archive contains exactly this set; entry order is tool-owned and not a project contract:

```text
LICENSE
completions/_skillsmith
completions/skillsmith.bash
completions/skillsmith.fish
skillsmith
```

GoReleaser records `root/root`, mode `0755` for `skillsmith`, and mode `0644` for every other entry.
Archive timestamps are tool-owned and are not a reproducibility contract. The license is
Apache-2.0. Archive consumers reject absolute,
traversal, symlink, device, duplicate, missing, extra, or oversized entries before executing an
extracted candidate.

The internal GoReleaser directory additionally contains four raw binaries, `artifacts.json`,
`metadata.json`, and `homebrew/Casks/skillsmith.rb`. The npm adapter creates five tarballs below an
internal npm candidate directory. Tests consume these standard outputs, but G6-04 uploads only the
five GitHub assets above and publishes npm/cask through their own channels.

For every target, the SHA-256 of the raw GoReleaser binary must equal the binary extracted from its
direct archive and its npm platform tarball. The cask SHA/URL branch must identify the matching
archive. No downstream channel recompiles or downloads a different binary.

Every raw binary is strictly smaller than 128 MiB (`134217728` bytes) before fan-out. Metadata-only
boundary tests accept `134217727` and reject `134217728` and `134217729` without allocating those
buffers. GoReleaser's size report is supplementary; the project gate remains fail-closed.

## Controlled, credential-free candidate build

Do not call the build hermetic. The compatibility spike proved that a cold Bun cross-target cache
downloads target runtimes for non-host targets; a warm second run reused them. Bun documents no
offline prefetch contract for all compile targets. The accurate flow is:

1. checkout the exact intended commit and install repository dependencies with the frozen Bun
   lockfile;
2. install/checksum-verify the exact GoReleaser version and install the exact npm version;
3. allow an unprivileged, credential-free preparation stage to acquire Bun's official cross-target
   runtimes when the pinned toolchain requires them;
4. launch GoReleaser from an explicit allowlisted environment and isolated HOME/XDG/tmp roots;
5. record whether the runtime cache was cold or warm and never claim network-free execution unless
   the runner separately enforces and proves it; and
6. keep publish credentials, npm OIDC authority, Apple credentials, and tap write authority out of
   the G6-01 unsigned candidate-build job.

The allowlisted child environment contains only the exact tool `PATH`, isolated `HOME`, `TMPDIR`,
`XDG_CONFIG_HOME`, `XDG_CACHE_HOME`, `XDG_DATA_HOME`, `LANG=C.UTF-8`, `LC_ALL=C.UTF-8`, `TZ=UTC`,
`NO_COLOR=1`, the explicit GoReleaser tag override used for local snapshots, and narrowly required
CI identity values. It does not inherit registry credentials, GitHub tokens, cloud credentials,
signing values, proxy credentials, or arbitrary parent variables. The wrapper verifies
GoReleaser's reported version before execution.

Local G6-01 candidate builds use `goreleaser release --snapshot --clean` with
`snapshot.version_template: "{{ .Version }}"` and an explicit `GORELEASER_CURRENT_TAG` derived
from the validated root version. This keeps archive and cask versions equal without publishing.
This unsigned characterization path never becomes a release artifact. G6-04 uses the protected
exact-tag sequence below instead of a normal publishing invocation.

TS01 injects unique credential and configuration-content canaries into the parent environment and
into isolated `.env`, `bunfig.toml`, HOME, and XDG fixtures. Bun compile keeps
`--env=disable`, `--no-compile-autoload-dotenv`, and `--no-compile-autoload-bunfig`. Exact-byte scans
must find no canary content in logs, raw/extracted binaries, archives, npm tarballs, cask, checksums,
or internal metadata. The candidate tree passes redacted repository-configured gitleaks scanning.
Failures name only the canary class, never its value.

The absolute checkout path is intentionally not a canary or rejection criterion. Reproducible
native bytes are also not claimed: two Bun 1.3.14 compiles can differ. Integrity is the one-build
fan-out plus G6-04 provenance, not unsupported byte-for-byte rebuild equality.

## npm and Bun package model

Track ordinary source manifests instead of manufacturing package identity dynamically:

- launcher manifest: `packaging/npm/package.json`;
- payload manifests: `packaging/npm/platform/<target>/package.json` for all four targets; and
- launcher executable: `packaging/npm/bin/skillsmith.cjs`.

Tracked manifests use non-publishable staging version `0.0.0`. The adapter copies only the declared
files into ignored staging directories, stamps the validated candidate version and exact-version
optional dependencies there, copies the already-built target binary, and runs
`npm pack --ignore-scripts`. It never edits tracked manifests or release-please-managed versions.

Package identity remains:

- launcher `@smorinlabs/skillsmith` with public bin `skillsmith`;
- `@smorinlabs/skillsmith-darwin-arm64`;
- `@smorinlabs/skillsmith-darwin-x64`;
- `@smorinlabs/skillsmith-linux-arm64`; and
- `@smorinlabs/skillsmith-linux-x64`.

All five packages declare Apache-2.0 and the exact public repository URL required for npm
provenance. Platform manifests use exact `os`/`cpu` and Linux `libc` constraints. The launcher has
exact-version `optionalDependencies` on the four payloads and has no install/postinstall script,
network downloader, workspace dependency, source runtime, or shell-startup mutation.

The launcher begins with `#!/bin/sh`, followed by these exact UTF-8/LF bootstrap statements:

```text
':' //; runtime="$(command -v bun 2>/dev/null || command -v node 2>/dev/null)" || { echo "skillsmith requires Bun or Node.js" >&2; exit 1; }
':' //; exec "$runtime" "$0" "$@"
```

No semicolon may appear between either leading string literal and `//`. The existing Biome override
remains limited to formatting this one file; linting remains enabled. The launcher preserves argv,
stdin/stdout/stderr, numeric exit, and signal settlement, and emits one actionable error for
unsupported platform, omitted/missing payload, or no Bun/Node runtime.

The packed launcher entry set is exactly:

```text
package/package.json
package/README.md
package/LICENSE
package/bin/skillsmith.cjs
package/share/completions/skillsmith.bash
package/share/completions/_skillsmith
package/share/completions/skillsmith.fish
```

`package/bin/skillsmith.cjs` is mode `0755`; every other launcher entry is `0644`. Each payload
tarball contains exactly `package/package.json`, `package/README.md`, `package/LICENSE`, and
`package/bin/skillsmith`; its binary is mode `0755` and the other entries are `0644`. The launcher
completion entries equal the signed G6-02B bytes at those exact paths.

Clean installation uses a loopback-only five-package registry and empty HOME/prefix/cache/config/
temp/work roots. npm-without-Bun and Bun-without-Node install only the launcher and allow the real
optional-dependency metadata to select exactly one host payload. Unknown or denied network routes
fail. Tests inspect the complete packed/installed tree, run version/help/all completions, exercise
argv/stdio/exit/signal behavior, and cover `--omit=optional`, missing payload, unsupported target,
and absent runtime.

G6-04 later publishes payload packages first and the launcher last, skips already-published exact
versions for idempotent partial-failure recovery, and uses one trusted-publisher configuration per
package with `npm publish`. No GoReleaser npm publisher is involved.

## Homebrew cask and existing tap

Generate `homebrew/Casks/skillsmith.rb` through GoReleaser. The cask uses the four archive branches,
`binary "skillsmith"`, and Bash/Fish/zsh completion stanzas. Each referenced archive carries the
Apache-2.0 `LICENSE`; Homebrew's cask DSL has no formula-style SPDX `license` stanza. The cask
contains no `preflight`, `postflight`, `xattr`, quarantine-removal, curl, installer script, or
source-build workaround.

G6-01 validates the untouched production cask's GoReleaser generation, Ruby syntax, cask style/audit
where locally available, and all GitHub URL/SHA branches. Lifecycle tests copy that cask only into a
disposable test tap and replace each of the four two-line `url ..., verified: ...` stanzas with one
syntactically valid loopback `url` line. A parsed/diffed allowlist requires that only the URL origin,
the production `verified` metadata, and the required trailing-comma removal differ. The production
cask is never rewritten.

The production-derived lane's loopback server serves only the exact local candidate archives and
records every request; unknown routes fail. Tests set `HOMEBREW_NO_AUTO_UPDATE=1`,
`HOMEBREW_NO_INSTALL_FROM_API=1`, and `HOMEBREW_NO_ANALYTICS=1`, isolate Homebrew
cache/config/temp/tap state around the runner's standard Homebrew prefix, point HTTP(S) proxies at
a deny listener, inventory the prefix before/after, and fail any non-fixture request. That lane
proves candidate install, execution, all three completion bytes, installed-binary SHA-256 equality
with the local candidate/archive binary, and residue-free uninstall. It does not claim upgrade.

A separate immutable lifecycle-fixture lane owns Homebrew upgrade behavior. It declares two
test-only archive/cask lineages, `.fixture.1` and `.fixture.2`, and serves only their exact reviewed
loopback routes. Starting from one reviewed fixture cask, the second may differ only in the version,
the four loopback URLs, and the four SHA-256 values computed from the declared fixture archives;
parsed semantic and textual diffs enforce that allowlist. The lane performs a real `brew upgrade`,
proves the installed bytes change from the exact `.fixture.1` payload to the exact `.fixture.2`
payload, rechecks execution and all three completion placements, and proves residue-free uninstall.
These fixtures are never derived from or substituted for the production candidate, and fixture-byte
canaries must remain absent from every raw candidate, direct archive, npm tarball, checksum, and
production cask.
Both receipt lanes use Homebrew's current documented `brew install --cask` and `brew upgrade --cask`
interfaces without a quarantine bypass. Homebrew removed `--no-quarantine`; the test must not
recreate that bypass with `xattr`, hooks, or another mechanism. The production cask contains no
bypass, and this functional receipt is not a substitute for G6-04 signing, notarization, stapling,
or public Homebrew readiness.

G6-04 must, before opening the tap PR:

1. sign and notarize both macOS binaries with standard Apple tooling or reviewed GoReleaser support;
2. staple/validate where applicable and execute a clean macOS cask install without quarantine
   bypasses;
3. generate the final cask from the exact signed archive bytes;
4. mint a short-lived GitHub App token scoped to `smorinlabs/homebrew-tap`;
5. open a reviewed PR adding `Casks/skillsmith.rb` rather than pushing directly to `main`; and
6. extend the tap's CI with cask syntax/install coverage and immutable action pins.

If Apple credentials are unavailable, G6-04 is blocked: no GitHub asset, npm package, or tap change
may publish, G6-04 cannot sign off, Phase 6 cannot exit, and P17 cannot complete. Partial channel
publication would require a separate explicit amendment to the consolidated Phase-6 contract,
catalog, EWP-P6-TS06, EWP-WF01, and D-016. An xattr bypass is never an alternative.

## Frozen G6-04 exact-tag promotion order

G6-04 must preserve this order; no job may collapse or reorder the irreversible boundaries:

1. release-please uses a short-lived App token to create the exact tag and a draft GitHub Release.
   The release-please manifest, root/CLI/core versions, tag, tag target, default-branch ancestry, and
   selected source SHA must agree before any candidate job starts. The draft is not made public.
2. A protected release-candidate job receives only Apple signing/notarization credentials—no npm
   OIDC authority, GitHub release-write token, or tap token—and invokes exact GoReleaser with
   publication disabled (`release --clean --skip=publish,announce`).
3. GoReleaser compiles each target once, then its reviewed `notarize.macos` stage signs and
   notarizes both macOS raw binaries before any archive/checksum/cask stage. It waits for and
   validates notarization. From that point onward those final signed bytes are immutable.
4. GoReleaser creates all four archives, `SHA256SUMS`, `artifacts.json`, `metadata.json`, and the
   cask from those final raw binaries. Only after it succeeds does the thin adapter stage all five
   npm tarballs from the same final raw binaries. No signing or binary mutation occurs afterward.
5. Credential-free validation jobs consume the transferred candidate and run the complete exact-
   SHA release check: raw/archive/npm byte identity, archive and checksum closure, notarization and
   no-bypass assessment, direct/npm/Bun/cask clean installs, version/source equality, leak/size
   gates, cask/tap candidate checks, npm dry runs, generated clean diff, live-tool receipts, and
   attestation-subject inventory. Every required validation must pass with no skip.
6. Only after that gate succeeds may separate dependent publication jobs receive their narrow
   authorities: GitHub assets plus artifact attestations and draft-release publication; five npm
   trusted-publisher operations in payload-first order; and a short-lived App token that opens the
   reviewed `smorinlabs/homebrew-tap` cask PR. Publication reruns are exact-version/idempotent and
   may never rebuild, resign, rearchive, or restage different bytes.

The final Phase-6/P17 availability receipt still requires every declared channel, including the
merged tap cask, to pass its public clean-install/orientation workflow. A successful local candidate
alone is not completion.
