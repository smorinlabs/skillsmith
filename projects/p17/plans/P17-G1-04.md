# P17-G1-04 implementation plan

P17-G1-04 replaces the overbroad `ScanEnv` dependency in current domain and application signatures
with capability-scoped ports, typed resolved runtime configuration, one real adapter composition,
and a deprecated 1.x compatibility facade. Primary IDs are `EWP-CF-034`, `EWP-P1-T10`, and
`EWP-P1-TS08`. P17-G1-03 is signed off at `cd7ec024dc9beef0872dfd06eaa72024fffe2966`;
its accepted runtime implementation is `3fb4c1a86d424be9010f04394a5546a4eedd93ac`.

Required-now validation is exactly `EWP-P1-TS08` plus signed `EWP-WF15`. `EWP-WF11` and
`EWP-WF16` remain downstream-only: this group supplies reusable deterministic clock/ID and
documentation/compatibility foundations but does not activate future migration, undo, GC, or
manual-workflow scenarios.

The frozen capability model contains cohesive `PlatformPaths`, `FileReadPort`, `FileWritePort`,
`LockPort`, `PathAccessPort`, `ProcessPort`, high-level `GitPort`, `HttpPort`, `ClockPort`, and
`IdPort` contracts.
`HttpPort` closes the existing doctor network-check ambient `fetch` gap; the accepted list is a
minimum rather than permission to leave network I/O ambient. `RuntimePorts` exists only at the
composition/application boundary. Downstream functions accept named structural subsets such as
inventory-read, detection, Git-read, placement-read/write, verification, or acquisition ports and
never the aggregate.

Raw environment is resolved once into frozen `ResolvedRuntimeConfiguration`. The whitelist covers
current Skillsmith config/home/tool/scope/path/registry inputs, XDG/PATH-derived platform paths,
tool-specific homes and current feature toggles, color/automation inputs, and the decoded test-only
journal pause. Unknown names and secret canaries are discarded. Domain/application requests do not
receive `process.env`, `envVars`, or an unfiltered string record.

`defaultRuntimePorts()` owns the sole production Node/Bun implementations. Deprecated
`defaultScanEnv()` remains public through 1.x as a thin view over the same path/read/write/lock/
process adapters. `runtimePortsFromScanEnv()` is confined to the compatibility module so existing
embedders and test fakes continue to work without a second real implementation. ScanEnv gains no
new clock, ID, Git, or HTTP members and is removable no earlier than 2.0.

## Frozen interface contract

- `PlatformPaths` has readonly `homeDir`, `executableSearchPath`, `platform`, and `{config,data,cache}`
  XDG paths. `FileReadPort` retains focused `fileExists`, `pathKind`, `realpath`, `listDir`,
  `readText`, `readBytes`, `readLink`, `isExecutable`, and `modifiedAt` operations. `FileWritePort`
  retains `makeDir`, `writeTextFile`, `makeSymlink`, `rename`, `copyTree`, `removeTree`, `fsyncFile`,
  and `fsyncDir`. `LockPort` exposes only `withFileLock`.
- `ProcessPort` exposes `exec(command,args,options)` plus `runVersion`; detection receives only
  `Pick<ProcessPort, 'runVersion'>`. `GitPort` exposes intent-level `findRepositoryRoot`,
  `inspectWorktree`, `resolveRemoteRef`, `initializeFetch`, `fetchRef`, `listTree`, `readBlob`, and
  `materializeTree` request/result operations—never argv. `HttpPort` exposes one bounded
  `request({url,method,headers,timeoutMs,signal})` operation used by the existing network check.
- `PathAccessPort` exposes only `assertWritableDirectory(path)`. On failure its safe error context
  carries the POSIX real UID reported by `process.getuid()` for the existing diagnostic wording. It
  closes the scope-writable `fs.access` seam without mutating the probed tree or routing a
  cross-platform filesystem capability through a shell.
- `ClockPort` exposes `wallNowIso`, `epochMilliseconds`, and `monotonicMilliseconds`. `IdPort`
  exposes `nextId(purpose)` for current transaction, staging, and temporary-file purposes; no
  correlation/event identity from G1-07 is introduced.
- Real async adapter failures reject with a safe `PortError` carrying exact `capability`,
  `operation`, `code` (`not-found | permission | unavailable | timeout | cancelled | conflict |
  invalid | io`), `message`, and scalar `context`. Raw causes are not exposed. Existing public
  coordinators catch these at their current `Result<_, SkillSmithError>` boundary; compatibility
  ScanEnv methods unwrap to the same legacy promise behavior and sanitized messages.
- Focused bundles are named structural intersections. Read-only inventory is
  `PlatformPaths & FileReadPort`; detection adds only the version probe; Git-aware reads add
  `{git: GitPort}`; mutation bundles add only the required write/lock/process/clock/id capabilities.
  Only `ApplicationContext` and adapter construction may name `RuntimePorts`.

`ResolvedRuntimeConfiguration` is frozen and contains only: `configLayer` (decoded
`SKILLSMITH_TOOL`, `SKILLSMITH_SCOPE`, `SKILLSMITH_PATH`, `SKILLSMITH_REGISTRY`),
`explicitConfigPath`, `skillsmithHome`, `claudeConfigDir`, `claudePolicySkillsDisabled`,
`claudeManagedSettingsPath`, `codexHome`, `kiloExternalSkillsDisabled`, `opencodeConfigDir`,
`opencodeClaudeSkillsDisabled`, `forceColor`, `noColor`, and decoded optional `journalPause`.
Platform PATH/XDG/home values live only in `PlatformPaths`; `SKILLSMITH_E2E` is consumed only while
decoding the test pause. Every other raw key and value is discarded.

Static allowlists are exact. `process.env`/cwd may occur only in CLI runtime composition and the
default/compatibility adapter modules; filesystem/process/lock imports only in real adapters;
`fetch` only in the HTTP adapter; Git argv/`execGit` only in Git infrastructure/compatibility;
Date, monotonic timers, randomness, UUIDs, and process IDs only in clock/ID/default adapters.
`ScanEnv` imports are allowed only in env types/default, ports compatibility, public re-exports,
and explicit compatibility tests. Domain modules cannot import real adapters, `RuntimePorts`, or
raw runtime configuration.

**2026-07-12 consistency amendment:** migration of the existing `scope-writable` check found its
read-only `fs.access(W_OK | X_OK)` plus POSIX real-UID probe was not representable by the initial
frozen contracts. `PathAccessPort` was added as the smallest high-level capability. Allowlisting the
ambient import, probing by mutation, or executing platform-specific shell commands would contradict
the same ownership and behavior-preservation rules. No command, output, or later-group behavior is
added by this amendment.

TS08 is test-first and must cover ten executable families:

1. exact public port, `RuntimePorts`, typed-config, compatibility, and structured `PortError` shapes;
2. no `ScanEnv`/`RuntimePorts` domain or application signatures outside the compatibility allowlist;
3. compile-negative focused read capability that can read/list but cannot write/remove/lock/exec;
4. focused-fake versus ScanEnv-compatibility behavioral parity with no unrelated fake methods;
5. one-real-implementation delegation and static infrastructure import ownership;
6. typed configuration whitelist and secret-canary isolation from requests, reports, and JSON;
7. high-level Git operations with no domain Git argv, `execGit`, or arbitrary process access;
8. structured filesystem/process/Git/HTTP failures rather than leaked Node/Bun exceptions;
9. deterministic wall/monotonic time and ID behavior for current transaction/journal/sweep seams;
10. lint/import gates for ambient environment, cwd, time, randomness, network, and real adapters.

Implementation proceeds in seven ordered slices:

1. Commit TS08 and compile-negative fixtures genuinely red while WF15 remains green.
2. Add ADR 0005, port/config/error types, semantic focused bundles, and public compatibility
   declarations; freeze these interfaces before parallel migration.
3. Implement the sole real adapters, high-level Git/HTTP adapters, typed configuration resolver,
   `defaultRuntimePorts()`, and the thin ScanEnv compatibility views.
4. Migrate read-side config/context/detect/agents/skills/commands/plugins/scan/doctor signatures and
   read application services to focused subsets.
5. Migrate verify/acquire/place signatures through Git/process/write/lock/clock/ID subsets and
   lifecycle services without changing reports, wire bytes, journals, or exit behavior.
6. Replace `CurrentApplicationContext.env/envVars` with ports plus typed configuration at the CLI
   composition root; remove ambient fallbacks from focused code while retaining explicit 1.x
   compatibility entry points.
7. Activate static/lint closure, replay compatibility/focused parity, WF15, current core/CLI suites,
   full `bun run check`, adversarial review, and traceability closure.

After the interface/red commits, parallel ownership is disjoint. Root owns docs/ADR, eslint,
`core/src/ports/**`, `config/runtime.ts`, env/default/exec/git, public exports,
application/CLI context integration, catalog, evidence, and commits. Planned test owner
`/root/g1_04_ts08` owns only TS08 and `fixtures/p1-ts08/**` until red commit. Planned read owner
`/root/g1_04_read_migration` owns agents, commands, config read paths, context, detect, doctor,
plugins, scan, skills, verify-read signatures, and focused tests. Planned effect owner
`/root/g1_04_effect_migration` owns acquire, place, config save, write/lock/Git/process/clock/ID
signatures, and focused tests. Shared application/public-export files remain root-only.

The immutable catalog baseline truncates the display title of `EWP-P1-T10` after `Process/` and
rejects title mutation. This plan and the canonical multiline Phase-1 task retain the complete
Git/HTTP/Clock/Id, typed-config, composition, and compatibility scope; evidence records the display
limitation rather than falsifying the immutable entity.

Prohibited scope: G1-05 tool descriptor/bundle registry and tool-behavior changes; G1-06 DTO,
codec, schema, or JSON redesign; G1-07 `OperationContext`, observer events, diagnostic sinks, or
verbosity behavior; Phase-2 artifacts; future repository/coordinator/undo/GC behavior; Phase-6
generated help/manual execution; new commands/options; and removal or shape growth of the public
1.x ScanEnv facade. Existing report bytes, exits, prompts, tool capability behavior, journal schema,
and CommandSpec/runtime ownership remain invariant.
