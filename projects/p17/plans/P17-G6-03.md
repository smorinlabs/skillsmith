# P17-G6-03 plan: rendering, compatibility cleanup, and current user guidance

## State and coherent boundary

P17-G6-03 is the dependency-ready rendering and documentation group after signed G6-02A. It
finishes the inherited human-presentation policy, removes disconnected direct CLI dependencies,
cleans the ordinary observation path without breaking the promised 1.x Logger compatibility
facade, and makes the current version/capability/install/upgrade documentation derive from live
authorities. It prepares a completed rendering, dependency, and documentation graph for G6-01 to
package; it does not build or claim a distribution channel.

Primary ownership is exactly four entities:

- `EWP-P6-T05` — color/observer, legacy-logger, and dependency cleanup;
- `EWP-P6-T06` — version/capability matrix and install/upgrade docs;
- `EWP-P6-TS03` — the TTY/pipe/color/quiet/JSON rendering suite; and
- `P2-08` — dependency/render cleanup.

Required-now is exactly one executable validation, `EWP-P6-TS03`. `EWP-WF01` remains downstream
and planned under G6-04. Signed P0-01, P2-06, the agents/help contracts, EWP-P1-TS05,
EWP-P1-TS11, and EWP-P6-TS04 are compatibility authorities that must be rerun; they do not become
new primary entities or move lifecycle ownership.

## Existing implementation and exact gaps

The current runtime already provides most semantic behavior:

- quiet, normal, verbose, trace, and debug resolve through one observation sink;
- verbose/trace/debug diagnostics are buffered and settled before canonical command output;
- observer failures cannot change outcomes, writes, rollback, or exits;
- JSON renderers emit strict versioned data and current JSON tests contain no ANSI;
- `agents --capabilities` already renders the registry-derived capability snapshot; and
- the package, core, and explicit/global version surfaces agree on `0.7.0`.

The remaining gaps are specific and measurable:

- `resolveColorMode` exists, but no human renderer uses Chalk. `--color always version` is byte
  identical to plain output, and even a pseudo-TTY help run contains zero ANSI escapes.
- preflight mutates global `NO_COLOR`/`FORCE_COLOR` process state instead of carrying a resolved
  invocation policy. That leaks presentation state across embedded/repeated program runs and does
  not model stdout and stderr independently.
- current unit characterization lets `--color always`, `FORCE_COLOR`, and `CLICOLOR_FORCE` color a
  non-TTY stream, contrary to the consolidated P0-01 acceptance that color never contaminates
  piped output.
- the runtime quiet filter already suppresses human report stdout and retains stderr. G6-03 must
  preserve the signed distinction instead of widening suppression: warning/deprecation and
  error/refusal stderr remain visible, observation detail remains silent, and JSON is never
  suppressed.
- `chalk`, `consola`, and `zod` are direct CLI dependencies with zero production imports. Chalk is
  the selected presentation library; `consola` and CLI-level `zod` have no owned use and must be
  removed. Core retains its own Zod dependency and codecs.
- ordinary direct scan/inventory calls currently synthesize an observation by adapting
  `noopLogger`. Only an explicitly supplied deprecated Logger should traverse the legacy adapter;
  native no-logger calls should use a no-op typed observer bundle.
- README capability support is hand-written prose, the install section is source-build-only with
  no upgrade procedure, and the current generator owns only the command index. These facts can
  drift from the registry and package version.

## Invocation-scoped presentation design

Add one CLI-owned `runtime/presentation.ts` seam. It consumes only requested format/color flags,
per-stream TTY facts, a filtered environment view, report kind, and already-rendered output. It
does not receive domain state, application ports, the observer, or raw throwable data.

The exact color precedence for each output stream is:

1. JSON is always color-off.
2. A non-TTY destination is always color-off, including explicit `always`, `FORCE_COLOR`, and
   `CLICOLOR_FORCE`. This deliberately replaces the current disconnected characterization and
   closes P0-01's no-piped-color requirement.
3. `--no-color`, `--color never`, nonempty `NO_COLOR`, and `CLICOLOR=0` disable color.
4. On a TTY, `--color always` enables color; otherwise `TERM=dumb` disables it.
5. On a TTY, nonempty `FORCE_COLOR` or `CLICOLOR_FORCE` enables color; normal `auto` enables it.

Stdout and stderr resolve independently. An embedder-supplied `CliRuntimeIo` exposes optional
readonly TTY facts; absence means non-TTY. Production maps those facts from the corresponding
process streams. Preflight validates option relations but never mutates `process.env`.

Color is a lossless human projection: stripping ANSI from colored bytes must reproduce the exact
plain renderer bytes. Styling is deliberately small and semantic:

- Markdown/help headings use bold cyan;
- `error:` uses bold red, `warning:` bold yellow, and explicit success labels bold green;
- the version report uses cyan; and
- all other data, paths, table cells, JSON, completion scripts, and observer detail/trace/debug
  lines remain byte-identical and unstyled.

The same seam covers runtime success/failure output, eager version, Commander help, usage errors,
failures before the command lifecycle starts, and the final rejected `main()` promise in
`packages/cli/src/index.ts`. It must not double-style existing escape input; the normalized error
boundary continues stripping hostile controls before presentation.

Quiet remains a semantic selection, not styling. It suppresses human report stdout and every
observation detail line, but it never suppresses warning/deprecation or error/refusal stderr.
Failure/cancellation retains its canonical error/refusal stream and exit. JSON ignores quiet and
remains one complete document on stdout. Verbose keeps the same canonical report and adds only the
current redacted observation lines to stderr. `-vv` and debug retain their signed trace/debug
grammar with zero ANSI.

## Observer and 1.x Logger compatibility cleanup

The public `Logger`, `noopLogger`, and `observationFromLegacyLogger` exports remain available and
deprecated. Exact legacy messages and recursive redaction remain covered for explicit 1.x callers.
No new production code may accept or emit free-form Logger messages.

The internal resolver follows this exact order:

1. use an explicitly supplied `ObservationBundle` by reference;
2. otherwise adapt an explicitly supplied deprecated `Logger`; or
3. otherwise construct a typed bundle backed by `noopObserver`.

`detectAll`, `listSkills`, `listCommands`, and the cross-scope doctor check use that resolver.
This removes `noopLogger` from ordinary production fallback paths without changing public option
shapes, event timing/order, scan results, diagnostics, or error behavior. The EWP-P1-TS11 parsed-AST
gate remains the static authority: Logger imports/calls stay confined to the compatibility
allowlist, and no CLI logging dependency replaces them.

## Dependency and native-size cleanup

`packages/cli/package.json` is reconciled with production imports:

- pin and use the already resolved `chalk` 5.6.2;
- retain exact `@bomb.sh/tab` 0.0.21, `@clack/prompts`, Commander 15, and the workspace core
  dependency because each has a live production owner;
- remove direct `consola` and direct CLI `zod`; and
- update `bun.lock` through Bun without changing unrelated dependency versions.

EWP-P6-TS03 statically closes every direct CLI dependency against an allowed production import or
documented package/runtime role. Under the repository-pinned Bun 1.3.14, it also compiles and runs a
current-host executable in an isolated temporary directory. The binary must print the package
version, contain the new rendering behavior, and remain below 128 MiB. The mapping baseline is
114,403,472 bytes on Linux x64; the portable 128 MiB ceiling catches material accidental bundling
while G6-01 retains ownership of exact four-target assets and checksums.

The CLI package README is updated to describe the complete 23-command runtime and the exact

## Explicit exclusions

formulae/taps, install scripts, release archives, provenance, or package-manager completion
placement. It does not change G6-01/G6-04 recipes, CI publication, tags, releases, exact-SHA gates,

persist observations, add OpenTelemetry, add trace/log files, add a log command, or add global CLI
options. It does not change JSON codecs/schemas, capability facts, tool IDs/order, verifier policy,
command count, aliases, options, exit classes, completion bytes, shell startup files, domain
results, planner/executor behavior, or interaction policy.

PowerShell, Windows-specific presentation, accessibility themes, user-configurable palettes,
progress spinners, localization, registry/search, man pages, and post-1.0 UI work remain outside
P17-G6-03.
