# P17-G6-04 plan: exact-SHA validation and controlled publication

## State and coherent boundary

P17-G6-04 is the terminal required Phase-6 group after signed G6-01. It converts the already
validated, single-lineage GoReleaser candidate into canonical PR and release recipes, proves that
the exact tagged source and exact candidate bytes pass every required gate, publishes those bytes
through GitHub, npm/Bun, and the existing `smorinlabs/homebrew-tap`, and finishes the first public
installation/orientation workflow. It does not design another packaging system.

Primary ownership is exactly four entities:

- `D-016` — complete the P0-P2 core workflow before 1.0;
- `EWP-P6-T07` — ADR 0010, canonical `just check` and `just release-check`, CI parity, and
  preparation/publication separation;
- `EWP-P6-TS06` — exact-SHA distribution and live-compatibility release gate; and
- `EWP-WF01` — first public installation and orientation.

Both executable validations, `EWP-P6-TS06` and `EWP-WF01`, are required now. There is no
downstream required validation. G6-04 cannot sign off, Phase 6 cannot exit, and P17 cannot complete
until both validations pass without a required skip and all three declared public channels are
available.

Signed G6-01 remains the packaging authority. Its four binaries, four archives, `SHA256SUMS`, five
npm tarballs, cask, GoReleaser `artifacts.json`, and `metadata.json` are the candidate graph. G6-04
may add the release-mode/signing seam and publication validators needed to promote that graph, but
may not replace GoReleaser, manufacture a second artifact graph, recursively copy dependencies, or
rebuild after the candidate gate.

provenance for this open-source CLI, final promotion requires a reviewed full-history/publication
audit and explicit authorization immediately before making `smorinlabs/skillsmith` public. Mapping,
Ready review, tests, workflow implementation, and hermetic dry runs may proceed while it remains
private; actual publication and G6-04 sign-off may not.

- `smorinlabs/homebrew-tap@19c3cd296546c7ef0a0a8056a986524238a9e1a9` is the public target

No one repository is copied wholesale. Toggle's precompiled formula, direct tap push, mutable npm
tool pin, and channel-parallel publication without a consolidated candidate gate are rejected.
Blueprint floating action references are rejected. Skillsmith retains the strongest shared
patterns while preserving G6-01's cask, script-free npm launcher, and one-build byte lineage.

Official documentation confirms the selected mechanisms:

- GoReleaser's cross-platform `notarize.macos` stage uses quill, signs and notarizes raw binaries,
  waits when configured, and makes the signed binaries the inputs to every later pipeline stage.
- GitHub recommends creating a draft, attaching all assets, and only then publishing an immutable
  release. `actions/attest` binds subjects to repository, workflow, environment, and commit.
- npm trusted publishing requires GitHub-hosted runners, Node at least 22.14, npm at least 11.5.1,
  `id-token: write`, an exact workflow filename, and an optional exact environment. It automatically
  emits provenance only for a public source repository and public package.
- Homebrew directs precompiled software to casks; the cask must rely on ordinary Gatekeeper
  signing/notarization and may not remove quarantine with `xattr` or a hook.

## Canonical ordinary PR gate

`just check` becomes the sole canonical ordinary PR recipe. It runs, in order:

1. Biome without writes;
2. ESLint architectural boundaries;
3. TypeScript no-emit checking;
4. generated command/capability/version documentation drift checking;
5. actionlint;
6. the P17 PR-openable catalog/package gate; and
7. `scripts/run-test-files-serial.ts`.

The final step discovers every Git-tracked Bun test file and runs it exactly once, serially, in a
fresh Bun 1.3.14 process under the signed G6-01 contract. It allows only the frozen 28 opt-in live
test skips. It never uses Bun `--isolate`, retries, shards, timeouts larger than the signed defaults,
or a monolithic process. The package scripts expose a named terminal-test convenience, but `just`
remains the recipe authority. The pre-push test command calls the same serial terminal runner and
retains its separate gitleaks, audit, and security-lint checks.

CI has one Linux ordinary-check job that installs exact tools and runs exactly `just check`; it
does not duplicate the recipe in YAML. A separate macOS supported-platform job retains G6-01's
Homebrew receipt and host-native smoke without rerunning the full repository suite. PR-title
validation remains a separate cheap job. Workflow top-level permissions are deny-all, credentials
are not persisted by checkout, and all action pins are immutable.

## Release-please preparation boundary

`.github/workflows/release-please.yml` has one serialized, non-cancelling job on `main`:

1. mint a short-lived GitHub App installation token from the release-please App credentials;
2. fail closed rather than fall back to `GITHUB_TOKEN` or a long-lived PAT;
3. run exact release-please v5 with deny-all top-level permissions and only job-local
   `contents: write` plus `pull-requests: write`; and
4. use `release-please-config.json` with `draft: true` so merging the release PR creates the exact
   tag and a draft GitHub Release, never a public empty release.

release-please remains the sole editor of root/CLI/core versions, the manifest, and changelog. The
release workflow never bumps, rewrites, or commits a version.

## Exact release workflow graph

`.github/workflows/release.yml` is triggered by an exact SemVer `v*` tag. It may also expose a
manual rerun path that names an already-existing exact tag; a dispatch may not invent a SHA or
version. Top-level permissions are `{}`, release concurrency is keyed by tag, and
`cancel-in-progress` is false.

The dependency graph is fixed:

```text
tag guard
   |
   v
protected candidate (Apple credentials only)
   |
   v
credential-free release-check
   |--------------------|
   v                    v
GitHub publish       npm publish
   |
   v
tap PR
```

No publication job is runnable unless the exact candidate validation job succeeds.

### 1. Exact tag guard

The unprivileged guard checks out full history at `GITHUB_SHA` and requires all of the following:

- the event resolves to one annotated or lightweight tag matching the exact accepted SemVer form;
- `git rev-parse <tag>^{commit}` equals `GITHUB_SHA`;
- `GITHUB_SHA` is an ancestor of the freshly resolved protected default branch;
- tag version, release-please manifest, and root/CLI/core package versions are identical;
- the draft GitHub Release exists for the tag, targets the same commit, and is not public; and
- the checked-out tree is clean and generated references are current.

Any mismatch fails before a job can access Apple, npm, release-write, or tap authority.

### 2. Protected candidate job

The `release-candidate` environment contains only these Apple values:

- `MACOS_SIGN_P12`;
- `MACOS_SIGN_PASSWORD`;
- `MACOS_NOTARY_KEY`;
- `MACOS_NOTARY_KEY_ID`; and
- `MACOS_NOTARY_ISSUER_ID`.

It has no npm authority, no release-write permission, and no tap App credentials. It installs the
exact Bun, GoReleaser, npm/Node, gitleaks, and dependency graph, then invokes the existing
Skillsmith adapter in release mode. Release mode differs from the signed snapshot path only in
these bounded ways:

- the repository must be at the exact release tag and SHA;
- all five Apple values must be present, with no secret written to the candidate;
- GoReleaser runs `release --clean --skip=publish,announce`, never `--snapshot`; and
- `.goreleaser.yaml` enables `notarize.macos` only for the `skillsmith` build, signs both Darwin
  raw binaries, waits for successful notarization, and fails closed on missing credentials.

GoReleaser compiles each of the four targets once. Signing/notarization happens before archives,
checksums, cask, and npm staging. The adapter validates the same G6-01 inventory and stages the
five npm tarballs from the final raw bytes. A redacted gitleaks scan and canary scan cover the
complete output. The candidate is transferred as a private short-retention Actions artifact; it is
not a public distribution and may not be rebuilt by downstream jobs.

### 3. Credential-free `just release-check`

The validation job checks out the exact tag/SHA, downloads the one candidate, installs exact public
tools, and has no environment, secret, OIDC, release-write, or tap permission. `just release-check`
accepts no free-form source/tag/version override. It derives identity from the exact checkout and
requires the transferred candidate root.

It runs the canonical ordinary `just check`, then proves:

- exact tag/SHA/default-branch/version/manifest/candidate-metadata equality;
- exactly four supported target binaries and archives and exactly five npm packages;
- macOS signatures/notarization and no quarantine-removal bypass;
- raw/archive/npm byte identity, archive layout/modes, completion identity, and `SHA256SUMS` closure;
- runnable host-native smoke and direct/npm/Bun/cask candidate install, upgrade, uninstall, and
  clean-prefix behavior on supported runners;
- package file lists, exact optional dependencies, payload-first publication order, and no install
  or postinstall scripts;
- no credential/configuration canary, gitleaks finding, oversize binary, dirty generated file, or
  dirty source tree;
- the exact GitHub attestation subject inventory is four archives plus `SHA256SUMS`;
- the cask points to the exact tag, final archive hashes, completions, and binary without hooks or
  `xattr`; and
- real Claude Code `2.1.202` and Codex `0.142.5` are installed in an isolated prefix and the
  tool-specific release compatibility suites run with `SKILLSMITH_E2E=1` and zero skips.

The ordinary serial runner intentionally continues to report its frozen 28 live skips; the live
release lane is separate and explicitly rejects a skip. Kilo Code and OpenCode remain read-only
capability fixtures in EWP-WF01 and do not become release-installed third-party dependencies.

### 4. GitHub publication

The `github-release` environment job downloads but never rebuilds the candidate. It receives only
`contents: write`, `id-token: write`, and `attestations: write`. For the four archives and
`SHA256SUMS`, it:

1. compares every existing draft asset's digest/size to the candidate;
2. skips an exact existing asset, uploads a missing asset, and fails on any occupied mismatching
   name—never `--clobber`;
3. generates GitHub artifact attestations with exact `actions/attest@v4` subjects;
4. verifies the complete draft asset/attestation inventory; and
5. publishes the draft only after every subject is present.

Repository immutable releases must be enabled before the first publication. Once public, no job
may replace or delete an asset or move/reuse its tag.

### 5. npm publication

The `npm` environment job uses a GitHub-hosted runner, Node 24, exact npm 12.0.1, and only
`id-token: write` plus read access to the transferred candidate. No npm token is stored. All five
packages must preconfigure the one trusted publisher as organization `smorinlabs`, repository
`skillsmith`, workflow filename `release.yml`, environment `npm`, allowed action `npm publish`.

For each exact package/version, the job computes the candidate tarball's SHA-1 and SHA-512
integrity. A missing version publishes; an existing version skips only when registry shasum,
integrity, and public metadata match; an occupied mismatch fails. The four platform payloads
publish first in deterministic order and the launcher publishes last. No retry rebuilds or
restages a tarball. Trusted publishing emits npm provenance from the public source repository.

### 6. Homebrew tap pull request

The tap job depends on successful GitHub publication so the cask's release URL is public. It mints
a short-lived App token scoped to `smorinlabs/homebrew-tap`, checks out that repository, and opens
or updates a branch/PR for exactly `Casks/skillsmith.rb`. It never pushes to `main` and never uses a
long-lived personal token.

Before the first release, a separately reviewed tap infrastructure PR must replace floating action
references with full-SHA pins and add cask syntax/install coverage on supported macOS runners. The
release PR then copies the exact candidate cask. If the exact tag branch/PR already exists, a rerun
accepts it only when bytes and base repository agree; a mismatch fails. The PR must pass tap CI and
merge before EWP-WF01 can close.

## EWP-WF01 first public installation and orientation

After all publications are public and the tap PR is merged, `EWP-WF01` runs against the exact tag
without a source checkout on the installation PATH. It covers:

- direct GitHub archive installation;
- npm global installation of `@smorinlabs/skillsmith` without Bun;
- Bun global installation of the same package without Node at runtime; and
- `brew install smorinlabs/tap/skillsmith` on supported macOS.

Each channel proves version equality, then runs `agents --capabilities`, `doctor`, root help, and
`completion zsh`. A controlled fleet matrix covers zero tools, Claude-only, Codex-only, both
full-lifecycle tools, Kilo-only, OpenCode-only, and mixed read-only/full-lifecycle detection. It
proves all 23 commands exactly once in group order, alias adjacency, capability/write distinction,
useful no-tool diagnosis, valid zsh syntax, read-only mutation exit 4, no writes outside documented
XDG/tool roots, and documented upgrade/uninstall behavior. Every channel finishes with an empty
owned prefix and no source-tree dependency.

Candidate-mode fixtures may establish TDD and prepublication behavior, but only a fresh public
receipt for the released version can mark EWP-WF01 passing or signed off.

## External readiness and authorization boundary

Repository-contained implementation can complete through hermetic green and adversarial review,
but the following external facts are mandatory before public execution:

1. a reviewed full-history secret/license/publication audit passes;
2. the user explicitly authorizes changing `smorinlabs/skillsmith` from private to public;
3. GitHub environments `release-please`, `release-candidate`, `github-release`, `npm`, and
   `homebrew` exist with appropriate protection;
4. release-please and tap GitHub Apps are installed with least-privilege repository scope;
5. the five Apple secret values are configured only on `release-candidate`;
6. immutable releases are enabled;
7. npm scope authority is confirmed and trusted publishers are configured for all five package
   names with the exact `release.yml`/`npm` identity; and
8. the tap cask-CI infrastructure PR is reviewed and merged.

Missing Apple credentials blocks every channel rather than allowing unsigned GitHub/npm output.
Missing npm or tap authority blocks the entire consolidated release rather than producing partial
availability. Changing that all-channel rule requires a new explicit product-contract amendment to
D-016, EWP-P6-TS06, EWP-WF01, G6-01, and this plan.
