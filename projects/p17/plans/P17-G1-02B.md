# P17-G1-02B implementation plan

P17-G1-02B makes `check` a CI gate by default while preserving doctor as the broader diagnostic
command. Primary IDs are `COMMAND:check`, `P0-04`, `EWP-P1-T05`,
`EWP-CMD-CHECK-TS01..05`, and `EWP-P1-TS04`. Its sole dependency, G1-02A, is signed off and
supplies the shared error/output and exit boundary.

Required-now validations are exactly the five check command tests and P1-TS04. Test-first records
separate failures for error-only registry execution; default error exit versus explicit
`--report-only`; tool/scope/config and artifact-pair selection; JSON/CI exits; and suppression of
network/advisory noise. Conflicts (`--report-only --exit-code`, `--all-tools --tool`, and lockfile
without file) must fail before environment construction or discovery.

Minimal implementation hardens core check mode to execute only error-class checks. The CLI adds
default gating, redundant 1.x `--exit-code` compatibility, explicit report-only exit 0, known-tool
selection and the new artifact options. A narrow shared resolver resolves explicit `--file` from
effective cwd, derives its sibling lock, accepts an explicit lock only alongside a file, and
provides the same read-only pair to check and doctor. This phase proves path selection/plumbing only;
it does not parse or write future manifest/lock schemas.

Root owns command integration, option-ledger migration, catalog, and evidence. Core error-only
filtering and pure artifact-pair selection can be implemented independently after exact red tests.

Prohibited scope: doctor fix/migration behavior; manifest or lock schemas, parsing, ownership,
coordination, or writes; Phase-2 desired-state semantics; G1-03 application runtime; and any future
command. Report-only changes exit selection only and must never change the executed checks or report
payload.
