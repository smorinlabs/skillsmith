# P17-G5-04 Ready plan

## State, amendment, and boundary

P17-G5-04 adds the flat public `skillsmith gc` maintenance command. It reclaims only exact
machine-local immutable store leaves that are unreachable after ledger, live-placement, pending
journal, history/undo, project-registration, and age protections. It also permits an operator to
forget an exact retired project registration without opening or editing that project's portable
manifest or lock.

The 2026-07-23 EWP-CF-044 amendment and its adversarial review close the implementation-blocking
ambiguities before product work begins:

- one fixed local store root is the bounded candidate inventory and ledger, registered-live,
  journal, history, and age state form the complete protection graph;
- omitted age means no additional floor, while explicit duration has a closed grammar and strict
  boundary;
- exact bytes means deterministic logical payload bytes, not platform-dependent allocated blocks;
- GC has command-local maintenance actions without widening portable `skillsmith.plan`;
- one private owner-only recovery-v1 record durably binds approval, request, ledger revisions,
  actions, containers, and payloads before forget or reclaim, so a matching retry resumes the same
  plan while a different request or unbound state refuses; and
- forget commits before an eligible leaf is atomically detached to its record-bound action-container
  payload, so crash/retry can leak space but cannot delete a still-protected object.

The amended catalog has exactly 426 entities: 419 required and 7 deferred. G5-04 owns exactly 16
primary entities: `COMMAND:gc`, D-012, EWP-CF-016, EWP-CF-044, GC TS01 through TS08, EWP-P5-T06,
EWP-P5-TS04, EWP-WF12, and P2-03. Required-now and impacted validation are the same exact 10
selectors: GC TS01 through TS08, P5-TS04, and WF12. Downstream coverage is empty. Signed findings
EWP-CF-028, EWP-CF-031, EWP-CF-035, EWP-CF-037, and EWP-CF-043 remain compatibility authorities,
not additional G5-04 primary entities.

Direct dependency P17-G4B-03 is signed off at all ten lifecycle gates. Phase 5 is active. No G5-04
target, product behavior, test receipt, or lifecycle gate is claimed by this candidate plan.

## Existing authority and exact reuse

G5-04 extends these signed owners and must not fork them:

- `readLedgerState`, `withLedgerLock`, the canonical ledger persistence writer, and the signed
  v1-to-v2 migration binding own absent/corrupt/newer handling, exclusion, durable writes, and visible
  migration. Dry-run against v1 stays byte-identical; first approved mutation migrates under the
  existing lock.
- Ledger v2 `projects` owns local project pair state and `projectRegistrations` is its exact derived
  mirror. A new pure `withoutLedgerProjectAt` transform removes one whole exact project subtree and
  re-derives registrations; it preserves user state, other projects, transactions, and history.
- Logical transactions, preserved legacy pair journals, bounded history, rollback lineage, retained
  store resources, and retention timestamps remain the only recovery/undo retention authority.
  GC projects their references; it does not finalize history, clean backups, abort, resume, or undo.
- Store leaves retain the existing layout `<store>/<namespace>/<repo>@<revision>/<skill>`. Existing
  lifecycle recovery retains ownership of the store's exact `.staging` child; `.fetch` is a
  data-directory sibling and is outside the store crawl. `contentHashOf` remains the content
  identity authority; GC adds a focused immutable inventory/measurement repository rather than
  teaching lifecycle writers to enumerate arbitrary trees.
- Registered placement paths provide the bounded live probe set. A current ledger store path and an
  observed store-linked live symlink target are independent protection edges, so drift cannot make
  either target reclaimable. GC never enumerates arbitrary adapter/project/home roots.
- The shared application outcome, interaction, preflight, error, observation-event, wire-codec, and
  renderer boundaries remain authoritative. There is no command-specific Commander orchestration.

The new `<data-dir>/.gc-recovery/v1` state is a private strict persistence codec owned only by GC.
It is neither the public `gc@1` report nor a portable plan, ledger, or lifecycle journal. No ledger
v3, journal v2, second writer, second lock hierarchy, portable artifact crawler, generic repair
command, or adaptation implementation is permitted.

The focused RuntimePorts boundary gains effective-user identity, optional UID/GID metadata, and
exclusive directory/text-file creation with caller-supplied initial modes. The default adapter uses
non-recursive exclusive mkdir and non-overwriting exclusive file creation; GC requests 0700/0600
and verifies ownership/mode/identity before use. The ScanEnv compatibility facade accepts that same
focused port as an explicit supplement; omission returns unavailable/null rather than weakening
exclusivity. The shared runtime fixture supplies it, and GC domain modules import no ambient process
or Node filesystem APIs.

## Public grammar and validation order

The exact command is:

```text
skillsmith gc [--dry-run] [--older-than <duration>]
             [--forget-project <path>]... [-y|--yes] [--json]
```

Inherited `--no-prompt` is accepted. There are no positional targets, aliases, tool/scope/all,
artifact, force, strictness, verification, delete/prune, batch, or continuation options. Omitted
targets are valid and report `selectionSource: bounded-default` because one configured local store
root bounds the candidate inventory.

Commander/spec preflight runs before application-context creation or I/O:

- `--yes` conflicts with `--dry-run`;
- `--older-than` is singular;
- unsupported flags and positional arguments are usage errors;
- duration is exactly `[1-9][0-9]*(s|m|h|d|w)` and its millisecond product must be a safe integer;
  signs, zero, fractions, whitespace, omitted/unknown units, and overflow are usage exit 2;
- repeated forget paths are permitted and normalized/deduplicated later because repeatability is
  contractual, not a conflict.

Dry-run never prompts or writes. An execution whose combined plan has no migration, forget, or
reclaim action is an explained exit-0 no-op and needs no approval. Any action requires one exact
approval. `--yes` supplies it. JSON, no-prompt, or non-TTY execution with actions and without yes is
usage exit 2 before writes. Interactive refusal is usage 2 and cancellation is 130. State,
execution, permission, and success exits remain 3, 1, 6, and 0 respectively; GC has no capability,
source, or drift exit class.

## Exact project-forget semantics

Every forget input is resolved lexically from effective cwd to an absolute normalized path before
ledger access. A deliberately missing root is never passed through `realpath`. Normalized repeats
collapse to one row in first-request order. The whole forget request refuses without mutation when
any row:

- does not exactly equal an existing v2 project key after supported v1 normalization;
- equals the current canonical ProjectContext root;
- has any filesystem state other than absent, including a directory, file, special node, or
  symlink/dangling symlink;
- contains a preserved legacy pair journal; or
- is the project identity of any pending logical transaction.

An alias, ancestor, descendant, case variant, or merely similar path never widens to a ledger key.
The pure hypothetical model removes each accepted `projects[root]` subtree, re-derives
`projectRegistrations`, and preserves transactions/history. Historical resources continue to
protect store leaves after forget when their own retention policy applies. Dry-run reports the
exact before consumers and hypothetical absence. Execution commits that same local ledger change
before any reclaim action. It never probes or writes `skillsmith.toml`, `skillsmith.lock`, or a saved
plan under the forgotten path.

## Candidate inventory and exact measurement

The private inventory repository enumerates only strict leaf directories at the signed store
layout depth. An absent configured root is an empty inventory. A present root and every traversed
ancestor must be a stable lstat-observed real directory with no symlink component and canonical
containment. The only recognized relative object path has exactly three filesystem components:
`<namespace>/<repository-name>@<revision>/<skill>`. Namespace is a nonempty publisher-sanitized
`[A-Za-z0-9._-]+` component other than `.` or `..`. The middle component is parsed at its final
recognized `@revision` suffix, where revision is exactly 12 lowercase hexadecimal characters,
`dirty-` plus 12 lowercase hex, or `content-` plus 12 lowercase hex. The repository-name prefix is
the exact current-publisher basename and may contain spaces, Unicode, or additional `@`; the whole
middle component must round-trip as one nonempty platform path component with no NUL or separator.
This preserves local/no-remote snapshots such as `my repo@content-<hash12>` and
`acme@tools@<sha12>`. Skill satisfies the canonical manifest-name grammar. The exact `.staging` child
is ignored as lifecycle recovery state and the exact `.gc-tombstones` child is reserved for GC
recovery. `.fetch` is a data-directory sibling and is never below or crawled from the store root.
Any other depth/component, root or parent kind, symlinked ancestor/object root, special node, or
escape refuses the whole invocation as state exit 3 before approval or writes. Empty parents are
not objects; safe empty `repository@revision` and namespace parents may be pruned only after a leaf
detach with stable identity/containment revalidation and parent flushes.

Each candidate observation is deeply immutable and contains:

- stable object ID derived from canonical kind/path/content identity;
- kind `store` (and a closed future `adapted-overlay` branch);
- canonical leaf path, parent/root identities, directory identity and link-count guard;
- canonical content hash, root modification time, and deterministic logical bytes;
- sorted file/symlink entry identities needed to detect a race;
- observed classification/protection/eligibility facts and reasons.

Logical bytes are the sum of regular-file byte lengths and UTF-8 byte lengths of literal internal
symlink targets. Directories add zero. Symlinks are never followed. Internal symlink targets must
pass the existing source-content safety rules. Any regular file or symlink whose lstat link count
is not one is unsafe; directory link counts need only remain stable. Unsupported/special entries,
escape, unstable kind/identity/link count/bytes, unsafe hard links, read failure, or safe-integer
overflow refuses the whole invocation as state exit 3 before approval or writes rather than
estimating or reclaiming safe-looking siblings. Human and JSON list each offending path/reason but
expose no executable action or eligible total. The CLI never recomputes counts.

The age cutoff is calculated once from the injected epoch clock. With no flag, `olderThan` and
`cutoff` are null and age adds no exclusion. With a flag, an otherwise-unprotected object is age
eligible only when `modifiedAt < cutoff`; equality and one millisecond newer are protected, one
millisecond older is eligible. Execution revalidates the exact timestamp and cutoff from the
approved observation rather than taking a second clock sample.

Adaptation is deferred. The plan closes `GcObjectKind` over `store | adapted-overlay` and accepts an
overlay only from an injected adapter-owned disposable-object inventory with the same containment,
identity, bytes, and revalidation facts. Production registers no overlay producer in this group.
TS05 exercises the pure injected branch; arbitrary local directories never become overlays.

## Reachability and retention graph

Pure `reachability.ts` projects protection edges keyed by exact canonical path plus content hash.
Hash-only or basename-only matching is forbidden. The graph uses the hypothetical post-forget
ledger for current project consumers and the unchanged transactions/history for retained state.
It protects:

- every user and surviving-project pinned `storePath` plus content hash;
- every derived registration consumer, including missing and other projects;
- both the ledger target and any different store-contained target observed from its registered live
  placement path;
- every store resource retained by a pending logical transaction;
- every store/staging/backup reference owned by a pending legacy journal where it can identify the
  candidate path;
- every retained store resource in committed history while its undo resource is still eligible;
  null `retainUntil` remains protected while the history row is undo-relevant, and an explicit
  timestamp remains protected while `now <= retainUntil` and expires only when `now > retainUntil`;
- transaction/history dependency and parent/child lineage units required by the signed bounded
  history/undo projection; and
- an adapter-registered live or retained adapted overlay.

GC does not delete backup files, journal paths, staging/fetch state, live placements, or portable
artifacts. Corrupt/newer ledger, inconsistent registration derivation, malformed journal/history,
invalid timestamps, out-of-root retained paths, or unverifiable edges fail closed. Missing project
roots are reported and their consumers remain protected unless the exact root is in the accepted
hypothetical forget set.

The report retains one sorted classification row for every valid candidate, including protected and
age-filtered rows. `filter-zero` means every observed candidate was valid but none eligible; it is a
successful explained no-op. An unsafe or unmeasurable observation instead refuses the entire
invocation, lists every known offending path/reason, exposes no actions or eligible totals, and
performs no writes.

## Immutable GC plan and approval product

Private modules form one immutable boundary:

- `inventory.ts` observes strict local objects and logical bytes;
- `observe.ts` reads ledger/project/live/clock/inventory facts and creates a deep-frozen snapshot;
- `reachability.ts` computes exact protection edges with no I/O;
- `plan.ts` validates forget and duration requests, projects the hypothetical ledger, and returns a
  deterministic plan/report skeleton;
- `recovery.ts` strictly encodes, discovers, validates, replaces, and completes the private
  owner-only recovery-v1 record;
- `repository.ts` owns exact metadata-bound tombstone detach/cleanup operations;
- `execute.ts` revalidates and executes only the approved plan under the ledger lock;
- `types.ts` closes requests, facts, actions, results, diagnostics, and errors;
- `index.ts` is the private domain entrypoint.

The command-local action union is exactly:

1. `migrate-ledger` — the existing shared v1-to-v2 operation projected into the GC report;
2. `forget-project` — exact registration present -> absent, mutating only the local ledger;
3. `reclaim-store` — exact immutable object present -> absent at its live path via tombstone detach.

Actions are ordered by kind, then normalized project path or canonical object path. Each public
action carries a stable action ID, exact dependency IDs, logical bytes, mutation target, outcome,
and reason; the report carries the shared bounded-default selection source. The private immutable
plan/recovery binding carries the before object/ledger image, expected after state, and exact
preconditions needed to authorize execution. `reclaim-store` actions made eligible by forget depend
on all forget actions; every non-migration action depends on migration when present. Input
permutation cannot change IDs/order. The GC actions are not `PlanOperationV1`, are not encoded in
`skillsmith.plan`, and are rejected if manufactured in saved apply. The shared observer event
taxonomy adds the two command-local operation kinds so action lifecycle remains correlated and
redacted without changing the portable operation vocabulary.

One combined immutable product—forget rows, candidate rows, actions, item/byte totals, checks, and
diagnostics—is shown for dry-run and approval. The application service never prompts and replans;
approved execution receives the same plan identity and action IDs. Preparation and dry-run first
perform strict read-only recovery-v1 observation without creating a directory, acquiring the ledger
lock, creating/removing a lock path, changing a live record, or cleaning a temp. An absent recovery
path is empty; exactly one valid live/temp state is reported with pending remediation; multiple
valid records, malformed live state, impossible temp/revision transitions, or unsupported state
refuses as exit 3 with no writes. A non-authoritative incomplete initial temp is reported but not
removed in dry-run. Summary counts distinguish
observed, protected, age-filtered, eligible, forgotten, reclaimed, already-absent tombstones,
refused, and failed items, with exact eligible/reclaimed bytes.

## Durable execution and crash convergence

Only approved execution owns one ledger-lock critical section. It repeats strict recovery discovery
and requires the read-only approved observation still exact before any GC state mutation:

1. validate that the configured data directory is a stable effective-user-owned real directory that
   is not group/world writable; create/validate `.gc-recovery/v1` one component at a time as stable
   contained mode-0700 effective-user-owned real directories with no symlink component, then
   strictly discover its closed live/temp namespace;
2. with no authoritative record, re-read strict ledger state and validate the approved byte/semantic
   revision and migration state; with exactly one valid pending record, require the same semantic
   request digest and resume its already-approved immutable plan without replanning or prompting;
3. for both new execution and retry, phase-aware revalidate every boundary not durably proven. Every
   uncommitted forget must still match its exact recorded ledger byte/semantic revision, key, and
   subtree and be absent
   including dangling symlink, non-current, and free of pending logical/legacy journal state. An
   exact expected post-forget semantic digest is adopted idempotently after a crash-before-phase-update;
   any other drift refuses with the record retained. Revalidate every candidate identity/hash/mtime/
   byte fact before mutation;
4. before migration, forget, or reclaim, validate that every deterministic action-container and
   payload path is absent, then durably publish
   `<data-dir>/.gc-recovery/v1/<plan-id>.json` with strict `skillsmith.gc-recovery` schema 1. Plan and
   action IDs, ownership tokens, and record revisions are 64 lowercase hex; generated CAS IDs are
   unique 16 lowercase hex. The record binds request/plan digest, sanitized retry argv, approval,
   source byte/semantic and expected post-forget semantic ledger revisions, normalized roots,
   action identity/path/hash/mtime/bytes,
   container/payload paths and identity, and phase;
5. execute the existing durable ledger migration when planned, re-bind the equivalent v2 model,
   and CAS-replace/flush recovery state after that durable boundary;
6. durably write the exact post-forget ledger through the canonical writer, flush it, then
   CAS-replace/flush recovery state;
7. recompute protection from that committed model and conservatively protected-skip before deletion
   if an approved reclaim is no longer eligible; never add a reclaim action;
8. after the live record exists, exclusively create its mode-0700 plan directory; retry may adopt
   only the exact empty record-named directory after owner/mode/identity validation. For each
   approved leaf, exclusively create its mode-0700 owner-bound action container at
   `<store>/.gc-tombstones/v1/<plan-id>/<action-id>`, publish/fsync its sole mode-0600 `owner.json`
   marker containing kind/schema, plan/action IDs, and the pre-recorded ownership token, flush and
   CAS-record the stable container identity, then revalidate source, container, and absent `payload`;
9. atomically rename the source on the same filesystem into the private absent
   `<store>/.gc-tombstones/v1/<plan-id>/<action-id>/payload` slot, assert original absence and exact
   payload identity, fsync both parents, CAS-record detach, remove only that bound payload, assert
   absence, fsync, CAS-record cleanup, and remove/flush the marker and empty action container;
10. prune only now-empty strict `repository@revision` and namespace parents after
   identity/containment checks and parent flushes; parent pruning never changes action eligibility
   or byte totals; and
11. after every action converges, CAS-remove the recovery record and flush its parent.

The recovery record, not a tombstone name or changed ledger alone, is deletion and retry authority.
Its request digest excludes output/interaction spelling but includes every semantic selector. A
pending record blocks a different request with state exit 3 and prints exact sanitized retry
remediation. Recovery live/temp files use the exact protocol below. A pre-existing container/payload,
collision, planted tombstone without the one matching valid record, malformed live record, or
unsupported version refuses the whole invocation. A crash-created container may be adopted only by
its record token/identity; before identity is recorded, only an empty or owner-marker-only container
may be removed/recreated. A payload may be adopted only when source is absent and every recorded
identity/hash/mtime/byte fact matches. An already-detached record-bound payload resumes the same
`reclaim-store` action and is never double-counted. A new source object has a different identity and
remains untouched.

Recovery live name is `<plan-id>.json`; initial temp is
`.<plan-id>.create-<new-revision>-<cas-id>.tmp`; replacement temp is
`.<plan-id>.cas-<expected-revision>-<new-revision>-<cas-id>.tmp`. A temp is exclusively created
mode 0600, canonically written/fsynced/read back, and the directory is flushed before guarded
same-directory rename. Initial publish rechecks live absence; replacement rechecks the exact live
revision and permits only the next monotonic phase. Discovery finishes one valid initial/successor
temp, removes a temp when live already has its new revision, and identity-checks/removes incomplete
non-authoritative staging. Multiple valid temps, an impossible revision/phase pair, unexpected entry,
symlink/hard link, or malformed live record refuses. Record transitions are only approved,
planned migration/forget completion, action-container prepared, detached, cleaned or conservatively
protected-skipped, and complete in deterministic action order; at most one nonterminal reclaim may
follow a terminal prefix, and all later actions remain pending. Already-absent is terminal only with
no container identity or state. A cleaned action may resume an exact identity-bound owner-only or
empty container after interruption between owner removal and atomic empty-directory removal. Absent
planned kinds are the only skips. Crash after a physical mutation but before record advance is
recovered by exact state revalidation and the next CAS record.

Crash before the durable recovery record leaves the original protective ledger and no GC mutation;
an incomplete initial temp is non-authoritative staging and is removed on discovery. Crash after the
record but before an uncommitted forget requires all forget preconditions again. Crash after the
exact forget but before rename leaves extra unreachable bytes plus the same plan authority. Rename
is atomic: a crash
leaves either the complete source or its record-bound detached payload. Crash during recursive
payload cleanup cannot expose partial content at the original path and matching retry finishes
cleanup. Direct recursive deletion of the live leaf and delete-before-record/forget are prohibited.
Cancellation follows the same durable boundary: before a boundary it leaves the old state; after it
leaves the recovery record describing the retryable migration, committed forget, or detached
payload. This adds only the private GC recovery-v1 codec; ledger v2, journal v1, and portable saved
plans remain unchanged.

## Application, wire, output, and exits

`gc-service.ts` normalizes the parser request, constructs the focused runtime/project context,
prepares once, requests one exact approval when needed, executes the frozen plan, and maps the
result through the shared application outcome. It receives focused ports through the existing
context and does not expose raw ledger/journal/capability objects in the report.

`gc@1` is a strict named codec with:

- identity `schemaVersion: 1`, `kind: skillsmith.gc`, `command: gc`;
- mode, state, plan ID, bounded-default selection source/outcome, project context, migration facts,
  normalized duration milliseconds/cutoff, approval facts, and sanitized recovery status/phase;
- ordered project rows with exact root/current/existing/missing/requested/action/outcome/reason;
- ordered object rows with stable ID, kind, path, hash, modifiedAt, logical bytes, protection edges,
  age/eligibility, action/result/outcome, and reason;
- ordered actions/results/checks, sanitized diagnostics, and exact item/byte summary;
- no raw ledger/journal, portable artifact bytes, arbitrary discovered path, URL/credential,
  stack/cause, internal capability object, or mutable reference.

Human and JSON map the same DTO. JSON is one strict codec-validated value plus terminal LF.
Diagnostics/deprecations remain on stderr through the shared runtime. Renderer startup closure lands
CommandSpec, service, wire mapping/codec, renderer, and current-state inventory together.
