# P17-G4B-01 Ready-plan candidate

## Outcome and corrected scope

preview. It selects one manifest/lock pair, observes immutable artifact, live, ledger, store, and
capability state, resolves missing or stale source pins when policy permits, computes one canonical
operation/check/diagnostic set, and renders human and strict JSON views from the same report. With
`--check`, an empty valid plan exits 0 and a nonempty valid plan exits 7. With `--out`, the same
approved operation set is encoded through the existing strict saved-plan v1 codec and written with
owner-only permissions. Planning never mutates the manifest, lock, ledger, live roots, store, or
configuration.

## Command and preflight contract

The activated grammar is:

```text
skillsmith plan
  [--file <path>] [--lockfile <path>]
  [-t, --tool <name>]...
  [-s, --scope <user|project> | --user | --project]
  [--locked] [--prune] [--check]
  [--out <path>] [-f, --force] [--json]
```

There are no positionals, command aliases, approval flags, batch controls, `--dry-run`, plan-file
input, or mutation modes. `-f` is the accepted short spelling of `--force`. Exact preflight rules
complete before project discovery, config reads, source resolution, output observation, or any
filesystem write:

- `--file`, `--lockfile`, `--scope`, and `--out` are singular; repeated occurrences exit 2;
- any two scope forms conflict even when they spell the same scope;
- `--lockfile` requires `--file`; the custom lock path is invocation-only and exactly reported;
- `--check` conflicts with `--out` and `--force`;
- `--force` requires `--out`, and authorizes replacement of that exact output path only;
- `--out -` is unsupported and exits 2; saved artifact bytes are never written to stdout;
- unknown tool/scope and positional input exit 2; and
- inherited `-C`, `--config`, JSON, quiet/verbosity, color, no-prompt, and cancellation behavior
  continue through the shared runtime without local process control.

Usage/refusal errors take precedence over discovery or drift. Exit 0 means a valid empty plan (or
ordinary valid preview without `--check`), 1 an execution/integrity failure while producing output,
2 usage/refusal, 3 invalid artifact state or locked stale/missing correlation, 4 unsupported
capability, 5 source/network failure, 6 permission failure, 7 valid nonempty check drift, and 130
cancellation. An actual 1..6 error always outranks drift 7. A partial report may name already
classified operations and refusals, but it never converts an error into drift.

## Artifact context and immutable observation

Plan selects exactly one artifact context through the signed project/artifact authorities:

1. explicit `--file` selects that manifest from `effectiveCwd`; an optional explicit lock is used
   exactly and is never persisted as a new default;
2. otherwise the bounded project/user discovery rules select one readable artifact pair and refuse
   ambiguity;
3. the artifact path never changes the independently resolved project identity or project live
   root; and
4. the selected pair, selection provenance, project identity, and custom/default lock relationship
   are explicit report facts.

Planning obtains one deeply immutable observed-state snapshot. Repositories expose exact revisions
and canonical domain hashes; planner code cannot read the filesystem, clock, environment, network,
or adapters directly. Source resolution happens before pure planning and contributes immutable
resolved resource facts. Repeating a plan against unchanged inputs produces the same operation IDs,
order, report bytes, and saved artifact bytes.

The selected manifest is the complete default authority boundary. Without tool/scope filters, plan
examines all declared entries and declared scopes in that one manifest. Filters only narrow it;
filter-to-zero is an explicit empty selection and never widens to all. Explicit custom artifact
selection never turns a config-only legacy file into a silently writable manifest. A project config
that is also a safely migratable legacy artifact may produce the visible
`migrate-project-config` preview; malformed, mixed, future, unsafe, or ambiguous dual-role content
refuses under the signed artifact rules.

## Lock and source policy

A current canonical lock whose root semantic hash and each selected declaration correlate supplies
the exact source pins. Noncanonical, malformed, future, unknown hash-version/domain, semantically
incoherent, or resource-incoherent lock state refuses.

Default plan may resolve a missing, incomplete, or stale selected pin from the manifest's portable
source/ref through the existing hermetic resolver. Resolution is observation only: it may use a
temporary materialization to compute the immutable SHA/content facts, but it never writes the
selected lock or store. The resulting plan visibly contains the required `write-lock` transition
and resource preconditions. `--locked` forbids that resolution and returns state 3 for every
missing, incomplete, or stale selected pin. Unselected lock entries do not authorize mutations and
unrelated state does not invalidate a bounded selection unless a whole-artifact write would touch
it.

## Desired/current reconciliation

The pure reconciler consumes only:

- selected canonical manifest intent and correlated or newly resolved pins;
- explicit tool/scope/filter/prune selection metadata;
- adapter-provided capabilities, roots, placement policy, verification facts, and legacy notices;
- immutable live/store/ledger observations and revisions; and
- visible project-config or ledger migration observations.

It returns one canonical `OperationPlan<'plan'>` plus a stable report projection. Generic planning
contains no known-tool branches. Claude Code and Codex provide the current full-lifecycle matrix;
Kilo Code and OpenCode produce explicit capability refusals for unsupported mutation work rather
than being silently omitted. A mixed supported/unsupported selection retains stable partial facts
and exits 4 without writes.

The operation matrix covers empty, install/create, update, remove, relink/move-scope, adapt,
repair, `migrate-project-config`, `migrate-ledger`, manifest/lock writes, and noop. Operations retain
the signed operation vocabulary, domain IDs, dependencies, conflicts, exact before/after images,
preconditions, and canonical topological order. G4B-01 adds no new executable operation kind.

Adaptation policy is not invented here. The registered adapter surface currently exposes
capability/version facts but no transformation engine. Production planning therefore renders an
explicit capability/refusal diagnostic when a required adaptation cannot be produced. TS01 also
proves that the renderer and report codec faithfully accept a canonical injected `adapt` operation
fixture; it does not implement the future adaptation engine early.

Visible project-config and ledger migration operations are previews only. A v1 ledger is normalized
in memory and, when convergence would later mutate governed state, yields one ordered
`migrate-ledger` prerequisite without writing. No migration operation is duplicated or allowed to
change current bytes during plan. Existing ordering/shape rules are amended only if a failing test
proves the exact prerequisite edge is not already representable; that change requires a reviewed
ownership amendment before edit.

## Prune authority

Prune is a separate deletion authority, never a synonym for convergence:

- without `--prune`, undeclared live placements are visible diagnostics only and no removal is
  planned;
- with `--prune`, removal is bounded to registered tool/scope pairs inside the selected manifest's
  declared authority and the current explicit filters, and requires exact
  selected-lock/live/ledger provenance correlation;
- unmanaged paths, unknown adapters, another project identity, placements whose selected-artifact
  authority is unproven (including wrong source, ref, content, or placement path), unselected
  tools/scopes, arbitrary custom roots, and store-only resources are never prune candidates;
- an empty manifest, filter-to-zero, unsupported adapter, ambiguous owner, or incomplete observation
  never widens deletion authority;
- user and project scope are independent even for equal skill names; and
- every removal carries exact live/ledger/resource preconditions and the normal coordinator
  operation shape for later G4B-02 execution.

P4B-TS04 is the destructive-safety owner and must positively prove preservation of every excluded
class, not merely count selected removals.

## Report, rendering, and saved output

`PlanReportV1` is a strict versioned wire projection with these closed top-level facts:

- schema version and command;
- selected artifact pair, project identity, and selection provenance;
- effective locked/prune/check/filter options;
- canonical operations, checks, and diagnostics;
- summary counts by operation/check/diagnostic outcome and total drift;
- nullable saved-output result with exact path, create/replace disposition, permissions, and
  portable/machine-bound classification; and
- stable success/refusal state needed by both renderers.

The JSON renderer encodes exactly one strict report value on stdout. Human output preserves the same
selection, ordering, before/after meaning, conflicts/refusals, summary, saved-output result, and
drift conclusion. Renderer tests compare semantic projections; neither renderer replans, reads
state, branches on tool IDs, or redacts independently.

`--out` builds `SavedPlanV1` through the existing strict canonical codec. It records the exact
operations/options, scoped manifest/lock/resource/selection/capability preconditions, hash schema
versions/domains, and recursive portability classification required by the future executor. The
builder maps default user/project/store locations to the signed portable tokens. Absolute explicit
artifact paths, arbitrary custom paths, and other local bindings are machine-bound with stable
reason codes and exact preconditions. Portable output contains no local absolute path. Source URLs
are credential-free canonical identities; credentials, environment values, raw errors, temporary
paths, recovery paths, store internals, and secret canaries are absent recursively.

The output writer uses a new focused module over the existing safe filesystem ports. Default is
create-only and refuses an existing path. `--force` atomically replaces only the exact output after
staging owner-only mode; failures preserve the prior file and clean bounded temporary state. The
writer does not join the manifest/lock transaction, acquire a project mutation lock, or alter any
selected state. Saved-plan execution, staleness decisions, approval, and executor compatibility
enforcement remain G4B-02 work even though G4B-01 records the required facts.
