# P17-G2-04 implementation plan

## Outcome and exact scope

P17-G2-04 defines the pure Phase-2 input beneath the future `init` command: strict validation of an
already-resolved skeleton request and current manifest bytes, deterministic canonical empty-manifest
construction, one lossless exact-legacy conversion, and one immutable create/replace/migrate/noop
operation input or fixed refusal. It performs no destination discovery, registration, rendering,
planning, locking, writing, or execution.

The primary entities are exactly:

- `EWP-P2-T05`;
- `EWP-P2-TS05`.

The remapped required-now and impacted validation set is exactly `EWP-CMD-CONFIG-TS01`,
`EWP-CMD-CONFIG-TS04`, `EWP-P1-TS08`, `EWP-P2-TS01`, `EWP-P2-TS04`, and `EWP-P2-TS05`;
downstream coverage is empty. TS05 is the new authority. The other five signed selectors are real
compatibility impacts of centralizing migration and extending the human-range model, not optional
local checks. Signed `EWP-CF-001` is a dependency-order trace. Planned `EWP-CF-041` remains
primarily owned by G4A-03; this group supplies only its Phase-2 request/skeleton/migration
prerequisite and does not claim the future command, option, workflow, renderer, or execution gates.

Dependencies are signed:

- G2-01 sign-off `944c41118cf0cc4710fb671a658d3fac443d7754`, accepted implementation
  `0751951bbb413dd80f5dc6e67eec8725d18c9735`;
- G2-03 sign-off `15c3c67658571b79f8b24059ea1db6b7e0518471`, accepted implementation
  `6151cdea0ece5727e5a11f36d619e278b64792bf`.

G2-02's exact-byte and semantic hash authority is transitively available. G2-04 consumes G2-01's
manifest reader/normalizer and portability rules, G2-02's manifest hash domains, and G2-03's bounded
human-TOML ranges. It must not clone any of them.

## Closed public boundary

The public runtime surface is exactly:

```ts
export const INIT_MANIFEST_OPERATION_KINDS = Object.freeze([
  'create-manifest',
  'replace-manifest',
  'migrate-project-config',
  'noop',
] as const);

export function planInitManifest(
  input: unknown,
): Result<InitManifestOperationInput, InitManifestRefusal>;
```

The public types are:

```ts
export interface InitManifestDefaultsInput {
  readonly tools?: readonly ManifestTool[];
  readonly scope?: ManifestScope;
  readonly path?: string;
}

export interface InitManifestSkeletonInput {
  readonly defaults?: InitManifestDefaultsInput;
  readonly registry?: Readonly<{ readonly default: string }>;
}

export type InitManifestIntentField =
  | 'defaults.tools'
  | 'defaults.scope'
  | 'defaults.path'
  | 'registry.default';

export interface InitManifestLegacyIntentInput {
  readonly requireMatch: readonly InitManifestIntentField[];
}

export type InitManifestCurrentInput =
  | Readonly<{ readonly state: 'absent' }>
  | Readonly<{ readonly state: 'present'; readonly bytes: Uint8Array }>;

export interface InitManifestRequest {
  readonly skeleton: InitManifestSkeletonInput;
  readonly current: InitManifestCurrentInput;
  readonly legacyIntent: InitManifestLegacyIntentInput;
  readonly force: boolean;
}

export interface InitManifestBeforeImage {
  readonly byteHash: ArtifactDigest;
  readonly semanticHash: ArtifactDigest | null;
  readonly shape: ManifestShape;
}

export interface InitManifestWriteImage {
  readonly source: string;
  readonly byteHash: ArtifactDigest;
  readonly semanticHash: ArtifactDigest;
  readonly shape: 'canonical';
}

export type InitManifestOperationInput =
  | Readonly<{
      readonly kind: 'create-manifest';
      readonly before: null;
      readonly after: InitManifestWriteImage;
    }>
  | Readonly<{
      readonly kind: 'replace-manifest' | 'migrate-project-config';
      readonly before: InitManifestBeforeImage;
      readonly after: InitManifestWriteImage;
    }>
  | Readonly<{
      readonly kind: 'noop';
      readonly before: InitManifestBeforeImage;
      readonly after: null;
    }>;

export interface InitManifestRefusal {
  readonly code: 'init-manifest';
  readonly exitCode: 2 | 3;
  readonly reason:
    | 'invalid-request'
    | 'existing-manifest'
    | 'future-manifest'
    | 'legacy-intent-conflict'
    | 'unsafe-legacy-migration';
  readonly field?: 'skeleton' | 'skeleton.defaults' | 'skeleton.defaults.tools'
    | 'skeleton.defaults.scope' | 'skeleton.defaults.path' | 'skeleton.registry.default'
    | 'current' | 'current.bytes' | 'legacyIntent' | 'legacyIntent.requireMatch' | 'force';
  readonly shape?: ManifestShape;
  readonly message: string;
}
```

`planInitManifest` accepts `unknown` so the request boundary, rather than its callers, owns runtime
validation. It accepts only ordinary own-data objects and ordinary dense arrays. Proxies are
rejected first with the platform's trap-free proxy predicate. Accessors, symbols, inherited fields,
array holes/extra keys, exotic prototypes, detached buffers, and unknown/missing fields then refuse
without invoking caller code. The exact allowed keys are the published fields above.
`legacyIntent` and boolean `force` are required. `current.bytes` must be an exact-prototype
`Uint8Array` backed by an ordinary `ArrayBuffer`; `SharedArrayBuffer`-backed views are rejected
before copying so another agent cannot race the synchronous snapshot. The view may expose only its
intrinsic dense numeric own properties: symbols, named extras, own `buffer`, `byteLength`,
`byteOffset`, or `constructor` shadows, and sparse or nonstandard index descriptors refuse.
Backing-store metadata is read through captured intrinsic typed-array getters, never caller
properties, iterators, constructors, or species. A fresh ordinary `Uint8Array` receives the bytes
through captured intrinsic operations before any decoding or hashing. Every optional property is
optional by absence only: an own `defaults`, `registry`, `tools`, `scope`, or `path` property whose
data value is `undefined` refuses as `invalid-request`; it is never silently normalized as absent.
A present ordinary empty `defaults` object is the one explicit exception and normalizes to absent
defaults.

Tools are nonempty, unique supported tool IDs and are copied into unsigned UTF-16 code-unit order.
Scope is `user` or `project`. A path is accepted only with a scope and only through G2-01's
`normalizePortablePath`. Registry identity is accepted only through G2-01's
`normalizeRegistryIdentity`; the request does not enable legacy registry spelling. Empty defaults
and absent defaults normalize to the same skeleton. `legacyIntent` is an ordinary exact-key object
with one required ordinary dense `requireMatch` array. Its members are unique intent fields in the
fixed order shown by `InitManifestIntentField`; every named field must also be present in the
normalized skeleton. An empty array preserves every existing legacy field. No default is inferred
here: the future application service resolves CLI/config/detection precedence and supplies this
pure request. It includes only fields whose values were explicitly selected by the user in
`requireMatch`; config/detected fallback values may remain in the skeleton without being compared.
Migration compares each named field independently and refuses if any named value differs or is
absent in the legacy semantics. Thus an explicit scope can be honored while unrelated detected tool
or registry defaults remain preserved; no supplied per-field intent is silently discarded.

The five fixed refusal messages are:

| Reason | Exit | Message |
|---|---:|---|
| `invalid-request` | 2 | `init manifest request is invalid` |
| `existing-manifest` | 3 | `init manifest already exists and requires force` |
| `future-manifest` | 3 | `init manifest uses a newer unsupported schema` |
| `legacy-intent-conflict` | 3 | `legacy project configuration conflicts with requested init defaults` |
| `unsafe-legacy-migration` | 3 | `legacy project configuration cannot be migrated safely` |

No message, field, shape, hash, or operation stores/interpolates a caller object, rejected source
value, rejected path, error, or credential-bearing/sensitive URL. Successful before images retain
only fixed shape and exact/semantic hashes, never raw current bytes. A successful migration after
image may contain preserved ordinary comments only after the shared sensitive-material guard
accepts the complete candidate;
it is structured operation data, not directly renderable or persistable outside the later shared
redaction/repository boundary. The result error is CF-041's refusal result; refusal is not an
executable operation kind.

## Canonical skeleton bytes

The skeleton is one canonical, declaration-empty v1 manifest. It never imports live skills,
placements, ledger entries, source identities, lock resolutions, or transaction state. Its exact
UTF-8/LF spelling is built in schema order:

1. `version = 1`;
2. optional `[defaults]` with present fields in exact `tools`, `scope`, `path` order;
3. optional `[registry]` with `default`;
4. no `skills = []` and no `[[skills]]` block;
5. one blank line between present sections and exactly one final LF.

With no defaults or registry the exact bytes are:

```toml
version = 1
```

The line shown includes the final LF. A representative complete skeleton is exactly:

```toml
version = 1

[defaults]
tools = ["claude-code", "codex"]
scope = "project"
path = "./skills"

[registry]
default = "github.com/acme"
```

Every string uses the signed G2-03 basic-string renderer; the supported-tool array uses its
canonical comma-space spelling. Construction immediately runs `readManifestSource` and
`normalizeManifestDocument`; any disagreement is an internal defect, never a fallback serializer.
The normalized semantic projection must have version 1, the requested normalized defaults and
registry, and an empty frozen `skills` array. `byteHash` is G2-02 `hashManifestBytes`; semantic hash
is G2-02 `hashManifestSemantics`. Before any create or replacement write image is returned, the
complete rendered skeleton candidate is checked by the shared `containsSensitiveMaterial`
authority. A match returns the fixed `invalid-request` refusal and no source or caller value; this
includes sensitive syntax embedded in otherwise portable path or registry strings.

## Current-state classification and operation algebra

The owned current bytes are fatally decoded for reading. A BOM or invalid UTF-8 is classified as
malformed for the replacement matrix; its exact bytes are still copied and hashed. For readable
input, G2-01 remains the sole shape and semantic authority.

The decision table is ordered and total:

| Current state | Force | Result |
|---|---:|---|
| absent | either | `create-manifest` with null before and canonical skeleton after |
| exact legacy, losslessly migratable, empty `requireMatch` | either | `migrate-project-config`; every legacy field is preserved |
| exact legacy, losslessly migratable, every named `requireMatch` field equal | either | `migrate-project-config` |
| exact legacy, losslessly migratable, any named `requireMatch` field absent/different | either | `legacy-intent-conflict` refusal |
| exact legacy, semantically nonportable or range-unsafe | either | `unsafe-legacy-migration` refusal |
| canonical and semantically equal to the requested empty skeleton | either | `noop`; exact existing bytes remain untouched and only their hash is retained |
| canonical but semantically different | false | `existing-manifest` refusal |
| canonical but semantically different | true | `replace-manifest` |
| structurally canonical but semantically invalid | false | `existing-manifest` refusal |
| structurally canonical but semantically invalid | true | `replace-manifest` with canonical shape and null semantic hash before |
| mixed, empty, malformed, or unknown | false | `existing-manifest` refusal |
| mixed, empty, malformed, or unknown | true | `replace-manifest` |
| future | either | `future-manifest` refusal |

Semantic equality compares the complete G2-01 `projectManifestSemantics` projection, including the
empty declaration set. Formatting, comments, line endings, and field order do not defeat a noop;
the operation records only the exact existing byte hash and returns no after image or raw bytes.
Nothing is rewritten. A canonical manifest
with any declaration, different default, or different registry value is not a noop. Force never
downgrades a future schema and never overwrites a source that is structurally exact legacy but
cannot migrate without dropping or reinterpreting data.

Before images contain an exact byte hash, optional semantic hash, and shape but no bytes, source,
path, or filesystem metadata. A malformed/mixed/empty/unknown or structurally canonical but semantically
invalid replacement has `semanticHash: null`. Write images contain one immutable canonical source
string plus matching exact/semantic hashes. Result records/arrays are recursively frozen.
Post-return mutation cannot alter source bytes or desynchronize hashes because no mutable byte view
is exposed. Later G4A-03 combines this path-free operation input with an already selected
destination and the general planner's revision preconditions; execution rereads the source under
its expected byte hash rather than trusting raw before content. G2-04 does not invent that planner
or call the G2-03 coordinator, whose current replace action intentionally handles absent creation
rather than future force policy.

## One lossless legacy migration authority

The consolidated contract requires one visible lossless project-config migration. The current
artifact path in `manifest-edit.ts` reserializes a normalized legacy document and drops ordinary
comments, while `config/human-edit.ts` contains a separate range migration that retains them. G2-04
must remove that split.

`packages/core/src/artifacts/legacy-migration.ts` becomes the single pure byte conversion used by
`planInitManifest`, `editManifestBytes`, and the existing project config edit. It is an internal
artifact mechanic, not an additional root public API. Its internal callable surface is:

```ts
export interface LegacyManifestMigration {
  readonly source: string;
  readonly beforeSemanticHash: ArtifactDigest;
  readonly afterSemanticHash: ArtifactDigest;
}

export interface LegacyManifestMigrationError {
  readonly code: 'legacy-manifest-migration';
  readonly reason: 'invalid-input' | 'unsafe-range' | 'unsafe-content';
  readonly message: string;
}

export function migrateLegacyManifestBytes(
  bytes: Uint8Array,
): Result<LegacyManifestMigration, LegacyManifestMigrationError>;
```

The local result/error types do not import `manifest-edit.ts`, coordinator types, config errors, or
any effect model. Each consumer maps the fixed local result/error to its own public contract. The
helper synchronously owns an ordinary `ArrayBuffer`-backed input, uses G2-03 `scanHumanToml` for
ranges, and uses G2-01 `readManifestSource`/`normalizeManifestDocument` for shape and meaning. Only
exact readable legacy input is accepted. It then performs these bounded changes:

1. select one unambiguous newline form from the source (`CRLF` or `LF`; a one-line source with no
   newline uses LF); mixed insertion context refuses;
2. preserve a file-leading comment run as heading trivia even when no blank line separates it from
   the first structural item; insert `version = 1` after that heading, then one blank line and
   `[defaults]` immediately before the first legacy root assignment or any non-heading comment block
   directly attached to that assignment;
3. preserve the original root assignment order; rename only decoded `tool` to `tools` through the
   scanner's exact `keyRange`, preserve its bare/single-quoted/double-quoted key spelling class, and
   wrap its exact string token as a one-element array without changing its quote spelling or inline
   comment;
4. leave `scope` and portable `path` value ranges byte-identical under the new `[defaults]` table;
5. keep `[registry]`, its position, header/field comments, spacing, and final-newline state; replace
   only an exact legacy HTTPS registry value with G2-01's canonical identity using the existing
   value quote class;
6. when the legacy file has registry but no root defaults, insert only `version = 1` after any
   file-leading heading and before the registry header or its non-heading attached comment block;
   do not create an empty defaults table;
7. apply non-overlapping replacements in descending JavaScript source-code-unit offset order,
   strictly reread/normalize the candidate, and require exact equality with the original legacy
   semantic projection.

Every file-leading comment run remains ahead of `version`, including the signed no-blank legacy
form. A later comment block separated from the heading remains attached to its field/header.
Inline comments and all untouched ranges are byte-identical. LF, CRLF, and no-final-newline fixtures
pin the exact output. Reopened or
aliased target tables, ambiguous attachment, duplicate scanner targets, multiline target values,
mixed insertion newlines, invalid UTF-8/BOM, unsafe registry/path/scope/tool semantics, sensitive
material that the shared redaction policy cannot safely retain, or a failed semantic reread returns
the fixed local refusal and never falls back to whole-file serialization.

`human-toml.ts` adds an immutable `keyRange` computed from the exact decoded-source slice before the
assignment equals sign. Its focused tests pin bare, quoted, escaped, indented, and non-ASCII-leading
comment cases so byte offsets can never be confused with JavaScript string offsets.

`manifest-edit.ts` delegates index-zero `migrate-legacy` to this helper and then applies any
remaining canonical edits to the migrated bytes. Its returned before/after hashes and touched
targets still describe one request. `config/human-edit.ts` delegates its exact project-legacy
conversion to the same helper before its existing narrow config patch. It translates the fixed
artifact refusal to its existing public config error without copying raw content. The old local
legacy range-conversion implementation is removed. Flat user/system configuration is unchanged.

This shared extraction is a reviewed dependent-group amendment to signed G2-01/G2-03 files. It
changes no signed manifest semantics, config command grammar, coordinator behavior, permissions,
or error exit policy. Their focused and required selectors are compatibility gates before sign-off.

The public type fixture compiles the exact function, constants, four operation kinds, input unions,
before/write images, refusal reason/field/exit unions, and `Result` carrier. Compile-negative
assertions reject

The selector has independent families for:

1. fixture integrity, counts, exact literal bytes, and hard-coded digests;
2. skeleton request validation, deterministic construction, immediate canonical reader/
   normalizer round trips, and no live declarations;
3. exact lossless legacy bytes, semantic equivalence, immediate round trips, and safe refusal;

## Explicit exclusions

G2-04 does not own:

- artifact destination discovery or explicit-file/Git-root/XDG precedence;
- an `init` command spec, Commander registration, application service, help, completion, human/JSON
  rendering, exit routing, dry-run presentation, approval, or prompts;
- filesystem reads/writes, artifact locks, coordinator calls, expected-revision IO, cancellation,
  crash recovery, sibling lock creation, or repository persistence;
- a generic `Operation`, plan, planner, executor, saved-plan codec, resource precondition, operation
  ID, transaction, ledger mutation, placement mutation, or live-fleet import;
- manifest/lock/plan/ledger/journal public codec registries and repositories (G2-05);
- force behavior beyond the pure manifest classification, including command-level option conflicts
  or authorization;
- any future init command/option/workflow selector or any G3B/G4A behavior.
