# P17-G6-02B amended Ready plan: recursive, alias-aware, local completion

## State and coherent boundary

P17-G6-02B is the dependency-ready completion group after signed G6-02A. It replaces the current
single-level static completion walker/renderers with deterministic Bash, zsh, and Fish scripts plus
a bounded tab-time candidate engine. It preserves the signed 23-command parser, the public
`completion <bash|zsh|fish>` command, all aliases/options/application routing, and emit-only
behavior.

Primary ownership is exactly 11 entities:

- `COMMAND:completion`;
- `EWP-CF-014`;
- `EWP-CMD-COMPLETION-TS01` through `EWP-CMD-COMPLETION-TS06`;
- `EWP-P6-T03` and `EWP-P6-TS02`; and
- `P2-04`.

Required-now is exactly seven executable validations:

- `EWP-CMD-COMPLETION-TS01` through `EWP-CMD-COMPLETION-TS06`; and
- `EWP-P6-TS02`.

`EWP-WF01` remains downstream and planned under G6-04. G6-02B may characterize the completion
portion of that future clean-install workflow, but may not create, target, or sign the workflow
early.

## Existing implementation and exact gaps

The current CLI already has a public `completion <bash|zsh|fish>` application and six completion
source files. `walk.ts` converts a live Commander tree into a small `CompletionNode` AST; three
Skillsmith-owned renderers emit scripts; `run.ts` selects the renderer; the shared metadata renderer
returns script bytes through the normal application/output boundary.

That baseline is useful characterization but does not meet the signed target:

- root completion emits only canonical command names, not adjacent aliases;
- Bash/zsh/Fish dispatch is only one command deep, so `config get|set|list|unset` is absent;
- command suggestions omit inherited globals after a subcommand;
- enum completion reads Commander `argChoices`, which intentionally contains broad parser values
  for capability-aware refusal; completion must instead use each command's exact `allowedValues`;
- no positional/option provider completes local skill names, paths, or manifests;
- generated scripts are static and have no internal candidate callback;
- no input, filesystem-read, latency, candidate-count, or output-byte bound exists; and
- current tests prove renderer fragments, not equality with the 23-command/alias/spec graph or
  absence of network/startup-file mutation.

The mapping baseline is 24/24 existing completion tests with 73 assertions and 17/17 EWP-P1-TS07
tests with 406 assertions. This is characterization only; none of the seven G6-02B selectors exists
yet.

## Approved library boundary

Use public exports from exact `@bomb.sh/tab` 0.0.21, centered on a fresh `RootCommand` per operation.
Do not use its module singleton and do not attach its Commander adapter to the live parser. The
library owns the detached candidate engine and supplies pinned shell skeletons; it is not trusted
to define Skillsmith's process-execution boundary.

The Skillsmith adapter has two derived operations:

1. construct a tab candidate graph from normalized `CommandSpec` records; and
2. ask tab to generate one supported shell script or resolve one internal candidate request.

The package currently writes setup/parse output through synchronous `console.log`. One guarded
adapter-local capture function may bridge that package API to a returned string. It must reject
re-entrancy, accept only string/number lines, restore the original console method in `finally`, and
be the only package-I/O seam. Production runtime I/O, public command rendering, errors, and exit
codes remain owned by the existing shared adapter.

One narrow deterministic shell hardening step consumes only those captured bytes. It must:

- recognize exact, version-pinned Bash and zsh template anchors and exact occurrence counts;
- replace the Bash and zsh request dispatch with direct argv-array invocation of the fixed
  `skillsmith complete --` transport, preserving spaces, quotes, globs, metacharacters, newlines,
  and the trailing empty token as literal argument bytes;
- remove every completion-request-path `eval` and replace zsh's dynamic `_describe` call with an
  argv array assembled only from fixed allowlisted flags;
- correct Bash attached-value handling so a candidate for `--scope=pr` is filtered against `pr`
  and returned as `--scope=project`, while the separated `--scope pr` form remains `project`;
- retain Fish's already direct argv dispatch and validate its exact fixed-command shape; and
- fail closed with no public script if any expected anchor is absent, duplicated, reordered, or
  otherwise changed by a dependency upgrade.

The final Bash, zsh, and Fish scripts must contain no runtime `eval`, no joined command string, and
no path by which a completion token becomes shell source. This adapter is the only Skillsmith-owned
shell correction: it duplicates neither the command registry nor the candidate engine. A future
package version may remove the correction only after the same executable hostile-token contract
passes against its generated bytes.

The old `CompletionNode` walker and its command-bearing static renderers are removed after the
library path is green. The existing shell modules may retain only the bounded capture,
hardening/validation, and public-script selection seam described above. No second long-lived
command inventory or candidate engine remains.

## Candidate graph contract

The graph is derived directly from the normalized registry:

- exactly 23 top-level public canonical commands in signed help order;
- every alias registered beside its canonical path: `ls`, `i`, `remove`, `rm`, and `demote`;
- recursive canonical `config get`, `config set`, `config list`, and `config unset` paths;
- every active command receives its local options plus every inherited root/global option, with
  duplicate spellings collapsed deterministically;
- option handlers use `allowedValues`, never the broader `parserValues`; positional enum handlers
  use argument choices;
- completion metadata is optional at the backward-compatible `CommandSpecInput` boundary and
  normalized before the adapter consumes it; and
- a generic extension fixture proves one declaration can still drive parser, help, docs,
  completion, and execution without a completion-local runtime.

Local provider kinds are `path`, `manifest`, and `skill`. Registry metadata binds them to exact
arguments/options rather than the adapter guessing from descriptions. The production provider:

- reads only the effective current directory, its bounded ancestor chain, and explicitly selected
  local path prefixes;
- completes directory/file prefixes without following symlinks;
- recognizes `skillsmith.toml` manifest candidates and obtains declared skill names only through
  the public canonical manifest codec;
- may recognize bounded nearby `SKILL.md` directories as local skill candidates;
- sorts and deduplicates by exact emitted value; and
- has no network, subprocess, environment discovery, mutation, prompt, config write, or application
  service capability.

## Internal transport and bounds

Generated scripts call the exact internal protocol:

```text
skillsmith complete -- [already-tokenized invocation ...]
```

`packages/cli/src/index.ts` recognizes only the adjacent `complete`, `--` marker before signal
installation or public `buildProgram()`. `complete` without the immediate marker falls through to
the public parser and remains an unknown-command usage error. The transport is not registered in
Commander, `CommandSpec`, help, docs, completion candidates, or the 23-command inventory.

The implementation freezes these defensive limits unless Ready review tightens them:

- at most 64 input tokens, 4 KiB per token, and 16 KiB total input;
- at most 32 ancestor levels, 512 entries per directory read, and 256 KiB per manifest;
- at most 256 deduplicated candidates and 64 KiB of emitted candidate protocol;
- a 500 ms monotonic local-provider deadline checked between reads; and
- fail-closed empty/directive output on malformed, over-limit, unreadable, deadline, or package
  adapter failure, with no error detail or local path leaked to shell stdout.

Successful protocol output has one closed line grammar:

```text
<candidate-value> [ TAB <description> ] LF
...
:<unsigned-decimal-directive> LF
```

The directive is the final and only directive line. Candidate values must be nonempty; values and
descriptions reject NUL, CR, LF, TAB outside the one field delimiter, C0/C1 controls, and any
invalid Unicode scalar sequence. Successful output permits only no-space, no-file-completion, and
keep-order directive bits; filter-file/filter-directory and unknown bits are rejected because local
providers emit exact bounded candidates. Input-token, candidate, description, captured-package,
and final-output limits are all measured in UTF-8 bytes, not JavaScript code units. Malformed,
truncated, over-limit, or post-directive content fails closed to exact `:5\n`
(error plus no-file-completion) and never partially exposes candidate data.

Empty target completion may return real bounded local candidates but never synthesizes `--all`,
wildcards, every known registry item, or another mutation-widening selection. Prefix filtering is
exact and deterministic.

## Public script and help contract

- `skillsmith completion bash|zsh|fish` exits 0 and writes exactly one byte-stable sourceable script
  to stdout plus no stderr/status output.
- Missing/unsupported shell, including PowerShell, exits 2 through the existing usage boundary.
- Each script registers only `skillsmith` and invokes only the exact internal `complete --`
  transport; it does not run discovery during generation.
- Sourced callbacks pass each already-tokenized word as one argv element and never evaluate,
  interpolate, or reparse it as shell syntax. A trailing space reaches the transport as one final
  empty argument.
- Completion help and generated current docs explain source/save/package-manager placement without
  adding an installer or suggesting automatic startup-file edits.
- Script generation and tab-time completion perform zero writes. Tests seed Bash, zsh, Fish, XDG,
  and home startup canaries and compare the complete fixture tree before/after.
- Syntax validation is host-independent for all three generated forms using exact shell-specific
  structural invariants; Bash additionally passes `bash -n`. G6-01 later repeats syntax and
  packaged-byte checks in its declared clean distribution images, where target shells are present.

## Test-first selector plan

All seven selectors are created before dependency/product changes. The existing 24-test completion
suite and EWP-P1-TS07 remain green characterization; the new selectors fail because aliases,
recursion, allowed-value narrowing, providers, internal transport, and library scripts are absent.

### EWP-CMD-COMPLETION-TS01

- Generate Bash/zsh/Fish scripts twice and prove byte equality.
- Exercise the callback protocol for each shell surface and compare root candidates with the exact
  23 canonical commands plus adjacent aliases, without five-group presentation affecting order.
- Reject duplicate aliases, a 24th public command, `complete`, PowerShell, or help-only names.

### EWP-CMD-COMPLETION-TS02

- Prove `config` recursively yields exactly `get`, `set`, `list`, and `unset`.
- Prove nested options/arguments resolve at their full paths and sibling/parent candidates do not
  leak into the active node.

### EWP-CMD-COMPLETION-TS03

- For all public/nested specs, compare suggested flags with exact local plus inherited global
  spellings independent of common/advanced help grouping.
- Preserve short/long pairs, value-taking behavior, alias command paths, and deterministic
  duplicate collapse.

### EWP-CMD-COMPLETION-TS04

- Compare every positional choice and option value handler with registry truth.
- Prove command-specific `allowedValues` narrow broader parser values; for example install scope
  offers `user|project`, not `system|managed`, while read-only commands retain their permitted set.
- Exercise both `--option value` and `--option=value` through the candidate engine and sourced Bash
  callback; attached Bash results retain the exact option prefix.
- Prove unsupported prefixes and boolean options do not emit value candidates.

### EWP-CMD-COMPLETION-TS05

- Use a hermetic local tree with paths, a canonical manifest, nearby `SKILL.md` directories,
  symlinks, oversized/unreadable inputs, and empty/malformed cases.
- Prove local path/manifest/skill prefix candidates, stable sorting/deduplication, no symlink
  traversal, every declared bound, no network/subprocess/write/prompt call, and byte-identical
  fixture state.
- Prove empty target completion never emits `--all`, `*`, undeclared skills, or a widened mutation
  set.

### EWP-CMD-COMPLETION-TS06

- Validate exact emit-only stdout/stderr/exits, deterministic bytes, Bash syntax, zsh/Fish
  structural syntax, exact internal callback markers, and zero runtime `eval`/joined request
  strings in every final script.
- First freeze the pinned upstream Bash behavior as expected red: source the unchanged generated
  skeleton and prove it executes a harmless command-substitution canary and loses exact token
  boundaries. Then source the hardened Bash script with a stubbed `skillsmith` function and prove
  byte-exact argv plus no filesystem side effect for literal `$()`, backticks, semicolons, single
  and double quotes, spaces, tabs, newlines, globs, backslashes, leading dashes, and a trailing empty
  token. The stub must prove the only fixed prefix is `complete --`.
- Corrupt, remove, duplicate, and reorder each pinned hardening anchor and prove generation fails
  closed rather than emitting partially transformed shell bytes. Exercise malformed candidate
  lines, invalid directives, protocol controls, UTF-8 byte boundaries, truncation, and content
  after the directive; no partial candidate may survive.
- Prove completion help/current docs give manual/package placement guidance while the parser has no
  install/uninstall completion form.
- Seed real-looking startup/config canaries and prove generation/candidate calls never modify them.

### EWP-P6-TS02

- Aggregate all three shells, root/alias/nested/flag/value/provider paths, and the public CLI plus
  internal pre-parser entrypoint.
- Prove 23-command parser/help closure, internal transport invisibility, bounds/directives, pure
  generation, source compatibility, typecheck, and runnable native x64/ARM64 compilation.

  attachment or singleton leakage?

  bounded in input, reads, time, candidates, and bytes?
