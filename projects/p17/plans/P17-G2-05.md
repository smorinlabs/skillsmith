# P17-G2-05 implementation plan

## Outcome and exact scope

P17-G2-05 completes the Phase-2 persisted-artifact contract. It supplies one immutable inventory
and conservative codec/repository boundary for manifest v1, lock v1, saved plan v1, placements
ledger v1/v2, and logical transaction journal v1. It adapts the signed manifest and lock
authorities, preserves the sole signed legacy-project conversion, defines explicit DTO/domain
mappers, performs supported migrations in memory, and emits deterministic canonical bytes where
full generated serialization is permitted.

The six primary entities are exactly `EWP-CF-029`, `EWP-P2-T06`, `EWP-P2-TS06`,
`EWP-P2-TS08`, `P0-07`, and `P0-08`. Dependencies are signed:

- G2-02 sign-off `7ce00ac`, accepted implementation
  `2efd38991a3bbaf8d0041615561a81d9c26c30be`;
- G2-03 sign-off `15c3c67`, accepted implementation
  `6151cdea0ece5727e5a11f36d619e278b64792bf`;
- G2-04 sign-off `4c8475c`, accepted implementation
  `5c902f700a14a83e33118d183e9eef08bab2c308`.

The immutable catalog remains unchanged at 16 required-now validations, 73 downstream-only
validations, and their 89-ID union. The exact required commands appear in the ownership section.
P1-TS10, P2-TS01, P2-TS03, and P2-TS04 are additional plan-level compatibility replays; they do
not alter the immutable catalog partition. During iteration P2-TS04 uses the repository smoke lane;
its full selector runs only for G2-05 sign-off or a direct change to its mechanics.

This group defines persisted formats, read/mapping repositories, and one policy-free
coordinator-delegated commit primitive for an already validated project-config migration. It does
not select or invoke that primitive, create a lockfile for migration alone, or implement the Phase-3
planner, status join, ledger reducers, staged ledger-v1-to-v2 replacement, history retention policy,
transaction scheduling, resume/abort, plan execution, approval, or any future command. The current
private G2-03 artifact-pair recovery record remains private physical mechanics and is not rebranded
as the public journal.

## Shared conservative codec and artifact inventory

The signed string/JSON `WireCodec` surface and current CLI output registry remain byte-for-byte and
type-for-type unchanged. TOML, raw-byte ownership, versionless legacy manifest classification, and
human-presentation policy do not fit that interface, so G2-05 adds the distinct byte-oriented
`ArtifactCodec` surface frozen in the normative API block below. `artifactContractRegistry` is the
one and only persisted-artifact registry and ordering authority; versioned entry points are frozen
re-exports of its codec objects and never construct another registry. ADR 0008 describes the one
complete contract catalog as these two type-safe views: the signed command-output view and this
persisted-artifact view. Its generated inventory concatenates their owned descriptors and is never
maintained as a third list. No parser library, schema object, migration handler, cause, raw payload,
or mutable DTO is exposed.

The artifact layer adds one immutable registry with this exact ordered inventory:

1. `manifest@1`;
2. `lock@1`;
3. `plan@1`;
4. `ledger@1`;
5. `ledger@2`;
6. `journal@1`.

Each artifact descriptor fixes ID, version, `version` or `schemaVersion` discriminator, optional
kind, TOML or JSON syntax, human or canonical presentation policy, terminal-LF policy, recursive
unknown-field rejection, declared source migrations, and conservative compatibility. Registry
construction owns its descriptor/codec array, rejects duplicate identities or policy drift, and
returns frozen artifact lookup views. Unknown IDs and versions return
no codec; decoding a known future version returns a fixed unsupported-version error. Exact legacy
manifest input is a structurally classified migration source of `manifest@1`, not a fictitious
version-zero codec.

Every codec:

- synchronously copies an ordinary non-shared byte view before decoding;
- uses fatal UTF-8 and rejects a BOM;
- discriminates kind/version before strict current-version validation;
- recursively rejects unknown fields, invalid finite-number forms, accessors, proxies, exotic
  prototypes, sparse arrays, duplicate identities, and inconsistent cross-references;
- returns deeply owned/frozen models and fixed secret-safe errors;
- never invokes a caller iterator, constructor, species, accessor, coercion, or thrown value;
- rejects sensitive material before returning canonical persistable bytes;
- declares migrations explicitly and never strips fields to guess a future schema.

Canonical JSON uses schema property order, two spaces, and exactly one final LF. The sole framing
exception is compatibility-only `ledger@1` encoding, which reproduces historical
`JSON.stringify(dto, null, 2)` with no final LF; generated current ledger output is always
`ledger@2` with one final LF. Canonical TOML uses the signed schema order and exactly one final LF.
Dynamic record keys and set-like arrays sort by unsigned UTF-16 code units; operation arrays and
journal history retain their semantic order.

### Normative artifact codec and registry API

```ts
type ArtifactId = 'manifest' | 'lock' | 'plan' | 'ledger' | 'journal';
type ArtifactSource =
  | { kind: 'version'; version: number }
  | { kind: 'shape'; id: 'legacy-project-config' };
type ArtifactDiscriminator =
  | { kind: 'field'; field: 'version' | 'schemaVersion' }
  | { kind: 'classifier'; id: 'manifest-v1-or-legacy-project-config' };
type ArtifactMigrationDescriptor = {
  source: ArtifactSource;
  targetVersion: number;
  mapperId: 'legacy-project-config-to-manifest-v1' | 'ledger-v1-to-v2';
};
interface ArtifactCodecDescriptor<Id extends ArtifactId = ArtifactId, Version extends number = number> {
  readonly id: Id;
  readonly version: Version;
  readonly syntax: 'json' | 'toml';
  readonly discriminator: ArtifactDiscriminator;
  readonly wireKind: string | null;
  readonly presentation: {
    readonly decode: 'human' | 'canonical';
    readonly encode: 'canonical' | 'compatibility';
  };
  readonly terminalLf: boolean;
  readonly unknownFields: 'reject-recursive';
  readonly migrations: readonly ArtifactMigrationDescriptor[];
  readonly compatibility: 'conservative';
}
interface ArtifactMigrationInfo {
  readonly mapperId: ArtifactMigrationDescriptor['mapperId'];
  readonly targetVersion: number;
}
interface DecodedArtifact<Model> {
  readonly source: ArtifactSource;
  readonly model: Model;
  readonly canonical: boolean;
  readonly migration: ArtifactMigrationInfo | null;
}
interface ArtifactCodec<Id extends ArtifactId = ArtifactId, Version extends number = number, Dto = unknown, Model = unknown> {
  readonly descriptor: ArtifactCodecDescriptor<Id, Version>;
  validate(input: unknown): Result<Dto, ArtifactCodecError>;
  fromDto(dto: Dto): Result<Model, ArtifactCodecError>;
  toDto(model: Model): Result<Dto, ArtifactCodecError>;
  decode(bytes: Uint8Array): Result<DecodedArtifact<Model>, ArtifactCodecError>;
  encode(model: Model): Result<Uint8Array, ArtifactCodecError>;
}
interface ArtifactContractRegistry {
  readonly codecs: readonly ArtifactCodec[];
  get(id: ArtifactId, version: number): ArtifactCodec | undefined;
  latest(id: ArtifactId): ArtifactCodec | undefined;
}
declare const artifactContractRegistry: ArtifactContractRegistry;
```

The descriptor table is exact:

| Identity | syntax/discriminator | kind | presentation | final LF | migrations |
|---|---|---|---|---:|---|
| manifest@1 | TOML/classifier | null | human read, canonical encode | yes | legacy-project-config → 1 |
| lock@1 | TOML/`version` | null | canonical/canonical | yes | none |
| plan@1 | JSON/`schemaVersion` | `skillsmith.plan` | canonical/canonical | yes | none |
| ledger@1 | JSON/`schemaVersion` | `skillsmith.placements` | human/compatibility | **no** | none |
| ledger@2 | JSON/`schemaVersion` | `skillsmith.placements` | canonical/canonical | yes | v1 → v2 |
| journal@1 | JSON/`schemaVersion` | `skillsmith.transaction-journal` | canonical/canonical | yes | none |

`packages/core/src/artifacts/registry.ts` alone constructs and orders this inventory. Repositories
resolve codecs only through `artifactContractRegistry.get`; direct codec imports are limited to
registry construction, focused codec tests, and the versioned re-export indexes. The public
versioned DTO mappers call the identical codec methods. There is no other artifact registry,
descriptor list, or hand-maintained generated-inventory list.

## Manifest and lock adapters

`manifest@1` delegates structural classification, strict reading, normalization, portability,
source identity, and semantic projection to G2-01. It accepts canonical human TOML without
requiring presentation canonicality. Its read result preserves owned exact source bytes/revision,
normalized semantics, shape, and visible migration metadata. Exact legacy input delegates only to
G2-04's internal lossless migration authority; mixed, empty, malformed, unknown, future, unsafe
comment relocation, unsupported scope, and nonportable values refuse. Read-only decode never
changes bytes.

Manifest generated encoding accepts only a normalized v1 model and emits the signed schema order.
It starts with the literal UTF-8 bytes `version = 1\n` and derives edits in this exact order:
nonnull defaults `tools`, `scope`, then `path`; nonnull registry default; then one `add-skill` for
each declaration sorted by name. Null DTO fields are omitted from the normalized editor input. A
nonempty derived list is applied in exactly one `editManifestBytes` call. A valid empty normalized
model derives zero edits and returns an owned copy of the literal base without calling the editor;
it never invents a noop edit. Both branches require the same canary scan, strict
reread/normalization, and semantic equality before returning. `manifest-v1.golden.toml` and TS08
round-trip both the empty model and a populated model. Thus the signed G2-03 editor and its private
serializer remain the only declaration/string serializer and neither file changes in G2-05. That
encoder is for new/generated artifacts and saved after-images. Human-file mutation
continues to use G2-03 targeted edits; a later executor must translate normalized intent into those
edits or refuse rather than full-rewrite an existing human file.

`lock@1` is a strict identity-preserving adapter over G2-02
`readPortableLockSource`/`serializePortableLock`. It requires exact canonical TOML and retains the
signed lock-canonical hash. The adapter cannot reinterpret source identity, hash domains, ordering,
or missing/stale/incomplete relationship policy.

## Saved plan v1

The canonical root field order and exact required fields are:

```text
schemaVersion, kind, skillsmithVersion, executorSchemaVersion, hashSchemaVersion,
portability, artifactPair, manifestSemanticHash, lockCanonicalHash, options, selection,
operations, checks, diagnostics, resourcePreconditions, selectionPreconditions,
capabilityPreconditions
```

The discriminators are `schemaVersion: 1`, `kind: skillsmith.plan`,
`executorSchemaVersion: 1`, and `hashSchemaVersion: 1`. `skillsmithVersion` is audit data, not a
patch-version execution gate. `manifestSemanticHash` is a manifest-semantic v1 digest.
`lockCanonicalHash` is a lock-canonical v1 digest or null only when the lock was observed absent.

`artifactPair` contains manifest and lock locations plus `lockSource: explicit | sibling`. A
location is either `{kind: portable, token}` or `{kind: machine-bound, path}`; it never contains
both a portable token and resolved local absolute path. `options` is exactly `{prune, locked}`.
`selection` carries `selectionSource`, sorted unique skill names, tools, and user/project scopes.

The exact executable operation kinds are install, update, remove, link-dev, promote, move-scope,
adapt, repair, write-manifest, write-lock, migrate-project-config, and migrate-ledger. Each ordered
operation has:

- normalized unique `operationId`, `groupId`, nullable `pairId`, kind, and earlier-only
  `dependsOn` IDs;
- skill, credential-free source, tool, scope, reason, and selection source;
- a closed absent/placement/manifest/lock/ledger before image and after image;
- referenced precondition IDs and required-check IDs;
- none/reversible/conditional reversibility plus retention-resource IDs;
- exact live/manifest/lock/ledger mutation booleans;
- null or one bounded conflict snapshot with class, normal/forced behavior, exact target, and
  backup policy.

IDs use G1-07's normalized 1..256/no-control grammar. `pairId` requires `groupId`; operation IDs are
unique. `dependsOn` may reference only an earlier operation. Operation kind, images, mutation flags,
source form, scope, and reversibility are cross-validated. A desired new lock is carried only in a
write-lock after image. Literal acquisition URLs, authentication, raw errors, causes, stacks,
ports, functions, and current renderer action DTOs are unrepresentable.

Resource preconditions declare a closed resource identity, exact hash domain/schema, expected
digest, and nullable closed repository revision from the normative union below. Ordinary manifest plans use semantic hashes;
migrate-project-config additionally pins exact manifest bytes. Selection preconditions carry the
complete sorted selected-set membership required by bulk/all/prune/delete behavior. Capability
preconditions contain only referenced tool/operation/version/support/scope facts. IDs are unique
and every reference resolves.

Checks are the closed source-resolution, capability, content-integrity, verification, and
precondition-validation families. They are blocking and name their dependent operations.
Diagnostics are non-executable noop, skip, refuse, conflict, or warning records with stable reason,
severity/refusal class, affected identity, correlation IDs, and selection source.

Portability is exact:

- portable means `{kind: portable, reasons: []}` and forbids every local absolute binding;
- machine-bound requires nonempty unique reasons using only absolute-artifact-selector,
  local-project-root, local-dev-source, absolute-live-placement, or custom-absolute-target. Each
  reason has a fixed message, path, and referenced resource preconditions.

G2-05 owns `SavedPlanV1` to/from plain `SavedPlanV1Dto` with explicit field enumeration. G3B/G4
later own planner-domain to persistence-domain construction, reasons/conflict policy, redaction and
portability derivation, staleness evaluation, execution reconstruction, approval, and scheduling.
Any later payload outside the frozen union requires a schema or executor version change; no opaque
extension bag is accepted.

summary. Every object has exactly the declared own string keys, recursively; symbols, accessors,
proxies, exotic prototypes, sparse arrays, non-finite numbers, and unknown keys refuse. `Id` is a
trimmed 1..256-character string without C0/DEL controls; `Code` matches

messages that do not interpolate paths, and reference existing resource preconditions.

local-project-root, `plan binds a local project root`; local-dev-source,

## Ledger v1/v2 and pure migration

Ledger v1 freezes the accepted current durable family:

```text
schemaVersion: 1, kind: skillsmith.placements, updatedAt, skills, optional projects
```

User/project skill trees retain placement path, mode, dev, optional-by-absence or null pinned,
optional origin, and optional-by-absence or null legacy pair journal. The embedded
`LegacyPairJournalV1` remains exactly the current promote/dev/rollback/install/uninstall record with
txId, prepared/staged/backed-up/live/committed phase, timestamps, before image, staging path, and
backup path. Migration preserves it without renaming or reinterpretation.

Ledger v2 is exactly:

```text
schemaVersion: 2, kind: skillsmith.placements, updatedAt, skills, projects,
projectRegistrations, transactions, history
```

V2 retains the v1 user/project/pair facts and legacy pair journal. Tool keys are normalized
nonempty adapter IDs rather than a hard-coded currently available tool branch. Each
`projectRegistrations[realpathRoot]` contains a canonically sorted `consumers` array; a consumer
names skill, tool, placement path, and null or `{path, contentHash}` store protection. Each current
project pair appears once; retained pinned facts remain consumers even in dev mode. Empty
registrations are legal, and no timestamp is fabricated during migration.

Pure v1-to-v2 migration copies every fact, makes projects required, derives registrations from
project consumers, initializes transactions to `{}` and history to `[]`, retains the v1
`updatedAt`, and reports every preserved legacy journal identity. It never writes. Decode returns
source version, exact byte revision, semantic revision, normalized model, and either null or a
visible pure ledger migration metadata envelope. G3B later translates that metadata to a
migrate-ledger operation. V1 encode is compatibility-only; current generated encode emits v2. V1
migration followed by v2 encode/decode must preserve semantic revision.

Only an absent path is a missing/empty read state, and it does not fabricate a timestamp. Existing
zero/whitespace, invalid UTF-8/BOM, truncated/malformed JSON, schema-invalid input, wrong kind,
unknown recursive field, or invalid cross-reference is state error 3. A version above 2 is a fixed
future-version/upgrade error. Read-only and dry-run paths take no lock and leave bytes unchanged.

The existing `place/ledger.ts` becomes the exact compatibility facade in the normative matrix
below; it must not retain JSON parsing or schema ownership. It preserves current v1 live behavior
until G3B and refuses v2 before any current mutable caller can truncate or downgrade it. G3A
integrates the read model; G3B owns
immutable reducers, writer locks, stage/fsync/backup/replace/cleanup, first-mutation migration,
doctor fix, and history bounds.

## Logical journal v1

`journal@1` has `schemaVersion: 1` and kind `skillsmith.transaction-journal`. It records one logical
execution attempt with transaction ID, persisted operation intent, context, disposition, logical
phase, actual resource state, timestamps, and retention.

The intent is the closed operation identity/kind/target, planned before/after, mutation flags, and
reversibility projection shared with saved-plan persistence. Context contains parent operation ID,
command, workflow, positive attempt, and start time. Disposition is forward or rollback. Logical
phase is prepared, staged, backed-up, live, or committed.

Unlike reviewed intent, `actual.before` and `actual.after` contain post-lock observed logical
resources as this exact union:

- live: resource ID, role, absent/present, nullable repository revision, canonical placement path,
  nullable dev/pinned mode, nullable symlink target, and nullable content hash;
- manifest: resource ID, role, absent/present, nullable repository revision, artifact location,
  nullable shape/version, nullable exact-byte hash, and nullable semantic hash;
- lock: resource ID, role, absent/present, nullable repository revision, artifact location,
  nullable version, and nullable canonical hash;
- ledger: resource ID, role, absent/present, nullable repository revision, nullable schema version,
  and nullable semantic resource hash.

Absent states require every content-specific field to be null; present states require their role's
path/location, version where applicable, and exact revision/hash fields. `actual.retained` is the
closed backup/store union: resource ID, role, path, repository revision, content hash, and nullable
retain-until. Arrays sort by resource ID, roles are unique per resource, and intent mutation roles,
actual states, and retained reversibility IDs cannot contradict. Transactions contain only
nonterminal journals; history contains committed final journal snapshots in commit order.
Bounds/expiry are writer policy deferred to G3B.

The journal never contains the G2-03 private artifact recovery key, cursor grammar, parent inode
facts, object slots, ownership token, collision/CAS path, transaction-directory name, private record
revision, physical barrier transcript, or retry cap. Logical and physical layers may correlate only
through shared operation/transaction identity.

## Repository boundary and fixed errors

The pure artifact repository owns absent/present classification, byte ownership, codec selection,
version discrimination, exact/semantic revision calculation, supported in-memory migration, and
canonical serialization. Its read capability is limited to path kind and exact bytes. Results are
immutable envelopes and never expose caller-owned bytes.

The separately named internal `executeProjectConfigMigration` adapter must delegate the frozen
`ProjectConfigMigration` to G2-03 `updateCoordinatedHumanFile`; it is the only G2-05 effect seam and
is not a repository method. It reruns the signed `{kind: migrate-legacy}` edit under the coordinator after
exact expected-revision comparison, targets only the manifest path, cannot create or select a lock
artifact, and cannot duplicate the physical protocol. Automatic mutation and doctor fix must call
this same operation factory/commit method; caller mode is deliberately absent from both APIs.
Ledger write/migration effects are not implemented here.

Codec errors use one fixed artifact-codec code and repository failures use one fixed
artifact-repository code; their closed reasons and precedence are normative below. They name only
artifact ID, requested version, bounded field path, exit class, and fixed message. Raw bytes, input
values, paths containing sensitive syntax, schema-library issues, thrown objects, and causes are
never retained or interpolated.

Each reason has exactly one message and exit: invalid-request, `artifact read request is invalid`,
2; invalid-file-kind, `artifact path is not a regular file`, 3; permission-denied,
`artifact read permission was denied`, 6; read-failed, `artifact could not be read`, 3; malformed,
`artifact source is malformed`, 3; invalid-shape, `artifact shape is invalid`, 3;
unsupported-version, `artifact version is not supported`, 3; migration-failed,
`artifact migration failed`, 3; noncanonical, `artifact bytes are not canonical`, 3; and
sensitive-content, `artifact contains sensitive content`, 3. Messages never interpolate artifact
IDs, paths, values, OS/parser/schema text, or causes. Error paths contain at most 16 static schema
segments of at most 64 characters or safe numeric indexes; dynamic skill/root/tool/resource keys
are represented by `'*'`. `requestedVersion` is null until a positive safe integer discriminator is
known and otherwise retains that discriminator.

Repository precedence is total:

1. Validate ordinary, nonempty, non-canary request path and artifact ID before invoking a port.
2. `pathKind`; EACCES/EPERM maps to permission-denied, other failure to read-failed.
3. Absent returns timestamp-free `ArtifactAbsent` without `readBytes`.
4. Directory, symlink, or other returns invalid-file-kind.
5. `readBytes`; permission outranks other read-failed.
6. Require/copy an ordinary non-shared byte view; a bad port value is read-failed.
7. Zero/ASCII-whitespace-only, UTF-8 BOM, or fatal UTF-8 is malformed.
8. Syntax error, truncation, or duplicate JSON object member is malformed. Duplicate members are
   rejected rather than last-wins accepted.
9. A primitive or array JSON root is invalid-shape.
10. For kind-bearing JSON, wrong/missing/nonstring kind is invalid-shape before version checks.
11. Missing, string, zero, negative, fractional, or unsafe discriminator is invalid-shape. The
    manifest structural classifier instead delegates canonical/legacy/mixed/empty/unknown/future
    shape identity to the signed manifest reader.
12. A positive unsupported future or old version is unsupported-version even when other fields
    are unknown.
13. Recursive unknown fields, bad enums/types, duplicate identities, and cross-reference failures
    are invalid-shape.
14. Lock, plan, ledger v2, and journal require byte equality with their canonical re-encode;
    otherwise noncanonical. Manifest and ledger v1 accept human/legacy presentation.
15. Apply the recursive sensitive-content gate before returning or encoding.
16. Run only the descriptor-declared in-memory migration and explicit DTO/domain mapper.
17. Return a deeply owned/frozen envelope; no read path writes, locks, retries, or converts failure
    into absence.

Model mapping is explicit: manifest maps to `NormalizedManifestV1`; lock to `PortableLockV1`; plan
to immutable `SavedPlanV1`; ledger v1/v2 to one immutable `LedgerModel` with the exact semantic
projection fields; journal to immutable `LogicalJournalV1`. DTOs never leak through the root API.

Repository CAS byte revision has one authority for every artifact:
`hashCanonicalInput('resource', 1, exactOwnedBytes)`. `ArtifactReadEnvelope.byteRevision`, ledger
source/target byte revisions, `ProjectConfigMigration.expectedByteRevision` and
`resultByteRevision`, and G2-03 `ArtifactFileRevision.digest` at the coordinated-human-file seam all
use that identical formula. This local CAS revision is distinct from portable semantic facts:
manifest exact-byte preconditions and `PlanImageV1.byteHash` use `hashManifestBytes` and its
`manifest-bytes` domain; lock identity uses `lock-canonical`; normalized manifest identity uses
`manifest-semantic`. These domains are never compared to one another.
