## Mapping corrections and overlap boundaries

### Semantic projection versus hashes

G2-01 owns a deterministic normalized manifest-semantic projection and fixtures proving that
formatting-equivalent input projects identically while every semantic field mutation changes the
projection. It does not frame a hash domain, invoke SHA-256, serialize a lock, or correlate a lock
to a manifest. G2-02 reruns and extends `EWP-P2-TS01` and owns all digest/domain/canonical-lock
behavior through `EWP-P2-TS03` and `EWP-CF-027`.

### Bounded config edit versus the general artifact editor

G2-01 owns the narrow vertical slice explicitly required by `EWP-CMD-CONFIG-TS01` and TS04:
range-preserving edits of known flat config keys and canonical `[defaults]`/`[registry]` keys,
visible exact-legacy migration in the same project edit, permission/newline preservation,
byte-identical semantic no-ops, single-file lock-and-replace, cleanup on ordinary refusal/failure,
and correct usage/state/permission exit classes.

G2-03 generalizes this prerequisite into the reusable all-field human-artifact editor and owns
absent-target coordination, exact external-writer guards, safe replan, SIGINT, two-file crash
windows, generalized pair atomicity, and shared recursive redaction. G2-05 owns repository-wide
CF-029 equivalence across every caller, supported-version migrations, saved-plan staleness,
concurrency/crash/no-lock matrices, and canonical repository codecs. G2-01 must not claim either
later contract complete. G2-03 mechanically requires replay of `EWP-CMD-CONFIG-TS01`,
`EWP-CMD-CONFIG-TS04`, and `EWP-P2-TS01` before its own sign-off.

### Bounded tokenizer/range editor design

The required Phase-2 spike is an internal tokenizer/range editor, not another object stringify and
not a new dependency. `smol-toml` remains the semantic parser; the editor independently scans exact
source ranges for newline/trivia, comments, bare/single-quoted/double-quoted keys, table and array-
table headers, dotted keys, single-line strings/booleans, and single-line arrays of strings. It
never reserializes an untouched range.

The supported G2-01 mutations are deliberately closed:

- replace one known scalar or tools-array value while retaining key spelling, surrounding spaces,
  comma style, and inline comment;
- insert one missing known key at the end of an existing `[defaults]` or `[registry]` table, or
  append the missing table with the file's newline form;
- unset one known key by removing only its syntactic key/value range; preceding comment blocks stay
  byte-identical in place rather than being guessed as disposable;
- migrate an exact legacy file only when `tool`/`scope`/`path` form one safely transformable
  top-level region and `[registry]` is structurally separate. The version/defaults header and mapped
  fields replace that region in place; attached leading trivia moves only within the same region.

Multiline strings/arrays, duplicate editable keys, inline tables, dotted aliases of target keys,
table re-openings, a comment that would cross a table boundary, or any ambiguous attachment refuse
without writing. The refusal includes a deterministic unified manual patch produced from the
validated semantic target, with paths and values redacted through the existing boundary.

The focused port extension is exact: `readFileMetadata(path)` returns the regular-file mode and
identity needed by the editor, and `setFileMode(path, mode)` applies the preserved permission bits to
a staged file. Symlink/directory destinations refuse. Under the existing ephemeral coordination
lock, a changed edit writes one same-directory temporary file, applies the original mode, flushes
the file, renames, flushes the directory, and removes any temporary residue on ordinary failure.
An absent destination uses the platform's configured creation mode. A byte-identical edit performs
no directory creation, staging, chmod, flush, or rename. “No migration lock” means no paired
`skillsmith.lock` artifact; the ephemeral coordination lock is still required.

The spike fixture table covers LF/CRLF/final-no-newline, tabs/spaces, single/double/quoted keys,
inline and leading comments, defaults/registry/skills table ordering, singleton/plural arrays,
`0o600`/`0o640`/`0o644` preservation, no-op identity, unsafe attachment refusal/manual patch, and
staged-write failure cleanup.

## Unified manifest boundary

### Shape discriminator

The document reader first classifies source text without writing:

- `canonical`: top-level integer `version` is present and only canonical keys/sections occur;
- `legacy`: no `version`, and only exact legacy `tool`, `scope`, `path`, and `[registry].default`
  fields occur;
- `mixed`: canonical and legacy markers coexist;
- `empty`: zero bytes, whitespace-only, or comment-only;
- `malformed`: TOML cannot be parsed;
- `unknown`: parsed structure contains an unknown key, invalid section shape, or unsupported value;
- `future`: a structurally canonical document names a version newer than 1.

Only exact legacy and canonical v1 are readable. Mixed, empty, malformed, unknown, and future
documents return state exit 3 and never normalize, migrate, or write. Read-only exact-legacy use
returns `migrationPending: true` and preserves the exact bytes.

### Raw v1 schema

The strict raw document contains:

- `version = 1`;
- optional `[defaults]` with `scope`, unique nonempty `tools`, and optional portable `path`;
- optional `[registry]` with credential-free `default` host/namespace identity;
- zero or more `[[skills]]` declarations with required `name` and `source`, plus optional `ref`,
  `tools`, `scope`, `placement`, and `path`.

Unknown keys are rejected recursively. A name is trimmed, nonempty, control-free, bounded, and
unique in one manifest. Raw declarations may omit `tools` and `scope` only when the corresponding
manifest default exists. The normalized declaration always has a nonempty unique registry-known
tool list and a user/project scope. Missing both local and default authority is a state error.

The exact portable name grammar is 1..128 ASCII characters matching
`^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$`, with a trailing dot forbidden. It therefore rejects dot
segments, leading option markers, whitespace, path separators, drive/UNC syntax, and controls.
Requested refs are 1..255 UTF-8 bytes and implement Git check-ref-format safety in-process: reject
leading `-`, leading/trailing slash, trailing dot, a value equal to `@`, any slash-delimited
component beginning with `.`, any component ending in `.lock`, whitespace/control/DEL, `..`, `@{`,
`//`, and `~ ^ : ? * [ \\`. Positive fixtures include branches, tags, nested refs, and a full
40-hex SHA; negative fixtures include `.foo`, `foo/.bar`, `x.lock`, `foo/x.lock`, and every other
forbidden form. Short-SHA resolution policy remains acquisition authority. No ref is passed to Git
before this validation.

Raw duplicate tools are a schema error; they are never silently deduplicated. Normalization sorts
the already-unique effective tool IDs into canonical lexical order, uses `ref: null` as the explicit
default-ref sentinel, uses `placement: 'symlink'` when omitted, and uses `path: null` when omitted.
Reordering an otherwise identical raw tool array therefore produces the same semantic projection.
Declarations are projected by unique name and schema field order. The result is recursively owned/
frozen and never stores literal acquisition input, clone URLs, credentials, runtime paths, or IO
capabilities.

### Scalar config compatibility

Existing user/system/environment `Config.tool` remains scalar. Canonical `[defaults].tools` is
plural and is never collapsed silently:

- internal effective configuration owns `{ tools, source, cardinality }`; every higher-precedence
  layer replaces rather than merges the lower selection, in CLI -> environment -> explicit-file ->
  project -> user -> system order;
- a higher scalar therefore truthfully shadows a lower plural, and a higher plural replaces a lower
  scalar for list/check/doctor and every later operational consumer;
- a singleton projects as the current scalar `tool` value and keeps existing v1 config JSON bytes;
- unscoped `config get tool` refuses only when the effective selection is plural; scoped get refuses
  only when that selected layer is plural;
- scoped list reports the selected layer; unscoped list reports the effective source and retains a
  diagnostic for a lower shadowed plural without presenting it as effective;
- `config set tool <id> --project` visibly replaces the array with the singleton;
- `config unset tool --project` removes the entire default and is an exit-0 byte-identical no-op
  when absent.

Get/list v1 DTOs add an optional closed `notices` array with code, path, migration state, plural
tools, and effective/shadowed disposition. Existing representable reports omit the field and retain
exact bytes. Set/unset gain named v1 codecs for their current shapes plus an optional visible
`migrate-project-config` operation. Both human and JSON renderers route core structured notices to
stderr while stdout remains one canonical document. No first/last selection, lossy join, or
implicit output mutation is allowed.

### Canonical source and portable path identity

Manifest source validation is separate from the current acquisition parser. It accepts
credential-free HTTPS, SSH, scp, and registry/shorthand identities and produces only canonical
host, repository, optional source-relative POSIX path, and separately stored requested ref. It
rejects HTTP(S) userinfo, every query component, fragments, percent-encoded delimiter/credential
forms, plain HTTP, Git protocol, `file://`, malformed authorities, empty/escaping source paths, and
control characters without echoing secret material. URL parsing and redacted classification happen
before any diagnostic includes the original input.

Canonical registry identity is `host[/namespace]` without scheme, userinfo, query, fragment, or
escaping segment. Exact legacy credential-free HTTPS registry URLs normalize to that form. Plain
HTTP, SSH/file/custom schemes, credentials, query/fragment, malformed, or nonportable legacy
registry values block automatic migration and produce a secret-safe manual replacement.

Portable paths are validated independent of host OS. Only normalized `./project-relative`,
`~/home-relative`, or source-relative POSIX tokens are allowed in their corresponding fields.
Absolute POSIX, drive-qualified, UNC, traversal, store, ledger, dev, and incompatible-scope paths
refuse before any write. Exhaustive credential-canary/redaction coverage remains G2-03.

## Discovery, ownership, and artifact pairs

One immutable discovery snapshot derives from `ProjectContext` and contains:

- effective cwd and stable project root/identity;
- the nearest selected project manifest on the effective-cwd-to-project-root ancestor chain;
- the XDG user desired-state manifest at `skillsmith/skillsmith.toml`;
- the distinct XDG user config at `skillsmith/config.toml`;
- optional explicit config and explicit artifact selectors;
- parsed shape/ownership summaries for selected candidates.

A nested manifest is an intentional desired-state context boundary but never rebases live project
roots. Cwd changes within the same ancestor chain are invariant. Crossing into a subtree that owns
another manifest intentionally selects that nested context. Automatic owner lookup examines exactly
the selected project manifest, the project-root destination when it is distinct, and the XDG user
manifest—not an unbounded repository scan. Every existing candidate is classified before lookup;
an unreadable/malformed root candidate blocks selection because its ownership cannot be excluded.

Destination precedence for one resolved declaration name is:

1. explicit singular `--file`;
2. the one selected-project/root-destination/user manifest already declaring the name;
3. exit-2 refusal naming every path when two or more candidates declare it;
4. for a new project declaration, `<projectRoot>/skillsmith.toml` (or effective cwd for explicit
   project scope outside Git);
5. for a new user declaration, the XDG user desired-state manifest.

Uninstall-style selection never creates a file to record absence. If the selected nested manifest
does not own a name but the root destination does, the root is the existing owner rather than a
false new destination. Root/nested, root/user, nested/user, and three-way duplicates all refuse.
For a genuinely new user-scoped declaration, a non-owning root candidate does not override user
routing. A multi-name request whose names resolve to different manifest owners refuses before
mutation; one invocation still selects one manifest.

The pair resolver is singular. `team.toml` derives sibling `team.lock`. Explicit `--lockfile`
requires explicit `--file`; both resolve relative to effective cwd. Lexically identical normalized
destinations refuse with usage exit 2 before IO. When paths exist, one cached realpath per input
also rejects symlink aliases; absent paths use normalized absolute cache keys. The same-path
`--config`/`--file` dual role is allowed and parsed once, but manifest/lock equality is never valid.

The pair retains both original selector tokens and resolved paths. A relative override is portable
only when its normalized POSIX token stays inside the stable project root and any existing symlink
target does too; `..` escape, drive/UNC form, or symlink escape refuses. An absolute override is
explicitly machine-bound. The override is invocation-only and is never persisted into the manifest.
The resolver does not read or write lock contents and does not alter project root or live placement.

`packages/cli/src/util/artifact-pair.ts` and application read services become thin consumers of the
core authority. Independent `.git` probing, config discovery, and pair derivation are removed.
When `--config` and `--file` resolve to the same path, the snapshot reads/classifies bytes once but
exposes separate configuration and artifact roles.

## Config command behavior

System and user config keep their current flat `config.toml` schema and precedence. Project reads
accept exact legacy or canonical manifest defaults. Project set/unset selects the discovered
manifest when one exists; otherwise it uses the project-root destination. It does not blindly append
`skillsmith.toml` to the invocation cwd.

Key mapping for project canonical writes is exact:

| Config key | Canonical field |
|---|---|
| `tool` | singleton `defaults.tools` |
| `scope` | `defaults.scope` |
| `path` | `defaults.path` |
| `registry.default` | `registry.default` |

Legacy project set/unset performs one visible migration-plus-edit. It adds `version = 1`, maps
legacy `tool` to a singleton tools array, moves scope/path under `[defaults]`, retains registry,
preserves comments/order/whitespace/newline/mode where safe, and refuses with an exact manual patch
when attachment or portability cannot be preserved. No migration-only lock is created.

Config get/list remain read-only. Config unset of a missing key is exit 0 and creates no file.
For an existing canonical project file, missing-key unset is byte-identical. For an exact-legacy
project file, project unset still performs the required visible legacy-to-canonical migration even
when that particular key is absent; the migration is the requested canonical write and no paired
lock is created.
System-scope tests use injected/hermetic paths and never touch `/etc`. Permission failures map to
exit 6; invalid scope/key/value is usage exit 2; invalid document state is exit 3. Config set/unset
JSON is routed through named v1 codecs while retaining current canonical bytes for existing cases.

Exact failure classification is:

| Condition | Exit | Write result |
|---|---:|---|
| invalid key/scope/value, nonportable CLI value, manifest/lock collision | 2 | no write/residue |
| unsafe comment attachment/relocation in an otherwise valid document | 2 | no write/residue; deterministic manual patch |
| mixed/empty/malformed/future document or nonportable stored legacy value | 3 | no write/residue; manual correction where applicable |
| coordination-lock contention | 3 | no destination/staging residue |
| unreadable file for a non-permission reason | 3 | no write |
| directory or symlink destination | 3 | no write |
| filesystem permission denial during read/create/stage/mode/flush/rename | 6 | original preserved; staging cleaned |

Errors never echo raw source/registry credentials or unredacted manual-patch values.
