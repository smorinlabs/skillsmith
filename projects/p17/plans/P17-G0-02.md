# P17-G0-02 implementation plan

## Contract and ownership

P17-G0-02 closes the live-to-target CLI migration ledger without implementing future 1.0 parser
behavior. Primary IDs are `EWP-P0A-T02`, `EWP-P0A-T07`, `EWP-P0A-T11`, `EWP-P0A-TS02..04`,
`EWP-P0A-TS08`, `EWP-OPT-TS01`, `EWP-CF-010`, and `EWP-CF-023`. G0-01 is signed off.

Owned implementation and test files:

- `packages/cli/src/contracts/commander-surface.ts`

- `packages/cli/src/contracts/cli-migration-ledger.ts`

No `program.ts` or command implementation is changed. G0-02 does not add target commands/options,
migrate current no-op approval behavior, activate OPT-TS02..10, or execute downstream EWP-CMD
coverage. Catalog policy, documentation drift, architecture reconciliation, and target help/
completion generation remain owned by G0-05, G0-04, G0-03, and G6-02A respectively.

## Implementation sequence

1. Add failing contract tests for all five primary validations.
2. Implement a deterministic pure Commander-tree canonicalizer covering nested commands, aliases,
   arguments, option flags/value shape/choices/default/repeatability, and stable ordering.
3. Commit an immutable current 0.7.0 snapshot generated explicitly, never during ordinary tests.
4. Add a machine-readable closed migration ledger mapping every current surface exactly once and
   every Section-8.20 target surface to K/A/C/D/N disposition, implementation phase, and validation
   ownership. The accepted target contains zero R entries.
5. Prove live ↔ snapshot ↔ current ledger ↔ target registry ↔ help/test ownership closure.

`EWP-P0A-TS04` is a Phase-0 structural ownership gate: it proves the exact OPT-TS01..10 set and
planned executable ownership, but executes only required-now OPT-TS01. Future option gates remain
immutable downstream obligations. `EWP-P0A-TS08` compares generated help to the live/current side
and requires an explicit future target-help owner; it does not require future help bytes early.

## Negative cases

Mutation tests cover missing/extra live options, aliases and arguments; duplicate current/target
mappings; missing/unknown disposition, phase, or validation owner; R entries; contradictory
defaults; duplicate short flags; negated-boolean and repeatability drift; missing command unit/CLI/
workflow ownership; stale help inventory; local/global no-prompt collision; prose-only owners; and
future validations incorrectly promoted to required-now.
