## Ready review

Fresh independent review identified `P17-RV-P17-G5-03-F01`: the initial candidate incorrectly
combined a rollback disposition with an already-inverted committed intent. The signed reducer owns
that inversion, so the draft would have double-inverted terminal membership and restoration.

The plan is corrected to retain the original forward intent orientation, bind the approved current
image to original `intent.after`, record the new transaction's `actual.before` as that current image,
and record `actual.after` as restored original `intent.before`. No catalog lifecycle transition or
product/test edit is authorized until fresh independent re-review accepts the correction.

The same review identified `P17-RV-P17-G5-03-F02`: the initial candidate did not distinguish a
forward pending transaction from an already-pending rollback and did not freeze repeated behavior
after the reversal committed. The corrected plan converts only forward pending state, resumes an
existing rollback with its original identities and action class, and treats the newest valid
committed rollback as an explained `already-reversed` no-op without toggling or older-history
fallback. TS02, TS04, and TS09 own the retry/convergence proof.

The review also identified two shared-authority manifest gaps:

- `P17-RV-P17-G5-03-F03`: shared mutator/planning command types and validation omitted undo;
- `P17-RV-P17-G5-03-F04`: retained-history rollback planning and placement-plan execution were
  artificially typed to dev/promote, making a private undo implementation likely to duplicate them.

The candidate now owns the four shared planning/placement sources and their four parity/behavior
tests. It adds undo to shared immutable-plan authority, preserves explicit-selection enforcement,
and generalizes the signed rollback planner/executor seam while keeping compatibility output at the
edge.

`P17-RV-P17-G5-03-F05` found that private `already-reversed` classification would have contradicted
status eligibility: the current join can advertise a terminal rollback as reversable. The candidate
now owns `packages/core/src/status/join.ts` and freezes a wire-compatible correction: terminal
rollback disposition is `not-reversible` with no reverse remediation, pending rollback remains
eligible for its undo-resume argv, and `status@1` does not gain a new field. TS05 and TS09 prove the
distinction. The manifest is now 77 unique product/test/governance paths.

`P17-RV-P17-G5-03-F06` found an unsafe scope claim: standalone artifact-pair recovery records do not
carry the skill/tool/scope/parent identity required for target-bound undo selection. The corrected
plan aborts or resumes only selected ledger logical placement/move-scope journals. Overlapping
artifact recovery remains an exact-remediation same-operation blocker under its existing
coordinator; G5-03 neither guesses correlation nor changes that record schema.

`P17-RV-P17-G5-03-F07` found that the logical pending sequence could not apply to a preserved v1
pair journal because no matching logical transaction exists. The corrected plan uses the logical
begin-attempt/conversion sequence only for v2 logical forward pending state, resumes v2 rollback

fabricating a logical identity. TS01 and TS09 own legacy crash/retry coverage.

`P17-RV-P17-G5-03-F08` found that the existing swap terminal seam always projects rollback
`actual.after` from `actual.before`. That is correct for the converted pending-abort model but would
make fresh committed-reversal history falsely report the current image as restored. The candidate

points by the already-owned swap tests. The manifest is now 78 unique paths.
