## Approved efficiency and library decisions

- Bun's official executable documentation confirms the exact four cross-compilation targets used
  by the plan.
- npm's official package model supplies the necessary `bin`, `files`, `optionalDependencies`,
  `os`, `cpu`, and Linux `libc` selection; no download-on-postinstall library is needed.
- Bun installs platform-specific npm dependencies and can override OS/CPU for matrix verification;
  `bun pm pack` creates standard package tarballs accepted by npm/Bun.
- Homebrew's official Formula Cookbook supplies `bin.install`, platform/architecture selection,
  temporary `test do`, and formula audit/test mechanics.
- A local Bun 1.3.14 spike found `Bun.Archive` produced byte-identical gzip archives twice but
  restored a `0755` input executable as `0600`. The plan uses standard `tar` for public executable
  archives and may use `Bun.Archive` only for inspection. This avoids both a mode regression and a
  new archive dependency.
- Ordinary iterations build only the host target and reuse it across direct, npm, Bun, and formula
  tests. The four-target build is reserved for the impacted milestone, and the full repository
  suite remains terminal-only.
