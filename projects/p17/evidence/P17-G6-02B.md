## Existing implementation and gap audit

The existing completion implementation is a useful six-file static baseline but does not meet the
target contract. It walks the live Commander tree only far enough for one-level renderers. Current
scripts omit aliases, nested config actions, inherited flags after subcommands, local providers,
and a tab-time callback. Enum values come from broad Commander parser choices instead of the
command-specific `allowedValues` authority.

The live normalized registry has 23 public top-level commands, five adjacent aliases, four nested
config actions, and exact local/global option metadata. Its capability-aware distinctions are
material: install scope allows only `user|project` even though the parser recognizes
`managed|project|system|user` for capability diagnostics. The G6-02B adapter must consume the
narrow allowed set.
