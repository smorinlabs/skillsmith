## Existing implementation and gap audit

The live registry contains 28 declarative parser nodes: one root, 23 top-level public commands, and
four nested `config` actions. It already closes command names, aliases, arguments, options,
questions, descriptions, examples, exits, application services, and generic runtime attachment.
Current help is partially generated but remains flat; it does not own the five-group index,
workflow metadata, minimal invocations, progressive option families, current complete topics,
near-miss suggestions, README orientation, or a generated current command reference.

`research/commands/README.md` is a historical current/draft inventory governed by documentation
drift annotations, not the future generated authority. The candidate therefore creates
`docs/commands.md` and a delimited generated README region rather than mutating historical command
pages into an accidental second registry.

Commander is 12.1.0 in both `packages/cli/package.json` and `bun.lock`. The approved pre-entry
amendment selected Commander 15.x in G6-02A before G6-02B completion. The isolated spike identified
one bounded source compatibility change: explicit parsed defaults must also be registered for
negated options. It found no command/alias/option growth, no Bun runtime incompatibility, and no
native binary-size increase from Commander alone.
