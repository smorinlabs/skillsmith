  doctor/health blockers and five durability/integration blockers. Health@2 now rejects mutation
  counters in `not-requested` mode, authorizes repairs by exact operation and path, redacts finding
  values at its single mapping boundary, and defers lock repair until after a project migration has
  converged. The durability correction makes migration visible before install/uninstall pair work,
  connects bounded history cleanup to production commits, records fresh/adopt/repair/stale-remove
  history, converges migration recovery cleanup, and refuses symlinked recovery roots.
- **Authority consolidation:** all mutating placement callers now use one private expected-revision
  persistence gateway; install, uninstall, promote, and dev use one private migration
  operation/journal/execution module; and the canonical writer owns recovery plus terminal history
  finalization. The historical `writeLedger` compatibility helper has no production caller. One
  `legacyLedgerView` remains authoritative, and health validation/redaction has one boundary.
- **History safety:** `LedgerWriter.finalizeHistory` persists an over-capacity committed history
  before selecting one victim, proves the exact regular file identity/mode/link count/revision/hash
  and absence from live/pending/retained references, deletes and fsyncs it, then performs an exact
  CAS rewrite. Restart after deletion but before rewrite is recognized; an unsafe linked victim
  remains durable and blocks later history mutation.
- **Repair-shadow correction:** the impacted replay proved that pending logical-only repair journals
  must not require a fabricated install shadow. Record-only repair now uses the shared journal
  projection, validates one committed logical journal, installs the terminal pair with
  `journal: null`, appends history, and persists once. Signed status tests remain unchanged; other
  record-only operations retain their existing in-memory compatibility-shadow path.
