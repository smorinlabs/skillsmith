## Implementation and validation

- Core check mode now executes only checks that both declare `runsIn: check` and have error-class
  severity; doctor retains the complete diagnostic registry and actual findings still determine
  report counts.
- `check` now gates error findings by default, keeps `--exit-code` as redundant 1.x compatibility,
  and supports `--report-only` without changing the executed checks or payload. Incompatible modes,
  all-tools/tool selection, and lockfile-without-file fail as usage errors before environment access.
- Effective config supplies default tool/scope selection behind explicit CLI choices. The shared
  artifact-pair resolver resolves an explicit desired-state path from effective cwd, derives its
  sibling `.lock`, or accepts an explicit lock only with a file. It performs no I/O and introduces
  no manifest/lock schemas or Phase-2 ownership.
- Check and doctor receive the same optional read-only artifact pair. The config-parse diagnostic
  consumes the selected file so malformed selected configuration remains a reported finding at the
  check gate instead of being silently replaced or expanding into future repair behavior.
- The current Commander state ledger records the new check options and the forward-compatible doctor
  path-selection options with explicit P17 ownership/history.
