## Ready plan

- **Accepted plan:** [P17-G3B-06.md](../plans/P17-G3B-06.md), SHA-256
  `3e58c96078d3d6f323eb58e1146f7384be554c8647d8affd0d3d5affcdf37de2`.
- **Exact scope:** two primary entities, one required-now/impacted selector, no downstream
  coverage, and exactly 21 owned product/test paths: 19 architecture/production paths and two
  selector paths. Governance files remain outside the product manifest.
- **Identity hierarchy:** command contexts retain the CLI invocation operation ID and no parent;
  actually started planned operations use their deterministic plan operation ID with the command
  ID as parent and the plan group/pair IDs; transactions and recovery use the transaction ID with
  the journal intent operation ID as parent and the journal group/pair IDs. The private plan ID is
  `plan:v1:<sha256(canonicalPlanningString(operationPlan))>` and is not persisted or added to a
  public plan, report, or wire shape.
- **Propagation boundary:** the existing `ObservationBundle` remains authoritative. One private
  execution observation module supplies scalar context derivation and best-effort emission;
  private source-module-only `*Observed` seams carry it through application, scheduler,
  acquisition, placement, transaction, and recovery edges. Public package-root options, reports,
  exports, planners, repositories, codecs, state authorities, adapters, and CLI surfaces remain
  unchanged and observation-free.
- **Journal and recovery boundary:** new journals unconditionally project the intent operation ID
  into `context.parentOperationId`, independent of observer presence. Pending recovery increments
  attempt through one narrow pure reducer that updates the logical journal and matching physical
  shadow while preserving the original start time. Observer and no-observer execution produce
  identical corrected journal bytes; legacy null-parent journals remain valid and reconstruct
  event parentage with `parentOperationId ?? intent.operationId` without rewriting committed
  history solely for correlation.
- **Single ownership and durable stages:** CLI owns command events; application/read edges own
  `plan.created`; the scheduler owns events only for actually started operations; existing
  acquisition/verification seams own tool events; swap and ledger durable-transition authorities
  own transaction stages; and per-transaction recovery wrappers own resume, rollback, cleanup, and
  recovery spans. A stage completion acknowledges its durable write-ahead marker, so later physical
  rename failure does not emit a second completion for the same stage. Ledger migration emits live
  only at the authoritative durable handoff and never duplicates an already-proven cursor.
- **Selector contract:** the exact future command is
  `bun test tests/ergonomics/phase/EWP-P3B-TS07.test.ts --test-name-pattern EWP-P3B-TS07`.
  Ten executable families cover static ownership, deterministic plan identity, three-level context,

  compatibility/no-growth. TS11 narrows to the literal owned import/event boundary while preserving
  all decision-use bans.
