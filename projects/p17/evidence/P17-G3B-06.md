- **Accepted identity model:** retain the CLI-created root context as command identity. For each
  actually started planned operation, derive one internal child context whose `operationId` is the
  deterministic planned operation ID, whose parent is the root operation ID, and whose group/pair
  values match the plan. Recovery reconstructs the same operation identity and increments the
  attempt. Unstarted cancelled or skipped operations receive no fabricated start event.
- **Accepted event ownership:** the application/runner edge emits `plan.created` only after pure
  planning succeeds; the scheduler owns `operation.started/completed`; existing detection and
  verification wrappers own tool events; the physical durable journal-transition authority owns
  transaction stages and commit/rollback; and recovery wrappers own resume, rollback, cleanup, and
  recovery spans. A lifecycle fact has one emitter and is not duplicated across layers.
- **Journal boundary:** project only existing scalar context into journal-v1. Journal intent keeps
  operation/group/pair identity and the existing transaction ID; journal context keeps parent,
  command, workflow, attempt, and durable start time. Events and observer objects are never
  persisted, and no schema/version change is accepted. Ready must reconcile the signed pending-abort
  parent-ID rewrite with forward/resume correlation explicitly.
- **Purity and result authority:** planners, reducers, repositories, codecs, and state readers stay
  observation-free. Event emission is best-effort, cannot be awaited as authority, and cannot feed
  branches, results, exit codes, journal bytes, state, rollback, or recovery. Structured results and
  durable journals remain the only semantic authorities.
- **Consolidation boundary:** use the existing `ObservationBundle` and one focused private
  planned-operation context helper. Add optional internal propagation at application,
  coordinator/scheduler, execution, swap, and recovery seams. Do not add global context,
  AsyncLocalStorage, middleware/decorators, an event bus, telemetry SDK, observer queue, lifecycle
  framework, metadata bag, or public/wire context fields.
