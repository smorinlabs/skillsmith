# SkillSmith MVP-1 design — "What's on my machine?"

**Status:** Approved 2026-04-24
**Scope:** Greenfield project scaffold + first feature slice
**Release framing:** Internal milestone (tag `0.1.0`, no public release). First public release is bundled with MVP-2b per the phase analysis below.
**Architecture framing:** Bun workspace with a library (`@skillsmith/core`) and a thin CLI (`skillsmith`) that consumes it. Per-agent concerns co-located in `packages/core/src/agents/<tool>/`.

## 1. Background

SkillSmith's phasing is documented in `research/skillsmith-phases.md`. MVP-1 is the smallest useful release: inventory of detected agent tools. Its primary value is **infrastructure**, not user-facing features — it scaffolds the workspace, the library's public API surface, the CLI framework, and the per-agent modules that `doctor`, `install`, and `check` reuse in later phases.

SkillSmith ships as two packages from one workspace:

- **`@skillsmith/core`** — library. Pure TypeScript, no CLI framework, no `process.exit`, no `chalk`, no terminal assumptions. Callable from any Bun/Node host. Exposes a stable, zod-validated, Result-returning public API.
- **`skillsmith`** — CLI binary. Thin shell: parses args, calls the library, renders output. Owns `commander`, `chalk`, `consola`, exit-code translation, TTY/color detection, and help text.

This spec covers MVP-1 only. The broader CLI surface is in `research/skillsmith-cli-design.md`; per-command detail is in `research/commands/`.

## 2. Phase analysis (why MVP-1 as-specified)

Alternatives considered:

- **Option A (chosen):** Keep the current MVP-1 scope, but tag it as an internal `0.1.0` milestone. First public release bundles MVP-1 + MVP-2a + MVP-2b so users see a coherent read-only inspection suite (`agents` + `list` + `doctor` + `config` + `completion`), not a CLI that only lists detected tools.
- **Option B:** Merge MVP-1 + 2a + 2b into one "Inspection" release. Rejected: 2–3× the work before any ship, and loses the MVP-1 checkpoint where per-agent modules stabilize in isolation before `doctor` depends on them.
- **Option C:** Invert phasing and ship `install` in MVP-1. Rejected: collapses the staged-risk discipline of the current plan (config, scope resolution, store, symlinks, adapters all landing at once) with no `doctor` for diagnosis when install misbehaves.

Recommendation locked: **Option A**. No changes to downstream phases.

## 3. Scope

### 3.1 User-facing CLI commands

- `skillsmith agents [--tool <name>]... [--detected-only] [--format markdown|json]` — inventory across supported tools; always exits 0.
- `skillsmith version` | `skillsmith --version` | `skillsmith -V` — prints the SkillSmith version.
- `skillsmith help` | `skillsmith --help` | `skillsmith -h` | `skillsmith <cmd> --help` | `skillsmith help <cmd>` | `skillsmith help <topic>` — help routing. Topic pages (`exit-codes`, `environment`, `scopes`, `manifest`, `sources`, `formatting`) ship with short stub content; the routing is fully wired so later phases fill in prose without changing the command surface.

### 3.2 Library public API (`@skillsmith/core` v0.1.0)

```ts
// packages/core/src/index.ts
export type {
  SupportedTool,        // "claude-code" | "codex" | "kilo-code" | "opencode"
  InstallRecord,        // { path, version, installMethod }
  InstallMethod,        // "brew" | "npm-global" | "native-installer" | "app-bundle" | "unknown"
  Agent,                // per-tool interface (MVP-1 subset)
  ScanEnv,              // injectable IO surface
  Logger,               // injectable logger
  Result,               // { ok: true, value } | { ok: false, error }
  SkillSmithError,      // tagged error union with .code
  DetectOptions,        // { tools?, logger?, signal? }
} from "./public-types.js";

export { defaultScanEnv } from "./env/default.js";
export { registry, listSupportedTools } from "./agents/registry.js";
export { detectAll, detectTool } from "./detect/detect.js";
export { VERSION } from "./version.js";
```

Library invariants (enforced by code review, biome rules, and tests):

- No `process.exit`, no `console.*`, no `chalk`, no `commander` anywhere under `packages/core/src/`.
- All public functions take an optional injected `Logger` and `AbortSignal`.
- All public functions return `Result<T, SkillSmithError>` — no throwing on expected failure modes.
- All public functions zod-validate their inputs at runtime for non-TS callers.
- Everything not re-exported from `packages/core/src/index.ts` is internal and not listed in `package.json#exports`.

### 3.3 Per-agent module shape

Each agent is one folder under `packages/core/src/agents/<tool>/` exporting an `Agent` that grows across phases. MVP-1 shape:

```ts
interface Agent {
  readonly tool: SupportedTool;
  detect(env: ScanEnv): Promise<Result<InstallRecord[], SkillSmithError>>;
  readonly installHint: string;   // canonical "install this tool" one-liner
}
```

Later phases add (not implemented in MVP-1, directory stubs land so the shape is visible):

- `resolveInstallPath(scope, env)` → scope → on-disk path mapping (MVP-2c)
- `parseFrontmatter(skill)` → expected SKILL.md schema (MVP-2c)
- `adaptFrom/<source>` → cross-tool transformers (MVP-5)

### 3.4 Global flags wired in MVP-1

Per `research/skillsmith-cli-design.md` §3.1. Wired now because they are inherited:

- `--help` / `-h`
- `--version` / `-V`
- `--verbose` / `-v` (count, stackable)
- `--quiet` / `-q`
- `--no-color`, `--color <auto|always|never>` (honor `NO_COLOR`, `FORCE_COLOR`, `CLICOLOR_FORCE`, `TERM=dumb`)
- `--cd <dir>` / `-C`
- `--debug`

Not wired in MVP-1 (land with their first consumer):

- `--json` (boolean) — `agents` uses `--format` per its spec; the global `--json` flag lands in MVP-2b with `list`/`doctor`.
- `--config`, `--no-prompt` — MVP-2a.

### 3.5 Exit codes wired in MVP-1

CLI translates `SkillSmithError.code` from the library into exit codes:

- `0` — success (including inventory of an empty system).
- `1` — generic failure (`error.code === "generic"`).
- `2` — usage error: unknown subcommand, unknown `--format`/`--tool` value (commander-originated; the library does not produce this).
- `130` — SIGINT.

Codes `3`/`4`/`5`/`6`/`7` are reserved for later phases and are not emitted in MVP-1.

### 3.6 Explicit deferrals

- No TOML config read/write (→ MVP-2a).
- No shell completion script generation (→ MVP-2a).
- No interactive prompts, no `@clack/prompts` (→ MVP-2c).
- No store, no symlinks, no adapters, no `install`/`uninstall`/`list`/`doctor`/`sync`/`apply` (→ MVP-2b and beyond).
- No `Operation[]` log yet (nothing writes in MVP-1); the Result/DI/per-agent patterns prepare for it.
- No codesign / notarize pipeline (→ first public release at MVP-2b).
- No Homebrew cask, no npm publish (→ first public release).

## 4. Architecture

### 4.1 Runtime stack

Per `research/skillsmith-v1-stack-summary.md`: Bun ≥ 1.3.13 end-to-end (runtime, workspace install, test runner, build).

Library runtime deps (in `packages/core/package.json`):

- `zod` — input validation at public API boundary.

That is the entire library runtime dep surface for MVP-1. `commander`, `chalk`, `consola` are CLI-only concerns.

CLI runtime deps (in `packages/cli/package.json`):

- `commander` — CLI framework.
- `chalk` — terminal styling (respects color env rules).
- `consola` — stderr progress / structured log adapter.
- `@skillsmith/core` via `workspace:*`.

Deferred deps (land when needed): `@clack/prompts`, `smol-toml`, `gray-matter`, `proper-lockfile`, `env-paths`.

Dev deps (root `package.json`): `@types/bun`, `@types/node`, `@biomejs/biome`, `typescript`, `lefthook`.

### 4.3 Core type contracts

```ts
type SupportedTool = "claude-code" | "codex" | "kilo-code" | "opencode";
type InstallMethod = "brew" | "npm-global" | "native-installer" | "app-bundle" | "unknown";

interface InstallRecord {
  path: string;          // resolved absolute real-path
  version: string;       // "unknown" if version flag fails/times out
  installMethod: InstallMethod;
}

interface Logger {
  info(msg: string, meta?: Record<string, unknown>): void;
  warn(msg: string, meta?: Record<string, unknown>): void;
  debug(msg: string, meta?: Record<string, unknown>): void;
}

interface ScanEnv {
  homeDir: string;
  path: string[];                    // $PATH split
  platform: "darwin" | "linux" | "win32";
  xdg: { config: string; data: string; cache: string };
  fileExists(p: string): Promise<boolean>;
  realpath(p: string): Promise<string>;
  runVersion(binaryPath: string, args: string[], signal?: AbortSignal): Promise<string | "unknown">;
}

type Result<T, E> = { ok: true; value: T } | { ok: false; error: E };

type SkillSmithError =
  | { code: "generic"; message: string; cause?: unknown }
  | { code: "unknown-tool"; tool: string };
// more variants added in later phases (config-error, source-unresolvable, etc.)

interface DetectOptions {
  tools?: readonly SupportedTool[];  // default: all registered
  logger?: Logger;
  signal?: AbortSignal;
}
```

### 4.4 Detection behavior

Detection runs all four agents in parallel. Within an agent, scanner location attempts also run in parallel. De-dup is by resolved real-path: after gathering candidates, each path is `realpath`'d and duplicates collapsed before version probes run.

Version probes use `Bun.spawn` with an `AbortController` armed by a 2000ms timer. On timeout or non-zero exit, the record's `version` is `"unknown"` and the record is still returned.

### 4.5 `agents` command behavior

- No arguments: scan all four supported tools.
- `--tool <name>` repeatable: narrow to listed tools. Unknown value → commander exits 2 with a did-you-mean hint.
- `--detected-only`: omit the "Not detected" section.
- `--format <markdown|json>`: default `markdown`. Unknown value → commander exits 2.
- Output goes to stdout. Warnings (e.g., scanner IO errors, version probe failures at `-v`) go to stderr.
- Always exits 0 on successful scan, including "nothing detected".

Implementation flow: CLI handler parses flags → calls `core.detectAll({ tools, logger, signal })` → receives `Result<Map<SupportedTool, InstallRecord[]>, SkillSmithError>` → renders via `agents-markdown.ts` or `agents-json.ts`.

Markdown output per `research/commands/agents.md` §Output. JSON output is a single top-level object with a schema that is validated in tests; schema marked experimental in the first public release.

### 4.6 Help routing

- `skillsmith` with no args → prints top-level help (no default action, exit 0).
- `--help` / `-h` on any command or root → prints that command's help.
- `help` subcommand with no args → top-level help.
- `help <cmd>` → per-command help.
- `help <topic>` where topic is in the allowlist → prints topic page.
- `help <unknown>` → exit 2 with a did-you-mean list.
- Topic allowlist: `exit-codes`, `environment`, `scopes`, `manifest`, `sources`, `formatting`. Each topic has a short MVP-1 stub that describes scope and points at the research docs; prose is fleshed out in later phases.

### 4.7 Color resolution

Precedence (high to low): `--no-color` → `--color=never` → `NO_COLOR` (any non-empty) → `CLICOLOR=0` → `TERM=dumb` disables color; `--color=always` / `FORCE_COLOR` / `CLICOLOR_FORCE` force color on; otherwise `--color=auto` uses TTY detection on stdout. `SKILLSMITH_COLOR` and `SKILLSMITH_NO_COLOR` land in MVP-2a with the config layer; MVP-1 honors the cross-tool standards only.

### 4.8 Signal handling

CLI installs a SIGINT handler in `src/util/signals.ts` that aborts the in-flight `AbortController` passed to the library, awaits pending cleanup, and exits 130. Library never installs signal handlers.

## 5. Dev toolchain

Shared at the workspace root. Each package inherits.

### 5.1 Biome (lint + format)

- `biome.json` at repo root, applies to both packages.
- Format: 2-space indent, single quotes, trailing commas `all`, line width 100, semicolons `always`.
- Lint: `recommended` enabled; `suspicious`, `style`, `correctness`, `complexity`, `security` at default severity. Import organization on.
- Custom rule via Biome's `noRestrictedImports` (or a small lint script in CI): `packages/core/src/**` cannot import from `commander`, `chalk`, `consola`, or call `process.exit` / `console.*`.
- Ignore: `dist/`, `node_modules/`.

### 5.2 TypeScript

- `tsconfig.base.json` at root: `strict: true`, `noUncheckedIndexedAccess: true`, `exactOptionalPropertyTypes: true`, `noImplicitOverride: true`, `noFallthroughCasesInSwitch: true`, `moduleResolution: "bundler"`, `module: "ESNext"`, `target: "ESNext"`, `types: ["bun"]`, `composite: true`.
- `packages/core/tsconfig.json` and `packages/cli/tsconfig.json` extend base. CLI's tsconfig has a `references` entry to core for build-order correctness.
- No emit; `tsc -b` (build mode) is the check.

### 5.3 lefthook

`lefthook.yml` at repo root. Skip-on-merge and partial-file-aware.

- `pre-commit`:
  - `biome check --staged --no-errors-on-unmatched` (must pass).
  - `tsc -b` on the whole workspace.
  - `actionlint` when any `.github/workflows/**` file is staged.
- `pre-push`:
  - `bun test` across the workspace.
- `commit-msg`:
  - Conventional Commits regex (`feat|fix|docs|style|refactor|perf|test|build|ci|chore|revert`).

Install: `bunx lefthook install` runs via the root `package.json` `postinstall` script.

### 5.4 actionlint

- Pinned version binary cached in CI; locally available via `brew install actionlint` or `bunx actionlint-github-download`.
- Lefthook runs it on staged workflow files; CI runs it on every push regardless.

### 5.5 GitHub Actions CI

`.github/workflows/ci.yml`. Triggers: `pull_request` and `push` on `main`.

Matrix:

- `os`: `macos-latest`, `ubuntu-latest`.
- `bun`: `1.3.13` (pinned).

Steps (same on both OSes):

1. `oven-sh/setup-bun@v2` with pinned version.
2. `bun install --frozen-lockfile` (installs the full workspace).

## 6. Testing strategy

### 6.1 Library (`@skillsmith/core`)

- **Per-agent detection:** unit tests with a fake `ScanEnv` — `fileExists`/`realpath`/`runVersion` stubbed. Cover: single install, multiple installs, symlink collapse, version probe failure → `unknown`, version probe timeout → `unknown`, scanner IO error non-fatal.
- **Orchestrators (`detectAll`/`detectTool`):** test parallelism, filtering via `tools` option, AbortSignal cancellation, logger invocation.
- **Public API shape:** an `exports.test.ts` imports from `@skillsmith/core` (not a relative path) and asserts the exported symbols match an allow-list — catches accidental public-API growth.
- **Result helpers:** unit tests for `ok`, `err`, map, flatMap.

### 6.2 CLI (`skillsmith`)

- **`agents` command:** snapshot test for markdown across representative scenarios (all four detected, none detected, `--detected-only`, `--tool` filter). JSON output validated against a zod schema in tests.
- **Help routing:** table-driven test across the 7 invocation forms.
- **Color resolution:** table-driven test across flag × env combinations.
- **Exit-code mapping:** table-driven test covering each `SkillSmithError.code` variant.
- **Binary integration:** CI builds the compiled binary, runs `./dist/skillsmith agents --format json`, and asserts exit 0 + valid JSON on stdout.

Coverage target is not gated in MVP-1; add gate in MVP-2b when `doctor` adds behavior tests that warrant it.

## 7. Success criteria

1. Fresh clone → `bun install && bun run build` produces a working binary on macOS and Ubuntu.
2. `./skillsmith agents` runs end-to-end, emitting valid markdown and schema-valid JSON on both OSes.
3. `bun run check` is green (lint + typecheck + actionlint + tests).
4. `bun run build` smoke-builds on both CI OSes and the smoke invocation of the binary succeeds.
5. Committing with a non-Conventional message is blocked locally by lefthook's `commit-msg` hook.
6. Library tests and CLI tests run and pass independently via `bun test packages/core` and `bun test packages/cli`.
7. A consumer test inside the repo imports from `@skillsmith/core` (via the workspace symlink) and calls `detectAll(await defaultScanEnv())` successfully — proving the library is usable without the CLI.
8. `skillsmith help <topic>` returns non-empty content for each of the six allowlisted topics.
9. A lint/CI check fails if `packages/core/src/**` imports `commander`, `chalk`, `consola`, or calls `process.exit`.
