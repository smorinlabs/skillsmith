# SkillSmith MVP-2b.1 design — "List, doctor, check (read path)"

**Status:** Approved 2026-04-24
**Scope:** Three read-only observability commands + global `--json` flag + skill-scanning foundation.
**Release framing:** Internal milestone (`v0.3.0`, no public release). First public release is MVP-2b.2 (separate brainstorm).
**Prerequisites:** `v0.2.0` (MVP-2a) tagged; config + completion + per-agent modules live.

## 1. Background

MVP-2b was originally scoped as a single milestone covering all of `list`, `doctor`, `check`, public release, PowerShell completion, and Windows CI. That scope is ~3× MVP-2a and breaks naturally along a dev-surface / release-engineering seam. This spec is the dev-surface half.

**Split decision:**

- **MVP-2b.1 (this spec)** — `list` + `doctor` + `check` + global `--json` → tag `v0.3.0` internal.
- **MVP-2b.2** — public release (npm publish of `@skillsmith/core` and `skillsmith` binary, Homebrew formula, codesign + notarize, release notes) → tag `v1.0.0` public. Separate brainstorm.
- **MVP-2c (expanded)** — previously `install`/`uninstall` alone; now also absorbs **PowerShell completion** and **Windows CI matrix** that were scheduled for MVP-2b. Cross-scope writability checks exercise Windows paths enough to warrant doing them together.

`research/skillsmith-phases.md` will be updated alongside this spec to reflect the split and the PowerShell/Windows push-out.

## 2. Scope

### 2.1 User-facing CLI commands

- `skillsmith list [<glob>...] [--tool <name>]... [--scope <s>] [--user] [--system] [--project] [--duplicates] [--long] [--json]` (alias `ls`)
- `skillsmith doctor [--tool <name>]... [--scope <s>] [--user] [--system] [--project] [--offline] [--strict] [--json]`
- `skillsmith check [--tool <name>]... [--scope <s>] [--user] [--system] [--project] [--exit-code] [--json]`

### 2.2 Global flag additions

- `--json` — new boolean global flag. Commands that support it (`list`, `doctor`, `check`) read `opts.json`. `agents` continues to use `--format markdown|json` (markdown is an agents-specific content choice, not a toggle).

The declaration-gate test from MVP-2a is extended to assert every new subcommand explicitly opts into or out of `--json`.

### 2.3 Exit codes

Finalized for read commands:

- `0` — all checks pass (for `doctor`/`check`); read succeeded (for `list`, regardless of empty result).
- `1` — generic failure *or* `doctor --strict` with any warning *or* `doctor`/`check` with any error finding *or* `check --exit-code` with any error finding.
- `2` — usage error (unknown flag value, conflicting scope shorthands).
- `3` — config error (re-used from MVP-2a).
- `130` — SIGINT.

No new codes minted.

### 2.4 Scope shorthand flags (`--user`, `--system`, `--project`)

All three commands accept both forms:

- `--scope=<enum>` canonical.
- `--user`, `--system`, `--project` as booleans that resolve to the equivalent `--scope` value.

**Conflict handling:** if two shorthand flags are passed (e.g. `--user --system`), exit 2 with a usage error. If `--scope` and a shorthand are both passed and agree, OK; if they disagree, exit 2. Commander's option-parsing order doesn't give us "last wins" naturally here, so we validate explicitly in the action handler.

### 2.5 Doctor check set (MVP-2b.1)

Built-in checks that run in `v0.3.0`:

| Check | Severity | doctor | check | Depends on |
|---|---|---|---|---|
| XDG paths resolvable | error | ✓ | ✓ | `ScanEnv.xdg` |
| `skillsmith.toml` parses (if found) | error | ✓ | ✓ | MVP-2a `loadConfig` |
| Tool detected on PATH | warning | ✓ | ✗ | MVP-1 `detectAll` |
| Skills directory writable | error | ✓ | ✓ | new `getSkillRoots` |
| Cross-scope duplicate skill | warning | ✓ | ✗ | new `listSkills` |
| Multiple installs of the same tool | warning | ✓ | ✗ | MVP-1 `detectAll` + filter |
| Legacy install method in use | warning | ✓ | ✗ | per-agent predicate (Codex deprecated path, etc.) |
| Network reach: `github.com` HTTPS | warning | ✓ | ✗ | native `fetch`; skipped by `--offline` |

Explicitly deferred to MVP-2c:

- "Manifest matches lockfile" — needs a lockfile; no `apply` yet.
- "No orphaned files in skills dir" — needs the SkillSmith-managed store.

### 2.6 Explicit deferrals

- PowerShell completion → MVP-2c.
- Windows in CI matrix → MVP-2c.
- Public release (npm publish, Homebrew formula, codesign + notarize) → MVP-2b.2.
- Plugin-contributed healthchecks (the `healthchecks` manifest field + TSV runner from `commands/doctor.md`) → P2. We reserve the manifest key but don't implement the runner.
- `--fix` command → not in scope; built-in checks ship remediation strings instead.

## 3. Library additions (`@skillsmith/core` → v0.3.0)

### 3.1 New public API

```ts
// skills/
export interface Frontmatter {
  name?: string;
  description?: string;
  version?: string;
}

export interface SkillEntry {
  name: string;          // directory basename
  path: string;          // absolute path to skill directory
  realpath: string;      // resolved (symlinks collapsed)
  tool: SupportedTool;
  scope: Scope;
  root: string;          // which scan root this was found under
  frontmatter: Frontmatter | null;  // null if SKILL.md missing or malformed
  // MVP-2c will add: source?, storePath?, installMethod, commitSha?
}

export interface ListSkillsOpts {
  tools?: readonly SupportedTool[];
  scopes?: readonly Scope[];
  globs?: readonly string[];
  duplicatesOnly?: boolean;
  signal?: AbortSignal;
  logger?: Logger;
}

export const listSkills: (
  env: ScanEnv,
  opts?: ListSkillsOpts,
) => Promise<Result<SkillEntry[], SkillSmithError>>;

export const parseSkillFrontmatter: (text: string) => Result<Frontmatter, SkillSmithError>;

// doctor/
export type Severity = 'error' | 'warning' | 'info';
export type CheckRunMode = 'doctor' | 'check';

export interface Finding {
  checkId: string;
  severity: Severity;
  title: string;
  message: string;
  remediation?: string;
  tool?: SupportedTool;   // set when the finding is per-tool
  scope?: Scope;
}

export interface CheckRunContext {
  env: ScanEnv;
  mode: CheckRunMode;
  tools: readonly SupportedTool[];
  scopes: readonly Scope[];
  offline: boolean;
  logger: Logger;
  signal?: AbortSignal;
}

export interface Check {
  readonly id: string;
  readonly severity: Severity;
  readonly runsIn: readonly CheckRunMode[];
  run(ctx: CheckRunContext): Promise<Finding[]>;
}

export interface CheckRunResult {
  findings: Finding[];
  counts: { ok: number; warning: number; error: number };
}

export const runChecks: (
  registry: readonly Check[],
  ctx: CheckRunContext,
) => Promise<Result<CheckRunResult, SkillSmithError>>;

export const builtInChecks: readonly Check[];
```

### 3.2 New `SkillSmithError` variants

```ts
| { code: 'skill-parse-error'; message: string; file: string }
```

Used for malformed SKILL.md YAML. `list` returns the skill with `frontmatter: null`; `doctor` reports it as an error finding. Exit-code mapping: `skill-parse-error` → `1` (generic failure; surfaces via `doctor` check, not a fatal library error).

### 3.3 Agent interface extension

Every agent module grows a new method:

```ts
interface Agent {
  // existing: tool, installHint, detect(env, signal?)
  readonly tool: SupportedTool;
  readonly installHint: string;
  detect(env: ScanEnv, signal?: AbortSignal): Promise<Result<InstallRecord[], SkillSmithError>>;

  // NEW in MVP-2b.1
  getSkillRoots(env: ScanEnv, scope: Scope): readonly string[];
}
```

`getSkillRoots` returns zero, one, or more absolute paths for a given scope. Examples:

- `claude-code`, scope `user` → `['~/.claude/skills']` (honoring `CLAUDE_CONFIG_DIR`).
- `codex`, scope `user` → `['~/.agents/skills', '$CODEX_HOME/skills' or '~/.codex/skills']` (both are read per research).
- `opencode`, scope `user` → `['~/.config/opencode/skills', '~/.claude/skills', '~/.agents/skills']`.
- `kilo-code`, scope `project` → `[<cwd>/.kilo/skills', '<cwd>/.claude/skills', '<cwd>/.agents/skills']` unless `KILO_DISABLE_EXTERNAL_SKILLS` is set.

The function is pure (no filesystem IO) — just path computation from env/config. IO happens in the walker.

### 3.4 `ScanEnv` addition

One new method for filesystem enumeration:

```ts
interface ScanEnv {
  // existing fileExists, realpath, runVersion, etc.
  listDir(path: string): Promise<string[]>;   // NEW — entries without '.' / '..'
}
```

Tests inject fake directory listings. Default implementation wraps `fs.readdir`.

### 3.5 New runtime deps

- `gray-matter` — SKILL.md YAML frontmatter parser. Already in the committed 9-dep stack summary; lands here.

### 4.1 `walkSkillDir` behavior

Given a root and `(tool, scope)`:

1. If root does not exist (via `fileExists`) → return `[]`.
2. `listDir(root)` → entries.
3. For each entry that is a directory: check for `SKILL.md` inside.
4. If present, read the file, pass to `parseSkillFrontmatter`. If parse succeeds → `SkillEntry` with `frontmatter` populated. If parse fails → `SkillEntry` with `frontmatter: null` AND log a `skill-parse-error` warning (the orchestrator collects these for doctor to report).
5. Realpath each skill dir; include the resolved path in the entry.
6. Skip entries that don't have a `SKILL.md` at the root of the skill dir. (Nested auto-discovery per Claude Code is out of scope for MVP-2b — same-level scanning only.)

Bounded recursion: `walkSkillDir` does NOT recurse into subdirectories of each skill dir (MVP behavior; plugin-nested auto-discovery is Phase 2).

### 4.2 `listSkills` orchestrator

```ts
const effectiveTools = opts.tools ?? listSupportedTools();
const effectiveScopes = opts.scopes ?? SCOPES;

const all: SkillEntry[] = [];
for (const tool of effectiveTools) {
  for (const scope of effectiveScopes) {
    const roots = registry[tool].getSkillRoots(env, scope);
    for (const root of roots) {
      const entries = await walkSkillDir(env, { tool, scope, root });
      all.push(...entries);
    }
  }
}

// de-dup by realpath (symlink collapse)
const deduped = dedupeByRealpath(all);

// glob filter (Bun.Glob)
const globbed = opts.globs?.length ? applyGlobs(deduped, opts.globs) : deduped;

// duplicates-only filter
const result = opts.duplicatesOnly ? filterCrossScopeDuplicates(globbed) : globbed;
```

Runs sequentially for MVP-2b.1 (scan volume is low, parallelism not worth the complexity here).

### 4.3 Check registry + runner (mode-parameterized)

```ts
// registry.ts — the authoritative list
export const builtInChecks: readonly Check[] = [
  xdgPaths,
  configParse,
  toolDetected,
  scopeWritable,
  crossScopeDuplicate,
  multiInstall,
  legacyInstall,
  networkReach,
];
```

```ts
// run.ts
export const runChecks = async (
  registry: readonly Check[],
  ctx: CheckRunContext,
): Promise<Result<CheckRunResult, SkillSmithError>> => {
  const applicable = registry.filter((c) => c.runsIn.includes(ctx.mode));
  const findings: Finding[] = [];
  for (const check of applicable) {
    if (ctx.signal?.aborted) return err(genericError('aborted'));
    try {
      findings.push(...(await check.run(ctx)));
    } catch (e) {
      findings.push({
        checkId: check.id,
        severity: 'error',
        title: `check '${check.id}' threw`,
        message: errorMessage(e),
      });
    }
  }
  return ok({ findings, counts: tallyBySeverity(findings) });
};
```

Per-check `run(ctx)` may short-circuit based on `ctx.offline`, `ctx.tools`, `ctx.scopes`. Each check is independently unit-testable.

## 5. CLI architecture

```
packages/cli/src/
  commands/
    list.ts               # runList + commander wiring
    doctor.ts             # runDoctor + commander wiring
    check.ts              # runCheck + commander wiring
  output/
    list-human.ts         # human-readable table / tree
    list-json.ts          # JSON renderer + zod schema (schemaVersion:1, experimental)
    doctor-human.ts       # grouped-by-tool per commands/doctor.md mockup
    doctor-json.ts        # structured findings
  util/
    scope-resolver.ts     # resolveScope(opts): Scope | readonly Scope[]
                          #   - validates shorthand conflicts → exit 2
```

### 5.1 Commander wiring

```ts
// global flag added in buildProgram
program.option('--json', 'Emit JSON on stdout', false);

// in each command:
program.addCommand(listCommand());
program.addCommand(doctorCommand());
program.addCommand(checkCommand());
```

Each command:

- Reads `--json` from `this.parent.opts().json || this.opts().json` (commander inherited flag).
- Reads shorthand scope flags and resolves via `scope-resolver.ts`.
- Calls the corresponding core function, maps Result to exit code via `exitCodeForError`.

### 5.2 Output contract

- **stdout**: data (JSON or human rendering).
- **stderr**: progress, spinner output, warnings.
- When `--json`, stdout is a single JSON value; stderr gets at most a one-line summary. TTY detection unchanged from MVP-2a.

### 5.3 ESLint zones (additions)

- `packages/core/src/skills/**` must not import from `agents/**` — the walker is agent-agnostic. `skills/` can import from `env/`, `errors`, `result`.
- `packages/core/src/doctor/**` may import from `scan/`, `skills/`, `agents/registry`, `env/`, `config/`, `errors`, `result` — doctor is the cross-cutting consumer.
- `packages/cli/src/commands/list.ts`, `doctor.ts`, `check.ts` may import from `@skillsmith/core` and sibling `output/`.

## 6. Data flow

### 6.1 `list`

1. CLI parses flags → `runList({ env, tools?, scopes?, globs, duplicatesOnly, long, json })`.
2. `core.listSkills(env, { tools, scopes, globs, duplicatesOnly })`.
3. Result renders via `list-human` (default) or `list-json`.
4. Exit 0 — always; empty result is a valid state.

### 6.2 `doctor`

1. CLI parses flags → builds `CheckRunContext { env, mode: 'doctor', tools, scopes, offline, ... }`.
2. `core.runChecks(builtInChecks, ctx)`.
3. Renders human or JSON.
4. Exit 1 if any `error` finding, or any `warning` under `--strict`; else 0.

### 6.3 `check`

1. Same as doctor, but `mode: 'check'` filters the registry to error-severity applicable checks.
2. Exit 1 if any error finding AND `--exit-code` was passed; otherwise 0 (reporting-only by default).

### 6.4 SIGINT propagation

Every command threads `controller.signal` through to `listSkills` / `runChecks`. `runChecks` checks `signal.aborted` between checks. Same pattern as MVP-1 detection.

## 7. Testing strategy

### 7.1 Library

- **`parseSkillFrontmatter`:** table-driven — valid, missing fields, malformed YAML, empty file, binary content.
- **`walkSkillDir`:** fake `ScanEnv` with injected `listDir`/`fileExists`/`readFile`. Fixtures for: empty root, single skill, skill missing SKILL.md, skill with malformed YAML (returned with `frontmatter: null`), symlink to external dir (resolved via realpath), cross-scope name collision (handled by orchestrator, not walker).
- **Per-agent `getSkillRoots`:** input→output table tests. One test per `(tool × scope)` including env-var overrides (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `OPENCODE_CONFIG_DIR`, `KILO_DISABLE_EXTERNAL_SKILLS`).
- **`listSkills` orchestrator:** integration with fakes; assert `(tool, scope)` tuples appear correctly, dedup by realpath works, glob filter narrows the result, `duplicatesOnly` surfaces only cross-scope name collisions.
- **Each built-in check:** unit tested in isolation with a mocked `CheckRunContext`.
- **`runChecks`:** mode filtering; check-throws → error finding; signal abort → early return.

### 7.2 CLI

- **Snapshot tests** for list human output and doctor human output across representative scenarios.
- **Integration tests** spawn the binary:
  - `list` on empty system → exit 0, "No skills installed" (human) or `[]` (json).
  - `list --json` returns schema-valid JSON.
  - `doctor` on healthy system → exit 0, no `⚠` or `✗`.
  - `doctor` with fake broken env → exit 1.
  - `doctor --strict` warnings → exit 1.
  - `check --exit-code` no errors → exit 0.
  - `check --exit-code` with error → exit 1.
  - `list --user --system` → exit 2.

### 7.3 Coverage gate

Introduce a coverage gate for the first time at MVP-2b.1: `doctor` is observability-critical, so test coverage matters here more than in MVP-1/2a scaffolding. Target `>= 85%` line coverage on `packages/core/src/doctor/**` and `packages/core/src/skills/**`. `bun test --coverage` wired into `bun run check`.

## 8. Success criteria

1. `bun run check` — all green (lint + boundaries + typecheck + actions-lint + tests + coverage gate).
2. `./skillsmith list` on a fresh checkout prints "No skills installed" (human) or `[]` (json), exit 0.
3. `./skillsmith list --json` emits a top-level array of `SkillEntry` conforming to a zod schema validated in tests.
4. `./skillsmith doctor` runs all 8 built-in checks, produces human-readable grouped output per the `commands/doctor.md` mockup.
5. `./skillsmith doctor --offline` skips the network-reach check.
6. `./skillsmith doctor --strict` flips warnings to failures (exit 1).
7. `./skillsmith check --exit-code` exits 0 on a clean system; non-zero when an error-severity check finds a problem.
8. `./skillsmith list --user --system` exits 2 with a "conflicting scope shorthand" error.
9. Library-side: `listSkills(env)` and `runChecks(builtInChecks, ctx)` are callable from `@skillsmith/core` without any CLI code.
10. A new agent (stub during testing) can be added by supplying `getSkillRoots` and an optional `legacy-install` predicate — no walker/orchestrator changes.
11. `v0.3.0` tag cut after all of the above.
